The multi-agent ADE: all your agents at once, each on its own branch.

An Agentic Development Environment: run Claude Code, Codex, opencode or the agent you already use in parallel, each in its own git worktree. Talk to it in a chat or its own terminal, fix its code in an editor with your language server, and review and merge the pull request in the same window.

agents · 8 supported

Bring the agents you already pay for.

lich finds them on your PATH, or installs them from its Welcome, and opens them in a chat or their own terminal. Your login, your plan and your config stay theirs; lich has no account and no API key of its own.

around the agent · 15 · 2 new

The window keeps track so you do not have to.

What each session is doing, which one needs you, what it costs and what it changed.

Chat or terminalnew

A chat folds the tool calls, opens each edit into its diff and takes / commands, @ files and ! shell lines. GUI | TUI moves the same conversation to the agent's own terminal.

An editor with your language servernew

Errors, completions, docs and go to definition from the server on your PATH, blame on the cursor's line, and Vim keys run by your own Neovim.

A worktree per task

Each session gets its own branch and checkout, so agents run in parallel without touching each other's files. Type #123 and the branch is named after the issue.

Review in place

Read the diff, comment on its lines and send the comments back to the session as one prompt. Revert a line from the gutter.

Pull requests

Check, review and merge GitHub pull requests and GitLab merge requests in Pulls, with the checks, the threads and the files you marked viewed.

A browser the agent drives

A page beside the session that the agent opens and clicks through. Draw on it and leave notes, and the agent reads them.

Know which one needs you

A session's card turns amber the moment its agent waits on you, and a desktop notification says which one.

Sessions that work together

Agents hand each other tasks, fork themselves and report back through lich's tools. A subagent gets a card of its own and closes when it is done.

Layouts that lay themselves out

Put sessions in a layout and lich picks the grid from how many there are and the room the window has. Name one, keep as many as you like.

Services that keep running

Save a dev server, a container or a tunnel once per project. lich starts it with the project, keeps it running and shows its console.

Your plan in sight

The context window, the prompt cache, what the session has spent and what is left of your plan's window, read from what each agent writes down.

Several accounts, one card

Keep a personal and a work login as profiles. A session moved to another account carries on in the same card.

Fork a conversation

Branch a session's conversation into a new worktree and try the other idea without losing the first.

Jump to any session

Ctrl+P finds a session by name or by something said in it, and resumes conversations you started outside lich.

Run a session confined

An OS sandbox with a fresh home, the rest of the machine read-only and only its checkout writable: bubblewrap on Linux, sandbox-exec on macOS. Not a boundary against hostile code.

extensions · go sdk

Build what lich is missing for you.

An extension is your own tool inside lich's window. It draws with the components lich itself is made of, and it drives lich through the same tools your agents use.

  • Run your sessions. Open one in a worktree, hand it a task and collect its answer.
  • Follow them. Know the moment a session starts working, finishes or waits on you.
  • Run your services. Start, stop and restart them, and read what they print.
  • Read the checkout. Its branch, its changes and its pull request.
  • Reach you. A desktop notification, a file in the dock or a page in a session's browser.
  • Have its own screens. A button in the top bar, its own shortcuts and data that outlives an update.

LichNotes is the published example: the Markdown notes of a folder, filtered as you type and edited beside a live preview. The catalog lists the rest; write your own with the Go SDK.

install · linux · macos · windows

Install it in one line.

Then open a project and pick an agent. git on your PATH; gh or glab only for pull requests.

$ curl -fsSL https://raw.githubusercontent.com/lichdotdev/lich/main/install.sh | sh

Picks the .deb, .rpm or .pkg.tar.zst for your distribution and checks it against checksums.txt. On Arch: yay -S lich-bin. x86_64, glibc 2.34+ and zenity.

debian, ubuntu · .debfedora, opensuse · .rpmarch · .pkg.tar.zst
$ brew install --cask lichdotdev/tap/lich

Through Homebrew; brew upgrade takes the next release.

apple silicon · .zipintel · .zip
$ scoop install https://github.com/lichdotdev/lich/releases/latest/download/lich.json

Through Scoop, or the installer, which updates itself in place.
