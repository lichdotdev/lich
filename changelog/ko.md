## [0.83.0] - 2026-10-29

- `lich insert --focused`는 lich 창에 카드가 표시된 세션, 즉 앞에 있는 프로젝트 탭의 활성 카드에 붙여 넣습니다. 파일 관리자 동작이나 편집기가 파일의 폴더로 짐작하지 않고도 지금 보고 있는 에이전트에게 경로를 보낼 수 있습니다. `lich sessions --json`, `lich whoami --json`, MCP 도구 `list_sessions`가 그 세션에 `"focused": true`를 표시합니다. 창이 닫혀 있으면 표시되는 세션이 없고 `--focused`가 그렇다고 알려 줍니다.

### Changed

- 세션 브라우저에서 페이지가 새 탭이나 창으로 여는 것이 더 이상 그것을 연 페이지를 대체하지 않습니다. 이전에는 새 탭의 주소가 그 페이지 위에 로드되어, 로그인이나 페이지가 스크립트에 담고 있던 것이 사라졌고, 탭을 열고 그것이 끝나기를 기다리는 흐름이 깨졌습니다.

### Fixed

## [0.82.0] - 2026-10-29

### Added

- `lich sessions --json`, `lich whoami --json`, MCP 도구 `list_sessions`가 세션 카드가 레이블 아래에 표시하는 줄을 담습니다. 세션이 작업 중일 때는 실행 중인 도구와 그 대상인 `tool`과 `detail`, 사용자를 기다릴 때는 `reason`입니다. 스크립트나 데스크톱 위젯이 창을 열지 않고도 각 에이전트가 무엇을 하는지 보여 줄 수 있습니다.
- 세션의 브라우저가 세션 체크아웃의 로컬 파일을 엽니다. 주소 입력란에 경로를 입력하거나 에이전트가 `browser_open`에 경로 또는 `file:` URL을 전달하면, lich가 체크아웃을 127.0.0.1의 http로 제공하며 포트는 worktree마다 따로 둡니다(체크아웃의 `LICH_WORKTREE_PORT`에 1000을 더한 값). 그래서 모듈 스크립트, `fetch`, 상대 경로 에셋이 동작하고 각 worktree가 자기 저장소를 유지합니다. 체크아웃 밖의 경로는 거부됩니다. 이전에는 로컬 파일을 아예 열 수 없었고, 미리 보려면 정적 서버를 직접 띄워야 했습니다.
- 세션 브라우저의 도구 모음에 확대/축소 버튼이 있습니다. 누르면 작은 메뉴가 열려 페이지 확대/축소를 10%씩 줄이고 늘리며 100%로 재설정할 수 있고, 각 컨트롤에 키보드 단축키가 표시됩니다. 이전에는 확대/축소를 키보드로만 바꿀 수 있었습니다.

### Fixed

- 다음에서 계속이 세션의 브라우저를 유지합니다. 세션을 다른 프로필로 옮기면 브라우저가 닫혀서, 세션이 다시 올라왔을 때 페이지와 쿠키가 사라져 있었습니다.
- 세션 브라우저가 바쁜 페이지를 따라갑니다. 애니메이션이 있거나 JavaScript를 많이 실행하는 페이지에서 브라우저 탭이 페이지보다 몇 초씩 뒤처지고 창의 나머지도 함께 기다렸는데, 이제는 최신 프레임으로 건너뜁니다.
- 세션 브라우저가 HiDPI 화면에서 선명합니다. 어떤 디스플레이에서든 탭이 페이지를 1x로 흐릿하게 표시했는데, 이제는 최대 1.5x로 그립니다.
- 세션 브라우저의 메모와 풀 리퀘스트 화면의 CI 오류 고치기, 충돌 해결이 Esc로 멈춘 Claude Code 세션에 전달됩니다. Claude Code는 누군가 세션에 입력할 때까지 메시지를 거부했고 트레이에는 "its mod refused it"이 표시되었는데, 이제 lich가 대신 프롬프트에 메시지를 입력합니다.

## [0.81.0] - 2026-10-28

> [!IMPORTANT]
> **에이전트가 웹 페이지를 작업하는 분께: 페이지를 가리키며 무엇을 바꿀지 말해 주세요.** 세션 브라우저 도구 모음의
> 십자선으로 고른 요소에 메모를 남기면 에이전트에게 한 번에 메시지로 전달됩니다.

### Added

- 세션 브라우저 도구 모음의 십자선으로 에이전트를 위해 페이지에 메모를 남길 수 있습니다. 포인터 아래의 요소가 윤곽선과 이름으로 표시되고, 포인터가 움직이면 윤곽선이 한 요소에서 다음 요소로 미끄러지듯 이동하며, 클릭하면 그 옆에 메모가 열리고, 각 메모는 번호로 요소에 고정되어 페이지가 스크롤되어도 따라갑니다. 메모는 페이지 아래쪽 위에 떠 있는 트레이에 모이며, 트레이는 크기가 바뀌지 않습니다. 트레이에서 메모에 호버하면 해당 요소가 강조되고, 메모나 번호표를 클릭하면 요소가 화면에 들어오도록 스크롤되며 메모를 편집할 수 있습니다. 스크롤되는 목록, 사이드바, 대화상자에 가려진 요소는 보이는 부분만 윤곽선으로 표시되고, 완전히 가려진 요소는 옆에 있는 것 위에 번호표를 남기지 않습니다. 보내기(또는 Ctrl+Enter)를 누르면 메모가 하나의 메시지로 세션에 입력됩니다. 어떤 요소인지, 에이전트의 `browser_click`이 받는 셀렉터, 개발 빌드에서 그 요소를 그린 React 컴포넌트, 그리고 사용자의 메모가 담깁니다. Ctrl+Shift+E(macOS에서는 Cmd+Shift+E)로 십자선을 켜고 끄며, Esc로 빠져나옵니다. 세션이 거부한 전송은 메모를 그대로 두고 그 이유를 트레이에 표시합니다.
- 세션의 브라우저가 파일을 다운로드합니다. 페이지가 링크, 버튼, 새 탭, 스크립트로 시작한 다운로드는 페이지가 지정한 이름으로 다운로드 폴더에 저장되며, 이미 있는 파일을 덮어쓰지 않고 ` (1)`을 붙입니다. 에이전트가 파일의 URL을 직접 열 수도 있습니다. 에이전트의 클릭, 키 누르기, 열기는 파일의 경로와 크기로 응답하고, 창에는 파일 이름을 알리는 토스트와 그 폴더를 여는 버튼이 표시됩니다. 이전에는 세션 브라우저의 다운로드 버튼이 아무 일도 하지 않았습니다.
- 에이전트가 브라우저 페이지를 반복해서 다시 읽는 대신 페이지가 바뀌기를 기다릴 수 있습니다. `browser_info`가 `wait_for`(나타나야 하는 텍스트)와 `wait_gone`(사라져야 하는 텍스트)을 받아 페이지 어디에서든 일치를 확인하고, 페이지에 표시되는 즉시, 또는 20초 뒤에 현재 페이지와 대기가 시간 초과되었다는 한 줄로 응답합니다.
- 에이전트가 세션 브라우저의 페이지가 깨졌을 때 알게 됩니다. 에이전트가 읽거나 클릭하거나 키를 누르는 각 페이지는 마지막으로 본 이후의 콘솔 오류를 한 번씩 담아 응답합니다. `console.error` 호출, 처리되지 않은 예외, 로드에 실패한 리소스이며, 짧은 한 줄로 줄여 처음 다섯 개와 그 밖의 개수를 알려 줍니다. 경고와 다른 메시지는 제외됩니다.
- 에이전트가 `close_project` 또는 `lich close-project`로 프로젝트를 닫을 수 있습니다. 탭이 창에서 사라지고 세션이 중지되며, 탭을 닫을 때처럼 다시 열 수 있게 보관됩니다. 에이전트가 실행 중인 프로젝트와 홈 프로젝트는 거부됩니다.
- 사용자와 에이전트가 세션 브라우저에서 페이지의 JavaScript 대화상자에 응답합니다. 페이지가 여는 alert, confirm, prompt, "이 페이지에서 나가시겠습니까?"는 세션의 브라우저 탭에서 페이지 위쪽에 카드로 표시되며, 연 사이트의 이름과 버튼, prompt라면 입력란이 있습니다. 사용자가 거기에서 응답하거나 에이전트가 `browser_dialog`로 응답하며, 이때 에이전트의 커서가 카드의 버튼을 누릅니다. 대화상자를 연 에이전트의 클릭은 그 대화상자를 담아 즉시 응답하고, 사용자가 응답한 대화상자도 에이전트에게 전달됩니다. 이전에는 alert를 띄우는 버튼이 페이지를 멈추게 해서, 에이전트의 클릭과 이후의 모든 읽기가 30초를 기다린 뒤 실패했습니다.
- 설정 › 일반에 터미널용 선택 시 복사 스위치가 있습니다. 기본값은 켜짐이며, 선택하는 즉시 복사합니다. 끄면 Ctrl+Shift+C(macOS에서는 Cmd+C)로 복사합니다.
- 세션의 브라우저가 인터페이스 확대/축소와 별개로 페이지를 자체적으로 확대/축소합니다. Ctrl+-와 Ctrl+=(macOS에서는 Cmd)로 10%씩 축소하고 확대하며 범위는 50%에서 200%까지이고, Ctrl+0은 100%로 되돌립니다. 축소한 페이지는 데스크톱 브라우저처럼 더 넓게 배치되므로, 창의 나머지를 줄이지 않고도 작은 화면을 쓸 수 있습니다. 확대/축소는 모든 세션의 브라우저에 적용되고, 100%가 아닐 때 도구 모음에 표시되며, 다음 시작에도 유지됩니다.
- 설정 › 일반 › 창 › 버튼에서 창의 최소화, 최대화, 닫기 버튼을 표시할지 선택합니다. 시스템 따르기, 항상 표시, 숨기기 중에서 고릅니다. 시스템 따르기는 기존 lich의 동작이며, Linux에서는 이제 시작할 때만 읽지 않고 lich가 열려 있는 동안 바탕 화면의 버튼 배치가 바뀌어도 따라갑니다. 항상 표시는 Hyprland처럼 창 관리자가 창을 꾸미거나 제목 표시줄 없이 타일링하는 곳에서도 버튼을 그립니다. 숨기기는 창에서 버튼을 없애며, macOS의 신호등 버튼도 포함됩니다.

### Changed

- 프로젝트의 GitHub 계정(설정 › 버전 관리)이 이제 그 세션에도 적용됩니다. 에이전트나 셸 카드에서 실행한 `gh`는 gh에서 활성화된 계정이 아니라 그 계정으로 응답하며, 세션이 다음에 시작될 때부터 적용됩니다. 그 세션 안에서는 `gh auth switch`가 더 이상 계정을 바꾸지 않습니다.
- 세션을 많이 열어도 창이 차지하는 메모리가 줄었습니다. 화면 밖의 터미널은 그렸던 픽셀을 놓아 주며, 각각 몇 메가바이트이고, 다시 돌아오면 한 프레임에 다시 그립니다.
- 창의 가비지 컬렉터가 이제 Go 기본값 100 대신 50으로 동작합니다. 세션 15개로 한 테스트에서 상주 메모리가 약 10분의 1 줄었는데, 시스템이 스왑으로 내보냈을 여유분입니다. `GOGC`를 지정하면 여전히 그 값이 우선합니다.
- 브라우저 도구가 에이전트에게 세션의 프롬프트 언어로 응답합니다. 요소 목록의 범례, 아래에 요소가 더 있다는 안내, 채워짐과 선택됨 표시, 진행 중인 다운로드, 시간 초과된 대기, 추가 콘솔 오류의 개수, 열린 대화상자가 에이전트에게 요구하는 것이 해당됩니다. 줄 태그(`url:`, `text:`, `downloaded:`, `console error:`, `dialog open:` 등)는 모든 언어에서 그대로입니다.
- 어떤 탭에도 표시되지 않는 세션의 브라우저는 이제 페이지를 Chrome의 800×600 대신 lich 창 크기에 브라우저 확대/축소를 적용한 크기로 배치하므로, 에이전트가 데스크톱 브라우저에 보이는 그대로 페이지를 읽고 스크린샷을 찍습니다. 브라우저 탭을 닫으면 페이지가 탭의 크기로 남지 않고 그 크기로 돌아갑니다.
- 풀 리퀘스트 화면의 충돌 해결이 CI 오류 고치기가 실패한 검사를 알려 주는 것처럼, 세션에 보내는 프롬프트에 충돌하는 파일을 명시합니다. 파일이 알려지기 전에 클릭하면 이전처럼 파일 없이 프롬프트를 보냅니다.

### Fixed

- Windows에서 작업 표시줄과 Alt-Tab의 창 제목이 `lich (native slice)` 대신 `lich`로 표시됩니다.
- GitHub Enterprise 서버에 GitHub 계정이 있는 프로젝트가 풀 리퀘스트 화면, 풀 리퀘스트 배지, 샌드박스 세션에 부여되는 토큰에서 그 계정을 받습니다. 토큰이 엔터프라이즈 호스트에서 gh가 무시하는 변수로 전달되어, gh가 그곳에서 활성 계정으로 응답했습니다.
- 세션 브라우저의 인덱스를 통한 클릭, 입력, 키 누르기가 에이전트의 마지막 페이지 읽기가 그 인덱스를 부여한 요소에 도달합니다. 스크롤한 뒤 다시 읽으면, 첫 번째 읽기에서 같은 인덱스로 나열되었던 요소가 이제 화면 밖에 있는데도 오류 없이 클릭을 받을 수 있었습니다.
- Windows에서 같은 프로필에서 세션이 동시에 시작될 때, lich가 그 프로필의 파일을 쓰는 동안 간헐적으로 `Access is denied`로 실패하던 문제가 없어졌습니다.

## [0.80.0] - 2026-10-27

> [!IMPORTANT]
> **에이전트에게 웹 페이지 작업을 맡기는 분께: 이제 에이전트가 세션 옆에서 브라우저를 직접 조작합니다.** 세션 카드
> 메뉴에서 브라우저를 열면 에이전트의 커서가 페이지를 클릭하고 입력하고 스크롤하는 모습을 볼 수 있고, 그동안 직접 페이지를 써도 됩니다.

### Added

- 세션 카드의 메뉴에서 다음에서 열기 위에 있는 항목으로 그 세션의 브라우저를 열 수 있습니다. 세션 옆의 탭에 한쪽에는 터미널, 다른 쪽에는 페이지가 놓이며, 분할과 같은 구분선, 회전, 확대를 지원합니다. 세션의 에이전트도 같은 페이지를 조작합니다. URL 열기, 읽기, 클릭, 입력, 키 누르기, 뒤로 가기와 앞으로 가기, 스크롤, 스크린샷을 `browser_*` 도구 또는 `lich browser`로 수행합니다. 에이전트 자신의 커서가 동작하는 위치를 보여 줍니다. 세션의 카드 색 또는 테마 색으로 그려진 lich의 화살표에 프로바이더 이름이 적힌 배지가 붙고, 페이지의 각 클릭, 입력란, 스크롤과 창 도구 모음의 뒤로, 앞으로, 새로고침, 주소 입력란으로 미끄러지듯 이동하며, 에이전트가 병렬로 호출해도 차례대로 재생됩니다. 에이전트가 작업하는 동안에도 사용자는 페이지에서 자신의 클립보드로 클릭하고, 입력하고, 복사하고 붙여 넣을 수 있습니다. 에이전트가 보내는 클릭과 키마다 직전의 페이지가 간결한 형태로 돌아오므로, 긴 세션은 페이지를 JSON으로 다시 읽을 때의 절반 정도의 토큰만 사용합니다. 에이전트가 스스로 브라우저를 열면 오른쪽 아래 모서리의 토스트가 표시를 제안합니다. 창에서 열기는 페이지를 쿠키까지 포함해 별도의 Chromium 창으로 옮깁니다. 카드를 닫으면 브라우저도 닫힙니다. 브라우저는 이미 설치된 Chrome, Edge, Chromium, Brave, Vivaldi, Helium 중 하나입니다.
- 하단 바가 마지막 턴에서 프롬프트 캐시로부터 읽어 온 비율을 보여 주며, 막대는 턴의 입력을 캐시됨, 캐시에 기록됨, 캐시되지 않음으로 나눕니다. 캐시가 만료된 뒤의 턴은 호박색 0%로 표시되며, 이는 전체 요금으로 청구된 턴입니다. Claude Code와 Codex에서는 컨텍스트 창 툴팁에, oh-my-pi와 opencode에서는 비용 툴팁에 표시됩니다.

### Changed

- opencode 세션도 Claude Code, Codex처럼 생성될 때 lich의 MCP 서버를 받으므로, opencode의 MCP 목록의 `lich` 서버 아래에 `browser_*`를 포함한 모든 lich 도구가 나열됩니다. 사용자의 서버와 내보낸 `OPENCODE_CONFIG_CONTENT`는 그대로 유지됩니다.
- 에이전트가 `control_session`으로 자신이 실행 중인 세션의 모델이나 추론 effort를 바꿀 수 있고, 사용자가 요청하면 그 세션을 닫을 수도 있습니다(`close_session`의 `self`, `lich close --self`). 두 가지 모두 이전에는 무조건 거부되었습니다.

### Fixed

- 세션 브라우저의 열기, 새로고침, 뒤로, 앞으로가 모든 이미지와 트래커가 끝나기를 기다리지 않고 페이지가 상호작용 가능해지면 반환됩니다. 이 대기는 페이지가 이미 화면에 표시된 뒤에도 load 이벤트가 끝날 때까지, 최대 30초 동안 에이전트의 다음 동작을 붙잡고 있었습니다. 스크린샷은 지켜보고 있는 뷰포트입니다.
- Codex 세션의 비용이 프롬프트 캐시에 기록된 토큰을 더 이상 두 번 청구하지 않습니다. 이전에는 캐시 기록 요율로 책정된 뒤 캐시되지 않은 입력으로 다시 책정되었습니다.
- 터미널의 마우스 휠이 다른 터미널과 같은 정도로 부드럽게 스크롤됩니다. 한 눈금이 셸의 기록이나 `less` 같은 전체 화면 프로그램에서 세 줄을 움직이며, 한 번에 여덟 줄 정도를 건너뛰는 대신 몇 프레임에 걸쳐 완만하게 이동합니다. nvim, Claude Code, Codex처럼 마우스를 가져가는 프로그램은 한 눈금에 휠 단계 하나를 받아 자신의 거리만큼 스크롤하며, 이전에는 약 여덟 개를 받아 대화를 순식간에 지나갔습니다.

## [0.79.0] - 2026-10-24

> [!IMPORTANT]
> **에이전트 옆에 개발 서버, 컨테이너, 터널을 띄워 두는 분께: 이제 lich가 그것들을 실행합니다.** 프로젝트의
> 설정 › 서비스에 한 번 저장하면 사이드바 맨 아래에서 시작, 중지하고 출력을 볼 수 있습니다.

### Added

- macOS에서 lich가 메뉴 막대 항목을 가집니다. 창을 닫은 lich는 Linux와 Windows의 트레이처럼 그곳에서 세션을 계속 실행 중임을 보여 주며, lich 보기, 실행 중인 세션 수, lich 종료를 제공합니다.
- **서비스: lich가 시작해 프로젝트가 계속 실행하는 명령.** 컨테이너, 터널, 개발 서버를 프로젝트의 설정 › 서비스에 한 번 저장하면, 사이드바 맨 아래 프로필 위에 있는 서비스 행에서 시작할 수 있습니다. 닫혀 있을 때 이 행은 실행 중인 개수(2/3)를 보여 주고, 펼치면 각 서비스가 얼마나 오래 실행되었는지 또는 어떻게 끝났는지를 나열하며, 호버하면 시작, 중지, 다시 시작이 나타납니다. 클릭하면 입력을 받고 Ctrl+C로 중지할 수 있는 콘솔이 열립니다. 서비스는 터미널이 아닙니다. 명령이 끝나면 서비스는 중지된 것이고, 마지막 출력은 그대로 읽을 수 있으며, 시작을 누르면 다시 실행됩니다. lich와 함께 시작을 선택하면 해당 프로젝트가 열린 채 lich가 시작될 때마다 시작됩니다. 설정 › 서비스에서 전역을 선택해 저장한 서비스는 홈 디렉터리에서 실행되고 lich의 시작 화면에 표시되며, 프로젝트와 상관없이 계속 열어 두는 `lazydocker` 같은 것을 두기에 알맞습니다. 서비스는 프로젝트 탭이 있는 동안만 유지됩니다. 탭을 닫으면 중지되고, 프로젝트를 다시 열면 lich와 함께 시작하도록 저장된 서비스가 시작됩니다. 창을 닫아도 서비스는 계속 실행되며 트레이에 출력 보기, 다시 시작, 중지와 함께 나열됩니다. lich를 종료하면 서비스가 중지되고, 닫기 대화상자가 그 수를 알려 줍니다. 사이드바를 접으면 레일의 서비스 버튼이 같은 목록을 엽니다.

- **풀 리퀘스트의 리뷰 스레드를 그 세션으로 보내기.** 풀 리퀘스트 화면에서 열린 리뷰 스레드에는 대화 탭과 diff 모두에서 답글, 해결 옆에 세션으로 보내기가 있으며, 대화 탭에서는 열린 스레드를 한꺼번에 보낼 수 있습니다. 스레드는 각 스레드의 파일, 줄, 링크, 모든 댓글과 함께 하나의 프롬프트로 그 브랜치의 체크아웃에 있는 세션으로 전달되며, 세션이 없으면 lich가 엽니다. 풀 리퀘스트 화면은 그대로 유지되고, 세션이 받으면 열기가 있는 토스트로 알려 줍니다. 이후 lich는 GitHub에서 각 스레드에 "Fixing this. It'll be in the next commit."라고 답하고, 풀 리퀘스트가 다시 push되면 스레드를 해결 처리하면서 반영된 커밋을 답글로 남깁니다. 그때까지 스레드에는 보냄 · push 대기 중이 표시됩니다. 스레드를 건드리지 않은 push라도 해결 처리됩니다.

### Changed

- github.com에서, 터미널의 `gh`로, 또는 에이전트가 lich 밖에서 머지한 풀 리퀘스트도 이제 풀 리퀘스트 화면에서 머지한 것처럼 머지 후 1분 안에 그 브랜치의 체크아웃에 있는 에이전트에게 알립니다. 이전에는 에이전트가 풀 리퀘스트가 아직 열려 있다고 계속 믿었습니다. lich가 열린 상태에서 머지된 것을 확인했을 때 그곳에서 실행 중이던 에이전트가 알림을 받으며, 그 순간 보관되어 있던 에이전트나 lich가 마지막으로 시작되기 전에 머지된 풀 리퀘스트는 받지 않습니다.
- Pulls의 충돌 해결과 CI 오류 고치기는 더 이상 풀 리퀘스트를 넘긴 세션으로 이동하지 않습니다. Pulls가 화면에 그대로 있어 다음 풀 리퀘스트로 넘어갈 수 있고, 세션은 사이드바에서 시작되며, 에이전트가 작업을 받으면 열기가 있는 토스트로 알립니다. 마지막 대화를 재개할지처럼 시작 전에 사용자의 답이 필요한 세션은 그대로 나타납니다. 세션에서 열기는 여전히 세션으로 이동합니다.
- Pulls의 풀 리퀘스트 목록 위 빠른 필터(전체, 준비됨, 초안, 실패)가 더 가벼워졌습니다. 도크의 탭처럼 작은 글자에 선택된 항목만 음영이 들어가며 목록의 너비를 나눠 씁니다. 항목이 없는 필터는 흐리게 표시되고, 체크가 실패하면 실패의 개수가 빨간색이 됩니다. 고정폭 인터페이스 글꼴에서도 더 이상 목록의 가장자리를 넘지 않습니다.

### Fixed

- 세션의 셸이 다른 저장소로 이동한 뒤 세션 카드의 풀 리퀘스트 배지, 풀 리퀘스트 메뉴 항목, 하단 바의 풀 리퀘스트 버튼이 더 이상 엉뚱한 풀 리퀘스트를 열지 않습니다. 배지는 그 저장소의 풀 리퀘스트를 보여 주는데, 클릭하면 그 번호를 Pulls의 프로젝트 자체 풀 리퀘스트에서 찾았습니다. 이제는 대신 GitHub에서 그 풀 리퀘스트를 엽니다.
- 접은 사이드바가 레일 맨 아래에 새 세션이 생성되는 프로필을 표시하고, 펼친 사이드바의 푸터와 같은 메뉴를 엽니다. 이전에는 프로필이 전혀 표시되지 않았습니다.
- 상단 바의 탭이 들어 올려진 채 멈춰, 드래그 중인 것처럼 강조 색으로 그려지고 lich를 다시 시작할 때까지 어떤 탭도 움직이지 않는 일이 없어졌습니다. 클릭으로 포커스된 뒤 Space나 Enter를 받은 탭이 키보드로 순서를 바꾸기 위해 집어 올려졌고, 다른 곳을 클릭해 키보드가 넘어가면 내려놓을 수도 취소할 수도 없었습니다. 이제는 포커스를 잃으면 제자리로 돌아갑니다. 드래그 도중 이름이 바뀐 레이아웃 탭도 같은 방식으로 멈추지 않습니다.
- 에이전트가 도구를 시작하거나 멈추거나, 사용자를 기다리거나, 컴팩트할 때 세션 카드가 커졌다 작아지면서 아래의 모든 카드를 위아래로 밀지 않습니다. 이제 그 줄이 표시되는 동안 카드의 경로 자리를 차지하고, 사라지면 경로가 돌아옵니다.
- 네이티브 창이 글꼴에 쓰는 메모리가 줄었습니다. 같은 글꼴 파일을 두 번 이상 요청하는 경우(같은 글꼴 계열로 설정한 인터페이스와 터미널, 세미볼드를 대신하는 볼드체 등), Nerd Font 한 서체당 약 30MB를 매번 다시 파싱했지만, 이제는 한 번만 파싱해 사용하는 동안 공유합니다. 중국어, 일본어, 한국어가 아닌 언어의 인터페이스는 시작할 때 수십 MB의 CJK 글꼴을 불러오지 않으며, 화면에 처음 CJK 텍스트가 나올 때 불러오고 그동안은 시스템 글꼴로 그립니다. 인터페이스, 터미널, 편집기에 Nerd Font 하나를 쓰고 화면에 CJK가 없을 때 글꼴이 차지하는 메모리는 246MB에서 119MB가 되었습니다.
- macOS에서 창을 닫은 채 실행 중인 lich를 Dock, Launchpad, Spotlight, Finder에서 열면 창이 다시 열립니다. `--no-window`로 로그인 시 시작된 lich도 포함되며, 이전에는 클릭해도 아무 일도 없었습니다. 로그아웃하면 이제 `lich quit`과 같은 방식으로 lich를 종료하므로, 다음 실행에서 이를 비정상 종료로 읽지 않습니다.

## [0.78.1] - 2026-10-23

### Changed

- 세션이 작업하는 동안 창은 사용 중 스피너를 디스플레이의 주사율이 아니라 초당 30프레임으로 다시 그립니다. 카드의 오른쪽 클릭 메뉴는 그 메뉴가 열려 있는 동안에만 만들어지고, 닫힌 대화상자는 아무것도 만들지 않습니다.

### Fixed

- 카드와 하단 바의 브랜치, 변경 사항, 풀 리퀘스트가 턴 밖에서 한 커밋, 체크아웃, 편집을 1초 안에 따라잡습니다. 이전에는 최대 3초까지 늦을 수 있었습니다. 또한 카드를 선택하면 마지막으로 읽은 결과를 보여 주는 대신 그 체크아웃을 즉시 읽습니다.
- Pulls에서 풀 리퀘스트 목록을 숨기면 바로 사라집니다. 이전에는 마우스가 움직이거나 Pulls가 다음에 GitHub를 확인할 때까지 목록이 화면에 남아 있었습니다. 다시 표시할 때도 한 프레임을 기다리지 않습니다.
- Kiro CLI 세션이 `KIRO_HOME`을 따릅니다. 설정해도 lich는 Kiro의 대화, 비용, 컨텍스트를 `~/.kiro`에서 읽었지만 Kiro는 이를 `KIRO_HOME` 아래에 두고 있었기 때문에 아무것도 표시되지 않았고 기록에도 나열되지 않았습니다. lich의 훅을 담은 에이전트도 Kiro가 보지 않는 곳에 설치되었고, 샌드박스 세션에는 Kiro가 쓰는 디렉터리가 주어지지 않았습니다.
- 도크를 열거나 닫아도 도크가 멈춘 뒤 세션의 터미널이 가장자리에서 잘린 채 잠시 남아 있지 않습니다. 터미널은 도크가 움직이기 시작할 때 새 너비를 받으므로 도크가 미끄러지는 동안 에이전트가 다시 그립니다. 이전에는 도크가 멈춘 뒤 10분의 1초를 기다렸다가 한꺼번에 바뀌었습니다. 분할 레이아웃의 터미널은 도크가 멈추는 순간 맞춰집니다.
- 사이드바를 펼쳐도 사이드바가 열린 뒤 세션의 터미널이 이전 너비로 잠시 남아 있지 않습니다. 도크와 마찬가지로 터미널은 사이드바가 움직이기 시작할 때 새 너비를 받습니다. 이전에는 사이드바가 멈춘 뒤 10분의 1초를 기다렸다가 한꺼번에 바뀌었습니다. 접을 때도 즉시 다시 맞춰집니다. 분할 레이아웃의 터미널은 사이드바가 멈추는 순간 맞춰집니다.
- 창을 다시 열어도 세션에 엉뚱한 텍스트가 입력되지 않습니다. 최근 출력으로 터미널을 다시 만들 때 그 안의 터미널 질의(예를 들어 nvim이 시작할 때 보내는 것)에 다시 응답했고, 그 응답이 세션의 입력에 들어갔습니다. 셸에서는 `command not found`로, 에이전트에서는 프롬프트 안의 텍스트로 나타났습니다.
- 세션이 출력하는 도중에 연 세션의 터미널이 그 순간에 출력된 내용을 놓치지 않습니다. 백엔드가 세션의 최근 출력을 실시간 출력과 이어서 창에 전달하므로 그 사이의 내용이 유실되거나 두 번 표시되지 않습니다.
- Linux에서 터미널 글꼴 크기를 바꿀 때와 카드를 처음 열 때의 끊김이 줄었습니다. 이전에는 모든 터미널이 매번 fontconfig로 글꼴을 다시 조회했고, 한 프레임 안에서 각각 약 10ms인 조회가 네 번 일어났습니다. 이제 lich는 그 결과를 실행이 끝날 때까지 기억합니다.
- 터미널 글꼴 크기를 바꿔도 열려 있는 모든 터미널의 글꼴을 다시 불러오지 않습니다. 각 터미널은 가진 글꼴을 그대로 쓰고 새 크기로 그리기만 합니다.
- 출력이 많은 세션이 백엔드에 주는 부담이 줄었습니다. 창으로 가는 각 바이트가 약 7번씩 메모리에 복사되어 이후 가비지 컬렉터가 회수해야 했는데, 이제는 한 번만 복사됩니다.
- 리뷰와 Pulls의 diff에서 접힌 구간 위에서 시작하는 블록 주석이 그 구간 뒤의 코드를 주석으로 칠하지 않습니다. 닫는 `*/`가 숨겨진 줄에 있어서 이후의 `*/`가 나올 때까지 아래의 모든 헝크가 주석으로 표시되었고, 구간을 펼쳐야만 해결되었습니다. 접힌 구간에 의해 잘린 주석의 위쪽 줄은 펼치기 전까지 코드로 표시될 수 있습니다.

## [0.73.0] - 2026-10-20

> [!IMPORTANT]

- 사용자 지정 바이너리로 세션을 시작하면 설정 › 프로바이더의 프로필 아래에 경고가 표시되며, 바이너리 경로와 그 위치를 보여 주는 버튼, 기본값으로 되돌리는 버튼이 함께 나옵니다. 자체 로그인 또는 설정 디렉터리를 지정하는 래퍼는 프로필보다 우선하며, 바이너리 설정은 화면 맨 아래에 접혀 있습니다.

### Changed

- 세션의 프로세스가 종료되면 터미널 하단의 띠 대신 오른쪽 아래의 토스트가 어떻게 할지 묻습니다. 대화가 있는 카드는 같은 대화를 다시 여는 재개(처음 시작한 프로필에서), 재시작처럼 카드에서 새 대화를 시작하는 새로 시작, 세션 닫기를 제공합니다. 셸이나 첫 프롬프트 전에 끝난 에이전트는 다시 시작과 세션 닫기를 제공합니다. 토스트를 닫으면 카드는 그대로 남고, 카드에 포커스하면 토스트가 다시 나타납니다.
- **프로젝트의 프로필이 모든 카드가 아니라 사이드바 맨 아래에 표시됩니다.** 한 프로바이더에 로그인이 둘 이상이면, 사이드바의 마지막 줄에 이 프로젝트의 새 세션이 시작되는 프로필이 표시됩니다. 화면에 보이는 카드의 프로바이더, 터미널이면 기본 프로바이더 기준입니다. 눌러서 다른 로그인을 고르거나(각 로그인의 5시간 사용량이 함께 표시됩니다) 전역의 로그인으로 되돌릴 수 있고, 다른 프로바이더는 같은 메뉴에서 바꿉니다. 카드에는 더 이상 브랜치 옆에 프로필 칩이 붙지 않습니다.

### Fixed

## [0.72.0] - 2026-10-19

### Changed

- 네이티브 창의 상단 바가 이제 제목 표시줄입니다. 시스템 제목 표시줄은 사라지고, 최소화·최대화·닫기 버튼은 설정 옆에 Windows, GNOME, KDE가 그리는 모양 그대로, 데스크톱이 두는 쪽에 놓입니다. macOS에서는 신호등 버튼이 상단 바에 들어갑니다. 상단 바의 빈 부분을 끌어 창을 옮기고, 더블 클릭하면 최대화됩니다. 타일링 창 관리자는 자체 장식을 그대로 유지합니다.

### Fixed

- lich가 응답하기 전에 종료되어도 `lich quit`가 더 이상 "EOF"로 실패하지 않습니다. 잃어버린 응답을 거부로 보지 않고 포트가 닫히기를 기다립니다.
- Wayland에서 네이티브 창이 다른 테마의 커서를 보여 줄 수 있던 문제를 고쳐, 데스크톱 자체의 커서를 그 테마와 크기로 보여 줍니다. 가장 큰 모니터보다 배율이 작은 모니터에서 커서가 창에 들어올 때 더 이상 튀지 않습니다.
- Linux에서 네이티브 창이 일반 아이콘을 단 별도 앱으로 독에 나타나던 문제를 고쳐, lich 자체 아이콘 아래로 묶입니다.
- 네이티브 창의 리뷰와 pull request의 파일에서 스크롤바가 화면을 채운 파일에 따라 늘었다 줄었다 하던 문제를 고쳐, 스크롤해도 크기가 유지됩니다. 이제 스크롤바를 끌면 파일 단위가 아니라 diff 전체를 고르게 이동합니다.

## [0.71.0] - 2026-10-17

### Added

- **네이티브 창의 분할 레이아웃(실험적).** 열려 있는 어느 프로젝트의 세션이든 나란히 놓고 원하는 대로
  분할할 수 있습니다. Ctrl+Shift+G는 포커스된 세션을 오른쪽으로, Ctrl+Shift+I는 아래로 분할하며
  각각 그 자리에 놓을 세션을 묻습니다. 사이드바의 카드를 창 가장자리로 끌어다 놓아도 됩니다.
  레이아웃을 재배치하려면 창 헤더를 끌어 다른 창의 가장자리에 놓거나, 가운데에 놓아 두 창을 서로
  바꾸세요. Ctrl+Shift+R은 한 쌍을 나란히 배치와 위아래 배치 사이에서 전환합니다. 모든 레이아웃은
  프로젝트 뒤에 탭으로 나타나 각 창의 상태를 보여 주며, 더블 클릭해서 이름을 바꿉니다. 두 창 사이의
  경계를 끌어 크기를 조절하고, Ctrl+Shift+M으로 하나를 확대하고, Ctrl+Shift+F로 창 사이를 이동하고,
  Ctrl+Shift+W로 하나를 빼냅니다. 창이 하나만 남은 레이아웃은 닫힙니다. 끌고 있는 세션을 다른 탭
  위에 잠시 두면 브라우저가 끌고 있는 파일에 하는 것처럼 그 탭이 열립니다. 사이드바와 푸터는 포커스된
  창을 따라갑니다.
- **세션의 위임을 옆에 표시합니다.** 네이티브 창에서 다른 세션을 연 세션은, 어느 프로젝트의
  것이든, 푸터에서 그 세션들을 보여 줍니다. 옆에 보기를 누르면 그 세션을 왼쪽에 두고 위임들을 오른쪽에
  쌓아, 들어가는 만큼 배치합니다. 레이아웃 안에서는 창 헤더가 그곳에 있는 위임의 수를 세고 나머지를
  추가하며, 다른 레이아웃에 있는 것을 빼 오기 전에 먼저 묻습니다. 레이아웃 안의 카드에는 그 이름이
  표시됩니다.
- **필수 체크가 표시됩니다.** 네이티브 창에서 풀 리퀘스트의 체크 탭은 GitHub처럼, 병합을 가로막는
  체크에 필수 표시를 붙입니다.

### Changed

- **lich는 `lichdotdev/lich`에 있습니다.** 저장소는 [lichdotdev](https://github.com/lichdotdev)
  조직으로, 사이트는 [lichdotdev.github.io/lich](https://lichdotdev.github.io/lich/)로
  옮겨졌습니다. 예전 GitHub 링크, 클론, 업데이트 확인은 리다이렉트되지만, 예전 사이트의 북마크는
  그렇지 않습니다.

### Fixed

- **새로운 기능 안내가 전환한 언어를 따릅니다.** 네이티브 창에서 인터페이스 언어를 바꾼 뒤에도
  릴리스 노트가 처음 읽었던 언어로 남아 있었고, 그룹 이름만 새 언어로 표시되었습니다.
- **diff가 CJK 텍스트에서 멈추거나 파일마다 메모리가 쌓이는 문제를 고쳤습니다.** 네이티브 창에서
  중국어, 일본어, 한국어 텍스트가 있는 리뷰나 풀 리퀘스트의 파일은 새 문자를 찾을 때마다 몇 초씩
  멈출 수 있었고, 모든 파일의 diff가 글꼴 사본을 따로 가지고 있어 큰 풀 리퀘스트는 수백 메가바이트를
  차지했습니다.

## [0.70.0] - 2026-10-17

### Added

- **새로운 기능 안내가 사용자의 언어로 표시됩니다.** 업데이트 후 열리는 대화상자가 릴리스 노트와
  그 그룹 이름을 선택한 인터페이스 언어로, 두 창 모두에서 보여 줍니다. 아직 번역이 없는 빌드의
  노트는 영어로 표시됩니다.
- **네이티브 창에서 세션을 포크할 수 있습니다.** 카드를 오른쪽 클릭해 포크 › 여기서를 고르면
  같은 체크아웃의 바로 아래 새 카드에서 대화를 이어 가고, 포크 › worktree…를 고르면 커밋하지 않은
  변경 사항과 함께 새 worktree로 옮깁니다. 복사본은 원본의 이름("auth-refactor 2")을 따르고
  포크 표시가 붙습니다. Claude Code, Codex, opencode에서만 가능하며, 다른 프로바이더는 재개만
  할 수 있습니다.
- **네이티브 창이 두 카드가 같은 대화를 실행하면 경고합니다.** 에이전트 자체 TUI 안에서, 이미 다른
  카드에 열려 있는 대화를 재개하면 오른쪽 아래에 경고가 뜨며, 전환을 누르면 재개한 카드가 닫히고
  그 대화를 가지고 있던 카드가 나타납니다.
- **네이티브 창이 이미지를 표시합니다.** PNG, JPEG, GIF, WebP, BMP는 파일 탭의 미리 보기에서 체커보드
  위에 크기 및 해상도와 함께 열리고, 리뷰에서는 변경된 이미지의 이전과 이후가 나란히 표시됩니다.
  PDF나 미리 볼 수 없는 다른 파일은 오류 대신 기본 앱에서 열기와 폴더에서 보기를 제공하며, 풀
  리퀘스트의 바이너리 파일은 GitHub의 해당 파일로 연결됩니다.
- **네이티브 창이 사용자의 언어로 표시됩니다.** 네이티브 창의 모든 화면이 포르투갈어, 스페인어,
  중국어로 표시되며, 설정 › 일반에서 웹 창의 모양 아래에 있는 것과 같은 인터페이스 언어와 프롬프트
  언어를 고를 수 있습니다. 고르기 전에는 시스템 언어를 따릅니다. 중국어 글꼴이 없는 컴퓨터에서
  중국어를 고르면 Noto Sans SC(약 25MB)를 lich 자체 폴더로 다운로드할지 묻습니다.
- **일본어를 지원합니다.** 두 창 모두 일본어로 표시되며, 일본어는 프롬프트 언어이기도 해서 lich가
  에이전트에게 일본어로 말합니다. 네이티브 창은 일본어, 중국어, 한국어를 각자 지역의 글꼴(Noto Sans
  CJK, Yu Gothic, Hiragino, Malgun Gothic 등)이 설치되어 있으면 그 글꼴로 그리므로 한자가 더 이상
  중국어 자형으로 나오지 않으며, 글꼴이 없으면 중국어의 Noto Sans SC처럼 Noto Sans JP나 KR을
  다운로드할지 묻습니다. README도 일본어로 제공됩니다.
- **한국어를 지원합니다.** 두 창 모두 한국어로 표시되며, 웹에서는 설정 › 모양, 네이티브 창에서는 설정
  › 일반에서 고릅니다. 한국어는 프롬프트 언어이기도 해서 브리핑, 전달 메시지, 알림이 에이전트에게
  한국어로 전달됩니다.
- **lich가 러시아어를 지원합니다.** 웹 창에서는 설정 › 모양, 네이티브 창에서는 설정 › 일반의
  인터페이스 언어로 Русский를 고를 수 있고, 프롬프트 언어로도 고를 수 있어 lich가 에이전트에게
  입력하는 브리핑, 전달 메모, 인계도 러시아어로 표시됩니다. 개수는 러시아어의 one, few, many 형태를
  따릅니다(1 файл, 2 файла, 5 файлов).
- **macOS와 Windows의 opencode 프로필, Windows의 Cursor CLI 프로필을 지원합니다.** 네이티브 창의
  설정 › 프로바이더에 Linux와 같은 방식으로 표시됩니다. macOS의 Cursor CLI와 macOS 및 Windows의 Kiro
  CLI에는 아직 없습니다. 이들은 로그인 정보를 키체인이나 어떤 설정으로도 옮길 수 없는 폴더에
  보관하므로, 프로필을 만들어도 모두 하나의 계정을 공유하게 됩니다.

### Changed

- **업데이트할 때마다 네이티브 창이 열립니다.** 각 릴리스의 첫 실행은 lich를 네이티브 창으로
  전환하며, 시작할 수 없으면 웹 창으로 대체합니다. 설정에서 다시 전환하면 다음 릴리스까지 lich는
  웹 창에 머뭅니다. 네이티브 창이 처음 열릴 때는 실험 단계라는 안내와 버그 신고 링크가 표시됩니다.
- **네이티브 창의 상태 링이 더 가벼워졌습니다.** 세션 카드 아이콘 둘레의 링이 더 가늘게 그려져,
  웹 창과 같은 굵기로 보입니다.

- **네이티브 창의 단축키 키캡이 더 넉넉해졌습니다.** 명령 팔레트, 단축키 오버레이, 설정 › 단축키의
  키캡에서 글자 둘레의 여백이 늘었고 글자는 가운데에 놓입니다.

- **네이티브 창의 설정이 전역에서 열립니다.** 상단 바의 톱니바퀴는 마지막으로 보던 범위 대신 항상
  설정을 전역에서 열며, 프로젝트 탭은 여전히 프로젝트 설정…에서 해당 프로젝트의 설정을 엽니다.

- **네이티브 창의 명령 팔레트가 더 차분해졌습니다.** 세션, 프로젝트, 메시지는 각각 한 줄을
  차지하고 이름 뒤에 경로가 붙으며, worktree의 경로는 마지막 세 부분을 보여 줍니다. 사용자를
  기다리는 세션이 먼저 나오고 그렇게 표시되며, 필터 탭은 알약 모양 대신 밑줄로 바뀝니다. 기록의
  닫힌 세션은 오른쪽에 브랜치와 경과 시간을 보여 주고, 검색어가 대화와 일치했을 때만 단어를 강조해
  둘째 줄을 보여 줍니다.

### Fixed

- **재시작된 세션이 더 이상 영원히 바쁜 것으로 표시되지 않습니다.** 턴 도중 에이전트가 죽었거나 턴
  도중 닫힌 세션이 같은 카드로 돌아왔을 때 다른 세션에는 여전히 바쁜 것으로 나타나, 그 세션에 보낸
  작업이 끝나지 않을 턴을 기다렸습니다. 이제 새 세션처럼 상태 없이 시작합니다.
- **Codex, Cursor CLI, Antigravity, Crush가 이미 답한 것을 다시 묻지 않습니다.** 이들 중 어느
  프로바이더든 샌드박스 세션은 바로 프롬프트에서 열립니다. Cursor CLI와 Antigravity는 신뢰한
  폴더의 worktree에서 다시 묻지 않고, Antigravity는 그 하위 폴더에서도 묻지 않으며, Crush는 새
  worktree마다 초기화할지 묻지 않습니다. 샌드박스 oh-my-pi 세션은 더 이상 설정 마법사에서 열리지
  않습니다.
- **Claude Code가 이미 답한 곳에서 "이 폴더를 신뢰하나요?"를 다시 묻지 않습니다.** 메인 계정에서
  신뢰한 폴더는 다른 모든 Claude Code 프로필에서도 그곳의 다음 세션부터 신뢰되고, 샌드박스 Claude
  Code 세션은 질문 없이 열립니다. lich가 대신 연 세션이 더 이상 Enter를 누르면 종료되는 그 화면에
  머물지 않습니다.
- **다시 연 네이티브 창이 각 세션이 어디로 갔는지 알아냅니다.** `cd`로, 또는 tmux나 ssh로 이동한
  세션이 다음 `cd`까지 체크아웃의 경로, 브랜치, 변경 사항을 표시한 채 돌아왔는데, 이제 창이 연결될
  때 각 세션이 마지막으로 있던 곳을 읽어 옵니다.
- **네이티브 창이 에이전트 프롬프트를 프롬프트 언어로 작성합니다.** 풀 리퀘스트와 이슈 인계, 그리고
  리뷰 코멘트 묶음이 항상 영어로 입력되었습니다.
- **재연결 중 테마를 바꿔도 네이티브 창이 더 이상 충돌하지 않습니다.** 창이 재시작된 lich에 다시
  연결되는 동안 테마를 바꾸거나 시스템이 밝은 테마와 어두운 테마를 전환하면, 재연결이 방금 해제한
  터미널을 그려 창이 종료될 수 있었습니다.
- **중국어, 일본어, 한국어 텍스트가 더 이상 Linux의 네이티브 창을 멈추지 않습니다.** CJK 텍스트로
  가득한 세션, 리뷰, 풀 리퀘스트가 창을 몇 초간 멈춰 "응답 없음"이 뜰 정도였고, 확대하면 멈춤이
  다시 나타났습니다.
- **네이티브 창이 메모리를 덜 사용합니다.** 각 세션의 터미널과 리뷰가 대체 글꼴을 각자 따로
  불러왔고, CJK나 이모지 글꼴은 하나에 수십 MB였습니다. 이제 세션 여섯 개를 열었을 때 메모리
  사용량이 이전의 약 절반입니다. CJK 글꼴이 설치된 컴퓨터에서는 시작도 더 빠릅니다.
- **대화가 이미 열려 있는 세션을 다시 열면 그 카드로 포커스가 이동합니다.** 기록의 닫힌 세션, 실행
  취소한 닫기, 기존 worktree가 다른 카드가 아직 실행 중인 대화의 두 번째 카드로 돌아와 둘이 같은
  대화 기록에 썼습니다. 이제 기록은 그런 대화를 마지막으로 닫은 시점 기준으로 한 번만 보여 주고,
  지우기는 그 대화의 모든 사본을 제거합니다.

## [0.69.0] - 2026-10-16

### Added

- **macOS에서 네이티브 창을 사용할 수 있습니다(실험).** Lich.app이 Apple Silicon과 Intel 모두에서
  lich와 함께 네이티브 창을 제공하며, 설정 › 모양 › 창에서 Linux, Windows와 같이 선택할 수
  있습니다. 터미널에서는 Option 키가 Terminal.app처럼 문자를 입력하므로, 에이전트의 Option+글자
  단축키는 터미널에 전달되지 않습니다. 지금까지는 GitHub의 macOS 머신에서만 실행해 보았습니다.
  알림은 클릭할 수 없는 일반 알림이며, 메뉴 막대 항목은 없습니다.
- **파일 트리가 훨씬 더 많은 파일 형식을 인식합니다.** Java, Gradle, C와 C++, C#, PHP, Ruby,
  Swift, SQL, Vue, Svelte, Terraform, Dockerfile, .gitignore를 비롯해 약 서른 가지가 더 이제
  파일 트리와 검색 결과에서 일반 파일 아이콘 대신 각자의 아이콘으로 표시됩니다.

### Fixed

- **`lich quit`이 네이티브 창을 닫습니다.** 백엔드가 사라진 뒤에도 창이 열린 채 lich를 연결이
  끊긴 것으로 표시했습니다. 이제 트레이의 종료와 중지 신호도 창을 닫으며, 업데이트 후 재시작할
  때는 창이 그대로 유지됩니다.
- **네이티브 창이 마지막 세션을 닫을 때 worktree 삭제를 제안합니다.** 닫힘 토스트에 실행 취소
  옆으로 worktree 삭제 버튼이 생겼으며, lich가 만들지 않은 worktree나 커밋하지 않은 변경 사항이
  있는 worktree는 삭제하기 전에 대화상자에서 알려 줍니다.

- **네이티브 창의 터미널이 포인터 아래의 셀을 선택합니다.** 클릭, 드래그 선택, 링크, 마우스를
  추적하는 프로그램이 모두 터미널 패딩만큼 어긋난 포인터 위치를 읽었기 때문에, 가리킨 셀이 아니라
  오른쪽 아래의 셀이 선택되었습니다. 배율이 적용된 디스플레이에서는 어긋남이 셀 하나에 가까웠습니다.
- **네이티브 창의 터미널이 이모지를 그립니다.** Noto Color Emoji 같은 컬러 이모지 글꼴은 각
  이모지를 윤곽선이 아니라 그림으로 저장하는데, 터미널은 윤곽선만 그릴 수 있어서 모든 이모지가
  빈 칸으로 보였습니다. 이제 컬러로, 두 셀 너비로 그려집니다.
- **네이티브 창의 파일 트리가 파일마다 언어 아이콘을 표시합니다.** 모든 파일이 똑같은 일반 파일
  아이콘으로 그려졌는데, 이제 웹 창이 붙여 주는 것과 같은 아이콘이 붙습니다.
- **에이전트가 연 풀 리퀘스트가 턴이 끝나면 카드에 표시됩니다.** 배지는 브랜치나 마지막 커밋이
  바뀔 때만 다시 확인했는데, 풀 리퀘스트를 열어도 둘 다 바뀌지 않아서 창이 포커스를 잃었다가
  되찾을 때까지 기다려야 했습니다.
- **Windows에서 네이티브 창이 열립니다.** 글꼴을 Windows에 없는 fontconfig로 찾으려다 시작할 때
  창이 닫혔고, lich는 웹 창으로 대체되었습니다. 이제 Windows에서는 설치된 글꼴을 직접 찾으며,
  터미널 기본 글꼴은 Cascadia Mono 또는 Consolas이고 설정의 글꼴 선택기에도 목록이 표시됩니다.
- **밝은 테마와 어두운 테마를 전환해도 네이티브 창이 더 이상 멈추지 않습니다.** Claude Code처럼
  터미널의 색 구성표를 따르는 세션이, 창이 아직 터미널을 붙잡고 있는 동안 변경 사실을 전달받아
  창이 멈춘 뒤 닫혔습니다.
