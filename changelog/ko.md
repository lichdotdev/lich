## [0.89.0] - 2026-11-12

### Added

- 처음 설치하면 에이전트를 고른 뒤 가이드 투어가 열립니다. 프로젝트 열기, 세션 시작, 터미널, 세션 행, worktree, 그리고 투어를 다시 찾는 방법을 차례로 안내합니다. 무언가를 하라고 요청하는 단계는 실제로 할 때까지 기다리며, 대화상자나 메뉴가 열려 있는 동안에는 투어가 물러납니다. 투어는 언제든 다시 실행할 수 있습니다. 오른쪽 위의 새 메뉴(설정도 여기에 있습니다)에서 가이드를 고르거나 명령 팔레트에서 실행하세요. 가이드는 worktree, 에이전트가 바꾼 내용 리뷰, 풀 리퀘스트, 새 세션으로 작업 넘기기, 세션의 브라우저도 안내합니다. 변경 사항이 있는 세션처럼 아직 갖추지 못한 것이 필요한 가이드는 메뉴에서 그 사실을 알려 줍니다.
- 푸터의 브랜치 이름을 클릭하면 터미널과 푸터 사이에 Git 패널이 열려, 기록을 읽는 동안에도 세션이 계속 보입니다. 모든 브랜치가 색이 있는 그래프로 표시되고, 그 옆에 브랜치와 태그가, 오른쪽에 선택한 커밋의 메시지와 파일이 나옵니다. 파일을 클릭하면 diff가 열립니다. 텍스트나 해시로 검색하거나 작성자, 날짜, 경로, 브랜치로 좁힐 수 있고, 세션이 올라 있는 브랜치에는 그 세션의 링이 붙습니다. 로컬 브랜치의 메뉴에서는 체크아웃, 이름 바꾸기, 그 브랜치에서 새 브랜치 만들기, 삭제를 할 수 있고 실행 취소도 가능합니다. 세션이 쓰고 있는 체크아웃과 어떤 브랜치에도 남지 않게 될 커밋을 만드는 삭제는 먼저 확인을 묻습니다. 높이와 열 너비는 끌어서 조절하고 저장되며, 터미널 위로 확장할 수 있고, 설정의 키보드 단축키에서 이 패널에 키를 지정할 수 있습니다.
- gh에 GitHub 계정이 둘 이상 로그인되어 있으면, 풀 리퀘스트 화면은 목록을 보여 주기 전에 프로젝트가 어느 계정을 쓰는지 묻습니다. gh가 마지막으로 전환한 계정으로 조용히 실행하지 않습니다. 프로젝트가 쓰는 계정에게 GitHub가 저장소를 숨길 때도 다시 물으므로, 설정을 거치지 않고 다른 계정을 고를 수 있습니다.
- 확장 프로그램이 자체 화면을 가질 수 있습니다. 확장 프로그램이 선언한 화면마다 상단 바의 알림 벨과 풀 리퀘스트 사이에 버튼이 생기며, 풀 리퀘스트 화면처럼 사이드바를 유지한 채 스테이지 전체 위에 열립니다. 열려 있는 동안 확장 프로그램 자체의 키보드 단축키가 동작하고, 키보드를 자신의 입력란에 둘 수도 있어 `/`로 검색창으로 이동할 수 있으며, Escape를 누르면 키보드가 돌아옵니다. 버튼의 점은 확장 프로그램이 멈췄음을 알려 줍니다. lich가 다시 시작하는 동안은 호박색, 포기한 뒤에는 빨간색이며, 그때 그 화면이 이유를 알려 주고 다시 시작과 폴더 열기를 제공합니다. 설정 › 확장 프로그램에서는 GitHub 저장소에서 설치하거나(사용 중인 시스템용으로 빌드된 최신 릴리스를 받아 릴리스의 체크섬으로 검증합니다), 디스크의 폴더에서 설치할 수 있습니다. 설치 전에 확장 프로그램의 이름, 버전, 출처를 밝히고 프로젝트와 세션에 대해 그 밖에 무엇을 할 수 있는지 쉬운 말로 나열하는 확인을 거치며, 설치를 누르기 전에는 아무것도 실행되지 않습니다. 목록에는 모든 확장 프로그램의 상태, 버전, 출처가 표시되고, 포기한 확장 프로그램을 다시 시작하거나, 폴더를 열거나, 삭제할 수 있습니다. 확장 프로그램의 상태 위에 마우스를 올리면 그 확장 프로그램이 할 수 있는 일이 표시됩니다. 확장 프로그램이 저장한 것은 폴더와 별도로 보관되며 삭제해도 남으므로, 업데이트 방법인 재설치를 하면 하던 곳에서 이어집니다. 삭제 확인에서 저장한 데이터도 삭제를 선택하면 그것까지 삭제합니다.
- 한 목록에서 다른 목록으로 항목을 끌어다 놓을 수 있는 확장 프로그램 화면은 이제 항목이 놓일 목록(비어 있는 목록 포함)을 강조 표시합니다. 사이드바가 세션이 들어갈 폴더를 강조하는 것과 같습니다.
- 확장 프로그램을 번역할 수 있습니다. 번역을 함께 제공하는 확장 프로그램은 상단 바와 설정 › 확장 프로그램에서 이름과 화면 제목을 인터페이스 언어로 표시하며, 시작할 때와 언어를 바꿀 때마다 어떤 언어인지 전달받아 자체 화면과 메시지도 그에 맞출 수 있습니다. 확장 프로그램 작성자는 lich의 번역 형식과 이를 읽는 Go 패키지를 쓸 수 있습니다. `docs/extensions.md`의 Translating an extension을 참고하세요.
- 확장 프로그램이 lich를 읽고 조작할 수 있습니다. 프로젝트와 그 worktree, 세션 목록, 세션 열기, 세션에 작업을 주고 답 받기, Claude Code 세션에 곁가지 질문하기, 세션의 상태 변화 수신, 프로젝트 서비스의 목록, 시작, 중지, 재시작과 출력 읽기, 체크아웃의 브랜치, 변경 사항, 업스트림 대비 앞서거나 뒤처진 커밋, 풀 리퀘스트 읽기, 데스크톱 알림 띄우기, 독에 파일 또는 세션의 브라우저에 페이지 표시하기를 에이전트가 lich의 도구로 하는 것과 같은 방식으로 할 수 있습니다. 확장 프로그램은 그릴 때 쓰는 것과 같은 채널로 요청하며, 매니페스트에 나열된 것만 요청할 수 있고, Go 패키지 `extension`에는 이 절차를 처리하는 클라이언트가 들어 있습니다. [Writing a lich extension](docs/extensions.md#calling-lich)을 참고하세요.
- 에이전트가 `lich check-log`나 `read_check_log` 도구로 자신의 풀 리퀘스트에서 체크가 왜 실패했는지 읽을 수 있습니다. `checks-failed` 감시가 작동한 뒤 호출할 도구입니다. 실패한 각 체크의 링크와, GitHub Actions 작업의 경우 실패한 각 단계의 마지막 80줄을 타임스탬프와 터미널 이스케이프 없이 보여 주며, `gh run view --log-failed`가 수십 킬로바이트를 건네는 자리에 몇 킬로바이트만 듭니다. 모든 프로바이더에서 동작하며, lich의 도구가 닿는 곳에서는 도구로, 그 밖에서는 명령으로 씁니다.

### Changed

- 세션 분할, 옆에 보기, 터미널 옆에 브라우저 열기가 이제 움직임을 갖습니다. 새 창은 분할한 가장자리에서 자라 나오고 이웃 창이 자리를 내주며, 빼낸 창도 같은 방식으로 줄어듭니다. 이전에는 둘 다 한 번에 바뀌었습니다. 각 터미널은 최종 크기를 한 번에 취하므로 에이전트는 한 번만 다시 그립니다.
- 분할 레이아웃에 있는 세션이 더 이상 프로젝트 탭 아래에 두 번 표시되지 않습니다. 프로젝트 탭에는 어떤 레이아웃에도 없는 세션이 표시되거나 모든 세션이 레이아웃에 있다는 안내가 나오고, 레이아웃에 있는 세션에는 사이드바에 열 표시가 붙습니다. 이를 클릭하면 레이아웃의 탭으로 이동합니다. 그 탭에는 자체 사이드바가 있어 각 프로젝트 이름 아래에 그 레이아웃의 세션만 나열하며, worktree, 부모와 자식 세션, 브라우저의 트리는 그대로입니다. 새 세션, 필터, 서비스는 프로젝트 탭에 남습니다. 레이아웃에서 빼기는 창뿐 아니라 세션 메뉴에도 있습니다. 모든 프로바이더에 적용됩니다.
- 사이드바의 링과 접기가 나머지 트리와 같은 방식으로 움직입니다. 세션이 작업을 시작하거나, 끝나거나, 사용자를 기다리느라 멈추면 링이 새 색으로 다시 그려지며, 이전에는 한 번에 바뀌었습니다. 체크아웃이나 폴더를 접으면 세션을 서브에이전트 위로 접을 때처럼 그 행들이 트리의 선을 따라 들어가고, 새 행의 링은 조금 더 빠르게 그려집니다.
- 세션의 브라우저가 같은 세션을 한 번 더 보여 주던 별도 탭이 아니라, 세션이 이미 있는 곳인 세션의 터미널 옆에 열립니다. 분할에서는 페이지가 그 세션의 창 옆에 놓이고 세션이 떠나면 함께 따라가며, 분할의 탭을 닫아도 눈에 보이지 않게 브라우저가 실행 중으로 남는 일이 없습니다. 페이지 헤더에는 최소화 버튼이 있어 페이지를 숨기되 에이전트를 위해 브라우저는 계속 실행하며, 브라우저를 닫는 닫기 옆에 놓입니다. 세션 메뉴의 브라우저는 최소화한 페이지를 다시 불러옵니다. 실행 중인 브라우저는 세션 아래 행으로 사이드바에도 나타나며, 열려 있는 사이트의 이름으로 표시되고 최소화된 동안에는 흐리게 보입니다. 클릭하면 페이지가 표시되고, 메뉴에서 최소화하거나, 창으로 옮기거나, 닫을 수 있습니다. 이전 버전에서 열려 있던 브라우저 탭은 복원되지 않으니 세션 메뉴에서 브라우저를 다시 여세요. 모든 프로바이더에 적용됩니다.
- 토스트는 푸터 바로 위의 오른쪽 아래 모서리에 놓이고 위로 쌓입니다. 이전에는 오른쪽 위에서 내려왔고, 확장 프로그램의 편집과 저장처럼 화면이 그곳에 두는 버튼을 가렸습니다. 오른쪽 아래 모서리에서 이미 기다리던 질문(프로세스가 종료된 세션, 두 카드에서 열린 대화, 에이전트가 연 브라우저, 프로필 제안)도 이제 다른 모든 토스트와 같은 스택에 들어갑니다.
- 인터페이스가 포르투갈어, 스페인어, 일본어, 한국어, 러시아어, 중국어에서 더 자연스럽게 읽힙니다. 각 언어를 전체적으로 다시 읽고 영어 문장을 지나치게 따라간 곳을 다듬었으며, 개념마다 하나의 용어로 통일했으므로 일부 레이블의 이름이 바뀌었습니다(예를 들어 포르투갈어에서 풀 리퀘스트 탭은 Checks입니다). 영어에서는 대시가 없어졌습니다.
- 세션 브라우저에서 에이전트의 커서 옆에 있는 배지가 프로바이더를 표시하던 것에서 에이전트가 하는 일을 표시합니다. 클릭 중, 입력 중, 스크롤 중, 이동 중 등이며, 프로바이더는 세션이 이미 알려 줍니다. 배지는 프로바이더의 아이콘을 유지하고, 각 동작 뒤에 잠시 남았다가, 에이전트가 생각하는 동안에는 화살표만 남깁니다. 모든 프로바이더에 적용됩니다.
- 세션의 브라우저 탭이 페이지의 각 프레임을 3~5배 빠르게 디코딩하므로 화면이 페이지보다 덜 뒤처지고, 애니메이션이 있는 페이지에서 창이 쓰는 CPU도 줄어듭니다. 소스에서 창을 빌드하려면 이제 libjpeg-turbo의 `libturbojpeg`가 필요하며, 패키지 이름은 `CONTRIBUTING.md`에 있습니다.

### Fixed

- 위임 세션을 연 세션의 창이 둘로 나누기에는 너무 좁지만 위임 세션을 쌓기에는 충분히 높을 때, 옆에 보기가 더 이상 "여기에는 창을 하나 더 놓을 공간이 없습니다"라고 답하지 않습니다. 이제 위임 세션이 그 창 아래에 놓입니다.
- 아주 큰 브라우저 창에 잔 노이즈나 필름 그레인이 있는 페이지를 표시하면, 창이 백엔드와의 연결이 받아 주는 크기보다 큰 이미지를 받아 모든 세션과의 연결이 끊길 수 있었습니다. 이제 그런 이미지는 건너뛰고, 창은 다음에 들어맞는 이미지가 올 때까지 마지막 이미지를 유지합니다.
- 하위 메뉴가 열어 준 메뉴 옆에, 어느 쪽이든 작은 간격을 두고 놓입니다. 창의 오른쪽 가장자리에서 왼쪽으로 뒤집히는 하위 메뉴가 더 이상 부모 메뉴의 일부를 가리지 않습니다. 상단 바의 메뉴가 더 넓어져 설정과 가이드가 답답하지 않습니다.
- HiDPI가 아닌 화면의 세션 브라우저는 페이지를 창 크기의 1.5배로 그린 뒤 모든 프레임을 맞게 줄였기 때문에 글자가 흐려지고, 큰 창에서는 애니메이션이 있는 페이지가 초당 약 30프레임에 머물렀습니다. 이제 브라우저는 창 자체의 배율로 그립니다. 글자가 선명하고 같은 창이 49~60프레임을 냅니다. 이미 열려 있는 브라우저는 시작했을 때의 배율을 유지하므로, 페이지 줌을 바꾸거나 창을 다른 밀도의 모니터로 옮긴 뒤에는 브라우저를 닫았다가 다시 열어야 선명한 프레임을 얻습니다.
- 풀 리퀘스트의 설명과 댓글, Markdown 미리보기, 확장 프로그램 화면에서 Markdown이 인용문을 흐린 글자의 막대 뒤에, 코드 블록을 별도의 패널 위에 그립니다. 둘 다 이전에는 주변 텍스트와 똑같이 읽혔습니다.
- 풀 리퀘스트의 설명이나 댓글에 있는 펜스 코드 블록이 두 번 표시되었습니다.

### Added

- 에이전트가 길어진 컨텍스트에서 계속 작업하는 대신 깔끔하게 끊어지는 지점에서 자기 자신의 새 세션에 작업을 넘길 수 있습니다. `handoff_session` 도구(와 `lich handoff`)는 짧은 노트를 받습니다. 노트에는 끝난 일, 브랜치와 커밋, 다음 단계, 주의할 점이 담기며, 같은 체크아웃에서 같은 프로바이더, 모델, 프로필로 새 세션을 열고 그 프롬프트에 노트를 입력합니다. 이전 세션은 사용자가 닫을 수 있도록 열려 있습니다.
- 다른 세션의 작업이 아직 답을 기다리는 동안 대화가 압축된 Claude Code 세션은 압축이 끝나면 그 작업들을 다시 안내받습니다. 각 티켓과 요청 내용, 그리고 답하는 명령입니다. 이전에는 요약에서 티켓이 빠질 수 있었고, 작업이 둘 열려 있을 때 어느 쪽도 지정하지 않은 답은 거부되어 요청한 세션들이 아무것도 아닌 것을 기다렸습니다.
- 그 사이에 작업 없이 서로 메시지만 주고받는 두 세션은 중단됩니다. 연속 두 번째 메시지는 교환이 루프처럼 보인다는 노트와 함께 에이전트에 전달되고 네 번째는 거부되어, 두 세션이 아무 의미 없이 토큰을 쓰는 일이 멈춥니다. 실제 작업 뒤에 오는 메시지, 세 번째 세션의 합류, 사용자가 어느 세션에든 입력하는 것은 횟수를 다시 시작합니다. 세 개 이상의 세션을 도는 루프도 마찬가지입니다. 받은 메시지를 전달하는 일만 한 세션이 연달아 보낸 다섯 번째 전달 메시지는 거부됩니다. Crush 세션은 도구를 보고하지 않으므로 중단되지 않습니다.

### Security

- 샌드박스에서 실행 중인 세션은 더 이상 lich 자신의 토큰을 가지지 않습니다. 그 세션만을 위해 발급된 토큰을 받으며, lich는 격리된 에이전트가 쓸 일이 있는 호출에만 이를 받아들입니다. 곁에 있는 세션에 메시지 보내기, 세션 열기와 조종하기, 자신의 브라우저 다루기, 프로젝트의 서비스와 비용 읽기입니다. 서비스 시작이나 편집(샌드박스 밖의 사용자 컴퓨터에서 명령을 실행합니다), 샌드박스 단계 자체 같은 설정 변경, 다른 세션의 터미널에 입력하기와 그 밖의 모든 호출은 이유를 알리는 메시지와 함께 계속 거부됩니다. 샌드박스 안에서 연 세션은 해당 체크아웃의 샌드박스 설정이 무엇이든 마찬가지로 격리되며, 격리된 세션은 자신도 격리된 세션에만 메시지를 보내거나, 입력을 넣거나, 제어하거나, 질문할 수 있습니다. 메시지는 그것을 받은 에이전트가 실행하므로 격리되지 않은 세션에 보낸 메시지는 사용자의 컴퓨터에서 실행되기 때문입니다. 답장은 누구에게나 도달하며, 격리된 작업자가 보고하는 방식이 이것입니다. 격리된 세션은 worktree를 강제로 닫을 수도 없습니다.
- 샌드박스는 lich 자신의 디렉터리와 다른 세션의 worktree를 숨깁니다. `~/.config/lich`(lich의 토큰, 데이터베이스, 다른 계정의 프로필)와 `~/.local/share/lich/worktrees`는 `~/.config`와 `~/.local/share`의 일부로서 격리된 세션 안에서 읽을 수 있었습니다. 이제 각각 위에 빈 디렉터리가 놓이고, 세션 자신의 프로필, 가져다 놓은 파일, 훅 스크립트, 체크아웃만 다시 마운트됩니다.
- `http://127.0.0.1:<port>/`에서 세션의 체크아웃을 제공하는 세션 브라우저의 로컬 파일 서버는 이제 `127.0.0.1:<port>` 또는 `localhost:<port>` 앞으로 온 요청에만 응답합니다. 일반 브라우저의 페이지가 자신이 제어하는 이름을 사용자의 컴퓨터로 향하게 해서 그것을 통해 `.env` 파일을 포함한 체크아웃을 읽을 수 있었으며, 이제 그런 요청은 거부됩니다.
- 자체 업데이트를 마치기 위해 lich가 붙여 넣는 명령은 curl의 표준 입력으로 전달되는 요청 헤더에 세션 토큰을 담아 lich에 보내므로, 같은 컴퓨터의 모든 사용자가 읽을 수 있는 프로세스 명령줄에 더 이상 나타나지 않습니다. 루프백 리스너는 `?token=`과 함께 `Authorization: Bearer <token>`도 받아들입니다. `install.sh`가 수행하는 재시작도 마찬가지입니다.
- lich 자신의 설정 디렉터리(Linux에서는 `~/.config/lich`)는 시작할 때마다 사용자만 읽을 수 있게 설정되므로 기존 설치도 강화됩니다. 프롬프트와 세션 텍스트가 그곳의 데이터베이스에 있습니다. 그 위의 디렉터리는 그대로 둡니다.

- 세션 브라우저 페이지의 메모 트레이에 리뷰 코멘트 묶음처럼 전체에 대한 메모를 쓸 수 있는 입력란이 생겼습니다. 여기에 쓴 내용은 에이전트가 받는 메시지의 끝을 맺습니다. Enter는 메모를 보내고, Shift+Enter는 새 줄을 시작하며, 지우기는 나머지 메모와 함께 입력란을 비웁니다.

### Changed

- 창이 그리는 매 프레임마다 CPU를 약 10분의 1 덜 사용합니다. 어차피 프레임 전체를 그릴 때는 프레임에서 바뀐 부분을 더 이상 따로 계산하지 않습니다.
- 창 위에서 포인터를 움직여도 이동할 때마다 다시 그리지 않고, 포인터 아래의 무언가가 바뀔 때만 그립니다. 마우스를 추적하는 에이전트(Claude Code가 그렇습니다)도 포인터를 움직일 때 출력을 즉시 그리게 만들지 않습니다. 마우스에 손을 올리고 있는 동안 전력이 덜 쓰입니다.
- 터미널의 링크는 클릭으로 여는 키인 Ctrl(macOS에서는 Cmd)을 누르고 있는 동안에만 밑줄이 그어지고 포인터가 손 모양으로 바뀝니다. Ghostty와 같습니다. 이전에는 포인터 아래의 모든 링크에 밑줄이 그어졌습니다.
- 코드, 리뷰, Pulls에서 리뷰 코멘트 묶음 아래의 메모가 이제 쓰는 만큼 늘어나는 입력란입니다. Shift+Enter는 새 줄을 시작하고, Enter는 여전히 묶음에 추가합니다.

### Fixed

- 위로 스크롤해 둔 터미널에 입력하거나 붙여넣으면 대부분의 터미널처럼 맨 아래로 돌아가 입력한 내용이 보입니다. 이전에는 텍스트가 세션에 전달되는데도 화면은 스크롤백에 머물러 있어서 직접 아래로 스크롤해야 보였습니다.
- 터미널 텍스트가 창의 나머지 텍스트와 같은 굵기로 보입니다. 이전에는 글자마다 부드러운 가장자리가 다르게 섞여서, 다크 테마의 밝은 텍스트는 실제보다 가늘게, 라이트 테마의 어두운 텍스트는 더 굵게 보였습니다.
- 셸 rc가 값에 줄바꿈을 넣어 내보내는 변수(인증서, 키)가 세션에 온전히 전달됩니다. 이전에는 첫 줄만 전달되었고, 뒤쪽에 `NAME=value`처럼 쓰인 줄은 별도의 변수로 들어왔습니다.
- Pulls 화면의 파일 탭에서 확인함으로 표시한 파일은 풀 리퀘스트를 다시 열 때 새 커밋이 그 파일을 바꾸기 전까지 접힌 채로 열립니다. 이전에는 펼쳐진 상태로 돌아왔습니다.
- lich를 종료한 직후 다시 열거나 업데이트 후 다시 실행할 때, 이전 lich가 아직 프로젝트의 서비스를 멈추는 중이어도 더 이상 "lich could not listen on 127.0.0.1:47821"로 실패하지 않습니다. 이제 종료할 때 서비스를 기다리기 전에 포트를 먼저 해제합니다.

## [0.84.0] - 2026-11-03

### Added

- 풀 리퀘스트 화면에서 풀 리퀘스트의 대화 탭은 GitHub처럼 왼쪽 열에 각 작성자의 GitHub 프로필 사진을 리뷰와 코멘트 옆에 보여 줍니다. 대화 탭과 파일 탭에서 리뷰 스레드 안의 코멘트는 선으로 구분됩니다. 사진이 로드되기 전이나 사진이 없는 계정에는 작성자의 이니셜이 그 자리를 채웁니다.
- 풀 리퀘스트 설명과 코멘트의 작업 목록이 문자 그대로의 `[x]`나 `[ ]` 대신 체크 여부가 표시된 체크박스를 보여 줍니다.
- 풀 리퀘스트 설명과 코멘트의 최상위 제목은 GitHub처럼 텍스트 너비 전체에 밑줄이 그어집니다.
- lich 색상 테마를 작성, 포팅, 수정하는 lich 플러그인의 테마 스킬이 이제 opencode, oh-my-pi, Crush, Kiro CLI에도 `lich-theme`로 제공됩니다. 이전에는 Claude Code, Codex, Antigravity, Cursor CLI에만 있었습니다. opencode에서는 `/lich-theme` 명령입니다. 설정 › 프로바이더에서 플러그인을 다음에 설치하거나 업데이트할 때 적용됩니다.
- opencode 2가 lich에서 실행됩니다. lich는 버전으로 opencode 1과 구분하고 2가 기대하는 방식으로 엽니다. 세션마다 자체 서버를 두므로 프로필, 모델, lich의 도구가 전달되며, 포크, 긴 붙여넣기 펼치기, 프로필 로그인, OpenCode Go 게이지가 opencode 1에서와 같이 동작합니다. opencode 2에서 시작한 대화와 그것이 이어 간 opencode 1 대화는 다시 비용, 마무리 말, 검색 결과를 보여 주고 기록에 나열됩니다. 카드의 스피너, 링, 벨, 제목에는 설정 › 프로바이더에서 설치하는 lich 플러그인의 다음 릴리스가 필요하며, 이 릴리스는 이제 opencode 2가 플러그인을 읽는 위치에 설치되고 이전 lich가 설치한 사본을 대체합니다. lich가 연 세션은 opencode 2의 공유 백그라운드 서버에 없으므로 `opencode pair`와 데스크톱 앱에서는 보이지 않습니다.
- 풀 리퀘스트 화면 개요의 설명 제목에 GitHub의 코멘트처럼 ⋯ 메뉴가 있습니다. 링크 복사는 풀 리퀘스트의 주소를, Markdown 복사는 작성된 그대로의 설명을 복사하고, 편집은 설명을 편집하도록 엽니다. 이전에는 제목 옆의 편집 버튼이 그 역할을 했습니다.
- 에이전트가 서비스 푸터에서처럼 프로젝트의 서비스를 관리할 수 있습니다. 서비스를 나열, 생성, 편집, 삭제, 시작, 중지, 강제 중지, 재시작하고, 모든 서비스를 시작하거나 중지하며, 실행 중이든 중지되었든 서비스가 출력한 내용을 `*_service` MCP 도구나 터미널의 `lich service`로 읽을 수 있습니다. 서비스는 프로젝트 안의 이름으로 지정하며, 다른 이름을 지정하지 않으면 에이전트 자신의 서비스입니다.

### Changed

- 내 풀 리퀘스트에서는 풀 리퀘스트 화면이 더 이상 GitHub가 작성자에게 거부하는 승인이나 변경 요청을 제공하지 않으며, diff의 메뉴도 풀 리퀘스트에 코멘트를 제공하지 않습니다. 또한 선택한 줄이 없을 때 diff의 메뉴는 풀 리퀘스트에 코멘트를 비활성 상태로 보여 주던 것을 없앴습니다.
- 풀 리퀘스트 설명, 코멘트, Markdown 미리 보기가 더 읽기 쉬워졌습니다. 텍스트가 더 밝고, 제목과 링크가 더 뚜렷하며, 인라인 코드가 강조되고, 줄과 블록 사이 여백이 넓어졌으며, 줄바꿈된 목록 항목이 텍스트에 맞춰 정렬됩니다.
- 풀 리퀘스트 화면은 화면 전체에 프로젝트의 풀 리퀘스트 목록을 보여 주며 열리고, 풀 리퀘스트는 목록 옆이 아니라 그 자리에서 열립니다. 제목 위의 뒤로 가기 버튼은 떠날 때 그대로의 목록으로 돌아가고, 그 옆에서 번호를 누르면 다른 풀 리퀘스트의 메뉴가 열리며, 이전과 다음은 목록의 필터를 따라 이동합니다. 파일 탭에서는 파일 트리만 diff 옆에 있고, diff는 목록이 차지하던 너비를 얻습니다. 개요는 설명을 리뷰어, 체크, 병합 가능 여부, 브랜치가 있는 체크아웃이 담긴 열 옆에 놓으며, 탭 줄은 풀 리퀘스트의 크기로 끝납니다. 세션에서 열기와 병합은 헤더에 남고, 풀 리퀘스트에 필요하면 충돌 해결이나 CI 오류 고치기가 그 옆에 놓이며, 승인, 새로 고침, GitHub에서 열기는 ⋯ 메뉴로 옮겨 갑니다. 화면은 사이드바의 간격에 맞춰지고 버튼은 창의 나머지와 같은 크기이며, 리뷰 스레드가 다루는 코드는 코멘트와 떨어진 별도 블록에 놓입니다. 목록에서는 j와 k 또는 화살표로 이동하고, Enter로 열고, /로 필터로 이동합니다. 풀 리퀘스트에서는 Escape로 돌아가고, Alt와 화살표로 이전 또는 다음 풀 리퀘스트로 이동합니다.
- 기본 제공 다크 테마는 인터페이스와 터미널에 같은 중립 차콜 배경을 적용해 터미널의 푸른 기가 도는 검정을 없애고, 초록, 코랄, 호박색, 파랑, 보라, 청록의 더 밝은 터미널 및 구문 팔레트를 사용합니다. 라이트 테마는 이 색상들의 더 어두운 대응색을 사용하며, 밝은 터미널 배경에서의 대비에 맞춰 조정되었습니다.
- 세션의 브라우저가 더 이상 묻지 않고 닫히지 않습니다. 어떤 창에도 표시되지 않고 5분 동안 아무도 사용하지 않으면, 토스트가 브라우저를 닫을지 묻습니다. 닫기는 브라우저를 닫고, 열어 두기나 토스트를 밀어서 치우면 5분 더 유지합니다. 응답하지 않으면 토스트가 남고 브라우저도 열려 있으므로, 점심시간 동안 열어 둔 페이지가 돌아와도 그대로 있습니다. 브라우저를 쓰거나 에이전트가 쓰면 토스트가 사라집니다. 이전에는 세션에서 5분 떠나 있으면 브라우저가 닫혀 페이지, 탭, 로그인이 사라졌습니다.
- 풀 리퀘스트 화면에서 풀 리퀘스트의 열린 리뷰 스레드를 세션으로 보내는 버튼이 모든 탭의 헤더에서 세션에서 열기 옆에 주변 버튼과 같은 크기로 놓입니다. 이전에는 대화 탭 맨 위의 작은 버튼이어서 대화를 스크롤하면 보이지 않았습니다.
- 사이드바의 크기 조절 영역이 코드 및 리뷰 패널의 것처럼 사이드바와 세션 사이의 틈이 아니라 사이드바 자신의 오른쪽 가장자리에 있습니다.
- 사이드바는 세션의 트리입니다. 세션은 한 줄입니다. 링, 이름, 풀 리퀘스트와 변경 사항이 있고, 포인터를 올리면 나타나는 …이 닫기를 포함한 세션 메뉴를 여는 모서리가 있습니다. 카드의 다른 줄이 보여 주던 내용은 툴팁으로 옮겨 갔습니다. 턴이 실행하는 도구 또는 기다리는 대상, 경과 시간, 경로, 모델입니다. 각 체크아웃은 브랜치, 풀 리퀘스트, 변경 사항과 함께 독립된 행이며 그 세션들이 아래에 달립니다. 다른 세션이 연 세션(포크, `open_session`이나 `lich open`으로 연 세션, 서브에이전트 카드)은 다른 worktree에서 실행되더라도 그것을 연 세션 아래에 달리고, 부모 세션은 자식을 접을 수 있으며 개수와 대기 중 또는 읽지 않음 표시를 유지합니다. 행은 선을 따라 움직입니다. 부모가 펼쳐지거나, 세션이 열리거나, worktree나 폴더가 나타나면 행이 이름이 이미 적힌 채로 열리고 선이 그곳까지 내려가 링을 그립니다. 접거나 닫으면 이름이 사라지고 링이 지워지며 선이 위로 되돌아가고, worktree나 폴더의 마지막 세션이 떠나면 그 뒤를 이어 worktree의 행이나 폴더도 사라집니다. 폴더는 트레이 위에 놓이므로 끝나는 위치가 보입니다. 고정은 카드의 메뉴로 옮겨 갔고, 그 메뉴는 세션이 응답해야 하는 요청의 `lich reply` 명령도 복사합니다. worktree가 없는 프로젝트는 평평한 목록을 유지합니다. 접힌 사이드바는 같은 트리를 한 열로 보여 줍니다. 각 체크아웃의 노드, 세션을 지나는 선, 부모의 선에 놓인 자식의 더 작은 링, 트레이 위의 각 폴더이며, 그 행들이 같은 선을 따라 나타나고 사라집니다. 세션을 끌면 선에서 떨어지고, 트리에 합류할 위치에 점선 슬롯이 표시되며, 놓이면 선이 다시 그곳까지 그려집니다. 분류될 폴더나 worktree는 전체가 밝아집니다. 끌린 부모는 자식을 함께 데려가고, 세션은 트리가 유지하는 위치에만 놓이며 부모와 자식 사이에는 절대 놓이지 않습니다. 색상이 있는 폴더에 분류된 세션은 그 색상을 가져 폴더가 그것을 유지합니다. 끌어다 놓든, 메뉴에서 폴더를 고르든, 에이전트가 `file_session`이나 `lich file`로 분류하든 같고, 폴더에 열린 세션, 서브에이전트의 작업자, 그것을 요청한 세션도 그 색상을 가집니다. 사이드바 아래쪽의 폴더에 세션을 놓으면 다시 분류되며, 이전에는 위에 있는 worktree도 그것을 받으면 원래 자리로 돌아갔습니다. 접힌 사이드바에서도 세션을 끌 수 있고, 검색 버튼은 펼친 사이드바와 같은 필터를 열며 패널이 닫힌 뒤에도 레일을 계속 필터링합니다.
- 풀 리퀘스트 화면 개요에서 설명 제목과 그 ⋯은 설명이 그 아래로 스크롤되는 동안 구분선 위, 열의 맨 위에 고정되며, ⋯은 열의 오른쪽 가장자리에 있습니다.
- 풀 리퀘스트 화면의 로딩 플레이스홀더가 그 자리에 로드되는 내용과 일치합니다. 목록은 실제 행 높이의 행과 체크 열이 놓일 위치를 화면을 채워 보여 주고, 풀 리퀘스트는 버튼이 있는 제목 행, 실제 탭 줄, 열린 탭의 레이아웃(설명과 그 옆의 정보, 커밋, 체크, 대화의 아바타와 코멘트, 또는 파일의 도구 모음, 트리, 카드)을 몇 개의 일반 막대 대신 보여 줍니다. 대화와 diff도 로드되는 동안 한 줄의 텍스트 대신 같은 플레이스홀더를 보여 줍니다.

- 세션이 작업하는 동안 창이 30프레임이 아니라 영화의 속도인 초당 24프레임으로 그려지고, 세션 터미널의 출력은 자체 프레임을 요청하지 않고 바쁨 링의 다음 프레임에 그려집니다. 스트리밍하는 에이전트와 도는 링이 두 속도의 합이 아니라 하나의 프레임 속도만 소모합니다. 입력한 내용은 터미널이 에코하는 즉시 계속 표시됩니다.
- 커서가 가만히 있는 동안 터미널이 더 이상 매 프레임 커서 행을 다시 그리지 않으며, 행은 커서가 움직이거나 텍스트가 바뀔 때 다시 구성됩니다.
- Linux에서 창이 세션이 작업하는 동안 매초 24번 전체를 다시 칠하는 대신 지난 프레임 이후 바뀐 부분만 그리고 그 영역을 컴포지터에 알립니다. 바쁨 링만 돈 프레임은 링과 터미널의 커서 행만 그리며, 창 렌더러에서 그래픽 카드의 작업은 15분의 1로 줄어듭니다. Windows와 macOS는 계속 전체 프레임을 그립니다. 환경 변수의 `GIO_DAMAGE=off`는 버퍼 내용을 잘못 보고하는 그래픽 드라이버를 위해 Linux에서도 전체 프레임을 그립니다.
- 세션이 작업하는 동안 lich 창이 쓰는 프로세서가 절반으로 줄었습니다. 화면의 모든 아이콘, 링, 호가 매 프레임 윤곽선에서 다시 만들어졌는데, 이제 각각 한 번 만들어 그래픽 카드에 유지됩니다.

## [0.83.0] - 2026-10-29

### Added

- 터미널이 Kitty 그래픽 프로토콜로 보낸 이미지를 그리고, 셀의 크기를 픽셀 단위로 프로그램에 알려 줍니다(`CSI 14 t`, `16 t`, `18 t`). 이런 방식으로 아이콘이나 미리 보기를 표시하는 TUI, 예를 들어 파일 관리자 `tfm`이 이제 Kitty나 Ghostty에서처럼 lich 세션에서도 이미지를 보여 줍니다. 이전에는 이런 프로그램이 작은 텍스트 글리프로 대체되거나 아무것도 그리지 않았습니다. Sixel이나 tmux를 통해 보낸 이미지는 여전히 그려지지 않습니다.
- 세션 브라우저에 탭이 있습니다. 탭은 브라우저의 헤더에 놓이며 +를 누르면 새 탭이 열리고, 탭을 클릭하면 전환하고 ×를 클릭하면 닫습니다. 페이지가 새 탭이나 창으로 여는 것도 탭에 합류해 맨 앞에 놓이며, 닫으면 그것을 연 페이지가 그대로 돌아옵니다. 에이전트는 새 MCP 도구 `browser_tabs`와 `browser_tab`(또는 `lich browser tabs`와 `lich browser tab`)으로 탭을 나열하고 전환하며, 에이전트의 커서가 작업 중인 탭으로 이동합니다.
- `lich insert --focused`는 lich 창에 카드가 표시된 세션, 즉 앞에 있는 프로젝트 탭의 활성 카드에 붙여 넣습니다. 파일 관리자 동작이나 편집기가 파일의 폴더로 짐작하지 않고도 지금 보고 있는 에이전트에게 경로를 보낼 수 있습니다. `lich sessions --json`, `lich whoami --json`, MCP 도구 `list_sessions`가 그 세션에 `"focused": true`를 표시합니다. 창이 닫혀 있으면 표시되는 세션이 없고 `--focused`가 그렇다고 알려 줍니다.

### Changed

- 세션 브라우저에서 페이지가 새 탭이나 창으로 여는 것이 더 이상 그것을 연 페이지를 대체하지 않습니다. 이전에는 새 탭의 주소가 그 페이지 위에 로드되어, 로그인이나 페이지가 스크립트에 담고 있던 것이 사라졌고, 탭을 열고 그것이 끝나기를 기다리는 흐름이 깨졌습니다.

### Fixed

- 옆에 브라우저가 열려 있는 세션을 터미널에 포커스를 둔 채 닫아도 lich 창이 닫히지 않습니다.

## [0.82.0] - 2026-10-29

### Added

- `lich sessions --json`, `lich whoami --json`, MCP 도구 `list_sessions`가 세션 카드가 레이블 아래에 표시하는 줄을 담습니다. 세션이 작업 중일 때는 실행 중인 도구와 그 대상인 `tool`과 `detail`, 사용자를 기다릴 때는 `reason`입니다. 스크립트나 데스크톱 위젯이 창을 열지 않고도 각 에이전트가 무엇을 하는지 보여 줄 수 있습니다.
- 세션의 브라우저가 세션 체크아웃의 로컬 파일을 엽니다. 주소 입력란에 경로를 입력하거나 에이전트가 `browser_open`에 경로 또는 `file:` URL을 전달하면, lich가 체크아웃을 127.0.0.1의 http로 제공하며 포트는 worktree마다 따로 둡니다(체크아웃의 `LICH_WORKTREE_PORT`에 1000을 더한 값). 그래서 모듈 스크립트, `fetch`, 상대 경로 에셋이 동작하고 각 worktree가 자기 저장소를 유지합니다. 체크아웃 밖의 경로는 거부됩니다. 이전에는 로컬 파일을 아예 열 수 없었고, 미리 보려면 정적 서버를 직접 띄워야 했습니다.
- 세션 브라우저의 도구 모음에 확대/축소 버튼이 있습니다. 누르면 작은 메뉴가 열려 페이지 확대/축소를 10%씩 줄이고 늘리며 100%로 재설정할 수 있고, 각 컨트롤에 키보드 단축키가 표시됩니다. 이전에는 확대/축소를 키보드로만 바꿀 수 있었습니다.

### Fixed

- 다음에서 계속이 세션의 브라우저를 유지합니다. 세션을 다른 프로필로 옮기면 브라우저가 닫혀서, 세션이 다시 올라왔을 때 페이지와 쿠키가 사라져 있었습니다.
- 세션 브라우저가 바쁜 페이지를 따라갑니다. 애니메이션이 있거나 JavaScript를 많이 실행하는 페이지에서 브라우저 탭이 페이지보다 몇 초씩 뒤처지고 창의 나머지도 함께 기다렸는데, 이제는 최신 프레임으로 건너뜁니다.

### Added

- 세션 브라우저 도구 모음의 십자선으로 에이전트를 위해 페이지에 메모를 남길 수 있습니다. 포인터 아래의 요소가 윤곽선과 이름으로 표시되고, 포인터가 움직이면 윤곽선이 한 요소에서 다음 요소로 미끄러지듯 이동하며, 클릭하면 그 옆에 메모가 열리고, 각 메모는 번호로 요소에 고정되어 페이지가 스크롤되어도 따라갑니다. 메모는 페이지 아래쪽 위에 떠 있는 트레이에 모이며, 트레이는 크기가 바뀌지 않습니다. 트레이에서 메모에 호버하면 해당 요소가 강조되고, 메모나 번호표를 클릭하면 요소가 화면에 들어오도록 스크롤되며 메모를 편집할 수 있습니다. 스크롤되는 목록, 사이드바, 대화상자에 가려진 요소는 보이는 부분만 윤곽선으로 표시되고, 완전히 가려진 요소는 옆에 있는 것 위에 번호표를 남기지 않습니다. 보내기(또는 Ctrl+Enter)를 누르면 메모가 하나의 메시지로 세션에 입력됩니다. 어떤 요소인지, 에이전트의 `browser_click`이 받는 셀렉터, 개발 빌드에서 그 요소를 그린 React 컴포넌트, 그리고 사용자의 메모가 담깁니다. Ctrl+Shift+E(macOS에서는 Cmd+Shift+E)로 십자선을 켜고 끄며, Esc로 빠져나옵니다. 세션이 거부한 전송은 메모를 그대로 두고 그 이유를 트레이에 표시합니다.
- 세션의 브라우저가 파일을 다운로드합니다. 페이지가 링크, 버튼, 새 탭, 스크립트로 시작한 다운로드는 페이지가 지정한 이름으로 다운로드 폴더에 저장되며, 이미 있는 파일을 덮어쓰지 않고 ` (1)`을 붙입니다. 에이전트가 파일의 URL을 직접 열 수도 있습니다. 에이전트의 클릭, 키 누르기, 열기는 파일의 경로와 크기로 응답하고, 창에는 파일 이름을 알리는 토스트와 그 폴더를 여는 버튼이 표시됩니다. 이전에는 세션 브라우저의 다운로드 버튼이 아무 일도 하지 않았습니다.
- 에이전트가 브라우저 페이지를 반복해서 다시 읽는 대신 페이지가 바뀌기를 기다릴 수 있습니다. `browser_info`가 `wait_for`(나타나야 하는 텍스트)와 `wait_gone`(사라져야 하는 텍스트)을 받아 페이지 어디에서든 일치를 확인하고, 페이지에 표시되는 즉시, 또는 20초 뒤에 현재 페이지와 대기가 시간 초과되었다는 한 줄로 응답합니다.
- 에이전트가 세션 브라우저의 페이지가 깨졌을 때 알게 됩니다. 에이전트가 읽거나 클릭하거나 키를 누르는 각 페이지는 마지막으로 본 이후의 콘솔 오류를 한 번씩 담아 응답합니다. `console.error` 호출, 처리되지 않은 예외, 로드에 실패한 리소스이며, 짧은 한 줄로 줄여 처음 다섯 개와 그 밖의 개수를 알려 줍니다. 경고와 다른 메시지는 제외됩니다.
- 에이전트가 `close_project` 또는 `lich close-project`로 프로젝트를 닫을 수 있습니다. 탭이 창에서 사라지고 세션이 중지되며, 탭을 닫을 때처럼 다시 열 수 있게 보관됩니다. 에이전트가 실행 중인 프로젝트와 홈 프로젝트는 거부됩니다.
- 사용자와 에이전트가 세션 브라우저에서 페이지의 JavaScript 대화상자에 응답합니다. 페이지가 여는 alert, confirm, prompt, "이 페이지에서 나가시겠습니까?"는 세션의 브라우저 탭에서 페이지 위쪽에 카드로 표시되며, 연 사이트의 이름과 버튼, prompt라면 입력란이 있습니다. 사용자가 거기에서 응답하거나 에이전트가 `browser_dialog`로 응답하며, 이때 에이전트의 커서가 카드의 버튼을 누릅니다. 대화상자를 연 에이전트의 클릭은 그 대화상자를 담아 즉시 응답하고, 사용자가 응답한 대화상자도 에이전트에게 전달됩니다. 이전에는 alert를 띄우는 버튼이 페이지를 멈추게 해서, 에이전트의 클릭과 이후의 모든 읽기가 30초를 기다린 뒤 실패했습니다.
- 설정 › 일반에 터미널용 선택 시 복사 스위치가 있습니다. 기본값은 켜짐이며, 선택하는 즉시 복사합니다. 끄면 Ctrl+Shift+C(macOS에서는 Cmd+C)로 복사합니다.
- 세션의 브라우저가 인터페이스 확대/축소와 별개로 페이지를 자체적으로 확대/축소합니다. Ctrl+-와 Ctrl+=(macOS에서는 Cmd)로 10%씩 축소하고 확대하며 범위는 50%에서 200%까지이고, Ctrl+0은 100%로 되돌립니다. 축소한 페이지는 데스크톱 브라우저처럼 더 넓게 배치되므로, 창의 나머지를 줄이지 않고도 작은 화면을 쓸 수 있습니다. 확대/축소는 모든 세션의 브라우저에 적용되고, 100%가 아닐 때 도구 모음에 표시되며, 다음 시작에도 유지됩니다.
- 설정 › 일반 › 창 › 버튼에서 창의 최소화, 최대화, 닫기 버튼을 표시할지 선택합니다. 시스템 따르기, 항상 표시, 숨기기 중에서 고릅니다. 시스템 따르기는 기존 lich의 동작이며, Linux에서는 이제 시작할 때만 읽지 않고 lich가 열려 있는 동안 바탕 화면의 버튼 배치가 바뀌어도 따라갑니다. 항상 표시는 Hyprland처럼 창 관리자가 창을 꾸미거나 제목 표시줄 없이 타일링하는 곳에서도 버튼을 그립니다. 숨기기는 창에서 버튼을 없애며, macOS의 신호등 버튼도 포함됩니다.

### Added

- **서비스: lich가 시작해 프로젝트가 계속 실행하는 명령.** 컨테이너, 터널, 개발 서버를 프로젝트의 설정 › 서비스에 한 번 저장하면, 사이드바 맨 아래 프로필 위에 있는 서비스 행에서 시작할 수 있습니다. 닫혀 있을 때 이 행은 실행 중인 개수(2/3)를 보여 주고, 펼치면 각 서비스가 얼마나 오래 실행되었는지 또는 어떻게 끝났는지를 나열하며, 호버하면 시작, 중지, 다시 시작이 나타납니다. 클릭하면 입력을 받고 Ctrl+C로 중지할 수 있는 콘솔이 열립니다. 서비스는 터미널이 아닙니다. 명령이 끝나면 서비스는 중지된 것이고, 마지막 출력은 그대로 읽을 수 있으며, 시작을 누르면 다시 실행됩니다. lich와 함께 시작을 선택하면 해당 프로젝트가 열린 채 lich가 시작될 때마다 시작됩니다. 설정 › 서비스에서 전역을 선택해 저장한 서비스는 홈 디렉터리에서 실행되고 lich의 시작 화면에 표시되며, 프로젝트와 상관없이 계속 열어 두는 `lazydocker` 같은 것을 두기에 알맞습니다. 서비스는 프로젝트 탭이 있는 동안만 유지됩니다. 탭을 닫으면 중지되고, 프로젝트를 다시 열면 lich와 함께 시작하도록 저장된 서비스가 시작됩니다. 창을 닫아도 서비스는 계속 실행되며 트레이에 출력 보기, 다시 시작, 중지와 함께 나열됩니다. lich를 종료하면 서비스가 중지되고, 닫기 대화상자가 그 수를 알려 줍니다. 사이드바를 접으면 레일의 서비스 버튼이 같은 목록을 엽니다.

It'll be in the next commit."라고 답하고, 풀 리퀘스트가 다시 push되면 스레드를 해결 처리하면서 반영된 커밋을 답글로 남깁니다. 그때까지 스레드에는 보냄 · push 대기 중이 표시됩니다. 스레드를 건드리지 않은 push라도 해결 처리됩니다.

- 풀 리퀘스트 화면에서 코멘트를 편집하고 삭제할 수 있습니다. 리뷰 스레드 코멘트(대화 탭과 diff에서)나 풀 리퀘스트 코멘트 옆의 …에서 편집을 고르면 GitHub에서 그 자리에서 다시 쓰고, 삭제를 고르면 먼저 확인을 묻습니다. 제출된 리뷰의 요약도 편집할 수 있으며, 리뷰의 판정은 그대로입니다. …는 GitHub가 내 계정에 변경을 허용하는 항목에만 표시됩니다.
- 설정 › 모양에서 인터페이스 글꼴로 고정폭 글꼴을 고르면 터미널과 편집기에도 같은 글꼴을 쓸지 묻습니다. 모두에 사용은 둘 다 바꾸고, 인터페이스만은 기존 그대로 둡니다. 가변 폭 글꼴이나 시스템을 고르면 묻지 않습니다.
- 리뷰 묶음에서 대기 중인 코멘트를 보내기 전에 고쳐 쓸 수 있습니다. 연필 버튼을 누르면 대화상자가 열리고, 저장 또는 Ctrl+Enter로 저장합니다. 풀 리퀘스트의 대기 중인 리뷰에 있는 줄 코멘트에는 버리기 옆에 편집 버튼이 있어 입력 상자에서 열고, 저장 또는 Ctrl+Enter로 저장합니다.

### Removed

- 네이티브 창이 처음 열릴 때 표시되던 실험 단계라는 안내가 사라졌습니다. 네이티브 창은 lich의 유일한 창입니다.

### Fixed

- 풀 리퀘스트 화면의 파일 탭에서 쓴 세션용 코멘트가 이제 그 풀 리퀘스트 브랜치의 체크아웃에 있는 세션으로 전달됩니다. 이전에는 보내기가 풀 리퀘스트 화면을 열기 전에 열려 있던, 다른 브랜치를 리뷰 중인 세션에 코멘트를 입력했습니다. 그곳에 세션이 없으면 보내기가 세션을 열라고 안내하고 코멘트를 그대로 두며, 세션에서 열기가 세션을 시작합니다. 그 탭에서 보낸 줄 참조도 같은 방식으로 전달됩니다.
- 풀 리퀘스트 화면에서 풀 리퀘스트의 세션으로 이동은, 지금 있는 세션이 그 풀 리퀘스트의 체크아웃에 있으면 그 세션을 엽니다. 이전에는 항상 그곳의 첫 번째 세션을 열었습니다.
- 디스플레이 배율이 100%를 넘는 Windows에서 드래그가 다시 포인터를 따라갑니다. 설정 › 하단 바에서 끌던 항목이나 터미널에서 끌던 선택 영역이 화면이 100%인 것처럼 배율이 적용되어 커서에서 벗어난 곳에 놓였습니다.
- 세션에 보낸 리뷰 코멘트는 세션이 받을 때까지 유지됩니다. 세션이 묶음을 거부했을 때(예를 들어 중지된 세션) 코멘트는 이미 사라졌는데 "댓글을 보내지 못했습니다"가 표시되었지만, 이제 코멘트가 묶음에 남아 다시 보낼 수 있습니다. 마찬가지로 풀 리퀘스트 화면에서 풀 리퀘스트 리뷰를 제출하면 그 리뷰에 담긴 코멘트만 지워집니다. 이전에는 리뷰를 보내는 중에 쓴 코멘트도 함께 사라졌습니다.
- Windows에서 창이 lich 아이콘을 사용하고 lich의 작업 표시줄 버튼 아래에서 열립니다. 이전에는 일반 아이콘이 표시되었고, 작업 표시줄에 고정한 lich에서 실행하면 고정 버튼 옆에 별도의 버튼으로 열렸습니다.
- 창 전체에서 클릭의 결과가 바로 표시됩니다. 이전에는 많은 경우 마우스가 움직일 때까지 기다렸습니다. 대화상자 열기와 닫기, 도크와 설정의 닫기 버튼, 코드 탭에서 파일 열기, 찾기 바의 토글, 풀 리퀘스트 화면의 필터와 대화, 사이드바의 필터, 설정의 섹션, 스위치, 단계 선택과 선택기가 해당합니다. 세그먼트 컨트롤이 클릭 직후 두 옵션을 눌린 상태로 표시하는 문제도 없어졌습니다.
- 코드 탭의 파일 트리나 풀 리퀘스트의 파일 트리에서 폴더를 클릭하면 바로 열리거나 접힙니다. 이전에는 마우스가 움직일 때까지 기다렸습니다. 또한 코드 탭은 파일이 수만 개인 체크아웃의 트리를 몇 초 걸리던 것에서 밀리초 만에 만들며, 행의 호버가 이벤트 하나씩 늦지 않고 포인터를 따라갑니다.
- 업데이트 후 lich를 다시 시작하면 새 버전의 창이 열립니다. 이전에는 이전 창이 새 lich에 연결된 채 열려 있었고, lich를 닫았다가 다시 열 때까지 세션이 "want 8 arguments, got 9"와 함께 시작되지 않을 수 있었습니다. 창은 다시 시작과 함께 닫혔다가 돌아오며, 창 없이 실행 중인 lich는 창 없이 유지됩니다. 이 변경은 이 릴리스 다음 업데이트부터 적용됩니다.
- 코드 탭에서 열어 둔 파일에서 Ctrl+F를 누르면 찾기 바가 열리고 거기서 입력한 키가 바에 들어갑니다. 이전에는 둘 다 탭 뒤의 세션 터미널로 전달되었습니다. 터미널이 매 프레임마다 코드, 찾기 바, 모든 일치 항목 표시 목록에서 키보드를 가져갔기 때문입니다. 이제 터미널을 클릭하면 터미널이 키보드를 받으므로, 코드를 선택해 복사한 뒤 입력이 어디에도 들어가지 않는 일이 없습니다.
- 풀 리퀘스트 화면 목록의 풀 리퀘스트는 작성자 이름이 길어도 리뷰 판정이 잘리지 않습니다. 대신 이름이 줄어들고, 줄 끝의 체크아웃 폴더는 아이콘이 반쪽으로 보이지 않고 전체가 들어갈 때만 표시됩니다.
- 풀 리퀘스트 화면 목록에서 리뷰 스레드가 모두 해결된 풀 리퀘스트의 "변경 요청됨"이 제목과 마찬가지로 해결 표시가 있는 호박색으로 표시됩니다. 이전에는 작성자의 답을 기다리는 스레드가 남은 경우와 같은 빨간색이었습니다. GitHub는 리뷰어가 승인하거나 리뷰가 기각될 때까지 판정을 유지합니다. 초안의 "초안"은 이제 윤곽선이 있는 회색 배지이므로, 옆의 호박색 판정의 일부처럼 보이지 않습니다.

## [0.75.0] - 2026-10-21

### Added

- 리뷰 탭의 Markdown 파일에는 "파일을 컨텍스트로 추가" 옆에 미리보기 버튼이 있어, diff 대신 표와 링크를 포함해 렌더링된 파일을 보여 줍니다. 다시 누르면 diff로 돌아갑니다. 풀 리퀘스트 화면에서는 해당 풀 리퀘스트가 추가한 파일에만 이 버튼이 있습니다.
- 코드 탭에서 열어 둔 파일에서 Ctrl+F(macOS는 Cmd+F)를 누르면 파일 안의 텍스트를 찾을 수 있습니다. 파일 이름 아래에 나타나는 바가 일치하는 부분을 모두 강조하고, Enter와 Shift+Enter로 차례로 이동하며, 대/소문자, 단어 단위, 정규식 일치를 지원합니다. 바의 목록 버튼은 일치하는 줄을 모두 바 아래에 보여 주고, 하나를 누르면 코드의 해당 위치로 이동합니다. Escape로 닫습니다.
- 세션 카드의 툴팁에 세션이 실행 중인 모델이 표시됩니다. Claude Code, Codex, Kiro CLI에서 지원합니다. 예를 들어 `/model` 이후처럼 세션을 연 모델과 달라지면 "…(으)로 시작, … 실행 중"으로 표시됩니다.
- 풀 리퀘스트 화면에서 풀 리퀘스트의 제목과 설명을 편집해 GitHub로 보낼 수 있습니다. 제목 뒤의 연필 아이콘으로 그 자리에서 이름을 바꾸며, Enter를 누르거나 다른 곳을 누르면 저장되고 Escape를 누르면 취소됩니다. 개요의 설명 옆 편집을 누르면 Markdown으로 열리고, 저장 또는 Ctrl+Enter(macOS는 Cmd+Enter)로 저장합니다. 긴 설명은 스크롤바와 함께 필드 안에서 스크롤되어 저장 버튼이 화면에 남아 있습니다. 각각 바뀐 부분만 보내므로, 설명을 저장해도 그사이 GitHub에서 한 이름 변경이 되돌려지지 않습니다.
- 프로필에 고유한 색상과 이미지를 지정할 수 있습니다. 설정 › 프로바이더에서 프로필의 ⋯ 메뉴에 세션 카드와 같은 8가지 색상을 고르는 색상과, 최대 10 MB의 PNG, JPEG, GIF, WebP를 받아 가운데 정사각형을 사용하는 이미지 선택…이 생겼습니다. 이미지나 색상은 프로필이 표시되는 모든 곳에 나타납니다. 프로필 목록과 선택기, 사이드바 하단, 다음에서 계속입니다. 이미지 제거를 누르면 프로필 색상 위의 이니셜로 돌아갑니다.

## [0.73.0] - 2026-10-20

> [!IMPORTANT]
> **모든 사용자: 이제 네이티브 창이 lich의 유일한 창입니다.** lich는 실행할 때마다 네이티브 창을 열며, 웹 창과 내장 Chromium은 없어졌습니다.

### Added

- **Windows와 macOS의 네이티브 창에서 클릭할 수 있는 데스크톱 알림.** Linux와 마찬가지로, 입력이 필요하거나 턴을 마친 세션이 열기와 닫기 버튼이 있는 알림을 띄웁니다. 열기를 누르면 lich가 해당 세션의 카드로 이동하고, 응답하거나 세션을 열면 알림이 사라집니다. macOS에서는 Lich.app으로 lich를 실행해야 하며 권한을 한 번 요청합니다. Windows에서는 사용자를 기다리는 세션의 알림이 조작할 때까지 화면에 남습니다.
- 사용자 지정 바이너리로 세션을 시작하면 설정 › 프로바이더의 프로필 아래에 경고가 표시되며, 바이너리 경로와 그 위치를 보여 주는 버튼, 기본값으로 되돌리는 버튼이 함께 나옵니다. 자체 로그인 또는 설정 디렉터리를 지정하는 래퍼는 프로필보다 우선하며, 바이너리 설정은 화면 맨 아래에 접혀 있습니다.

### Changed

- 세션의 프로세스가 종료되면 터미널 하단의 띠 대신 오른쪽 아래의 토스트가 어떻게 할지 묻습니다. 대화가 있는 카드는 같은 대화를 다시 여는 재개(처음 시작한 프로필에서), 재시작처럼 카드에서 새 대화를 시작하는 새로 시작, 세션 닫기를 제공합니다. 셸이나 첫 프롬프트 전에 끝난 에이전트는 다시 시작과 세션 닫기를 제공합니다. 토스트를 닫으면 카드는 그대로 남고, 카드에 포커스하면 토스트가 다시 나타납니다.
- **프로젝트의 프로필이 모든 카드가 아니라 사이드바 맨 아래에 표시됩니다.** 한 프로바이더에 로그인이 둘 이상이면, 사이드바의 마지막 줄에 이 프로젝트의 새 세션이 시작되는 프로필이 표시됩니다. 화면에 보이는 카드의 프로바이더, 터미널이면 기본 프로바이더 기준입니다. 눌러서 다른 로그인을 고르거나(각 로그인의 5시간 사용량이 함께 표시됩니다) 전역의 로그인으로 되돌릴 수 있고, 다른 프로바이더는 같은 메뉴에서 바꿉니다. 카드에는 더 이상 브랜치 옆에 프로필 칩이 붙지 않습니다.

### Removed

- 웹 창. lich는 네이티브 창을 열며, 릴리스에 더 이상 Chromium이 포함되지 않습니다. 설정의 창 선택(웹 또는 네이티브)과 다른 창을 여는 트레이 항목이 없어졌고, `lich -- <chromium flags>`, `lich --shell`, `LICH_SHELL`도 없어졌습니다. 네이티브 창을 시작할 수 없으면 lich가 이유와 로그 위치를 알려 줍니다.

### Fixed

- Claude Code 또는 Codex 프로필로 로그인할 때, 브라우저에서 마치거나 붙여 넣은 코드를 제출하면 인증 중이라고 표시됩니다. 이전에는 대화 상자가 끝까지 로그인을 기다리기만 했고 코드 입력란은 그냥 비워졌습니다.

- Windows에서 네이티브 창으로 lich를 업데이트할 때 "Setup was unable to automatically close all applications"와 함께 롤백되던 문제를 고쳤습니다. 설치 프로그램이 교체해야 하는 `lich-native.exe`에서 창이 열린 채 남아 있었습니다. 이제 설치 프로그램이 실행되기 전에 창이 닫히고, lich가 돌아오면 다시 열립니다. 0.72.0 이하에서 업데이트할 때는 한 번 더 발생합니다. 메시지가 나오면 작업 관리자에서 `lich-native.exe`를 종료하고 다시 시도를 선택한 뒤, 시작 메뉴에서 lich를 여세요.
- lich가 종료되었거나 다시 시작 중이어서 없는 동안 네이티브 창을 닫으면, "창을 닫을 때" 설정과 관계없이 창이 닫힙니다. 묻기나 종료로 설정하면 창이 열린 채 세션을 셀 수 없다는 오류만 표시되었습니다.

- 세션이 끝난 뒤에도 계속 실행되던 플러그인 훅(예: WakaTime)이 파일을 남겨 "already holds"로 거부되던 문제를 고쳐, 다음에서 계속으로 Claude Code 대화를 방금 떠난 프로필로 되돌릴 수 있습니다.
