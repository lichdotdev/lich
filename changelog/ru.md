## [0.78.0] - 2026-10-22

### Added

- Комментарии можно изменять и удалять на экране Pull requests. Кнопка … рядом с комментарием в ветке ревью (на вкладке «Обсуждение» и в диффе) или с комментарием к pull request предлагает «Изменить», что переписывает его на месте в GitHub, и «Удалить», что сначала спрашивает подтверждение. Описание отправленного ревью тоже можно изменить; его вердикт остаётся прежним. … показывается только у того, что GitHub разрешает менять вашей учётной записи.
- Выбор моноширинного шрифта для интерфейса в «Настройки › Оформление» спрашивает, должны ли терминал и редактор использовать его тоже. «Использовать везде» применяет его к обоим; «Только интерфейс» оставляет их как были. Пропорциональный шрифт или «Системная» ничего не спрашивают.
- Комментарий, ожидающий в пакете ревью, можно переформулировать до отправки: его карандаш открывает комментарий в диалоге, сохраняется кнопкой «Сохранить» или Ctrl+Enter. У построчного комментария в отложенном ревью pull request есть кнопка «Изменить» рядом с «Отбросить», которая открывает его в поле, сохраняется кнопкой «Сохранить» или Ctrl+Enter.

### Removed

- Уведомление о том, что нативное окно экспериментальное, которое показывалось при первом открытии, убрано: нативное окно теперь единственное окно lich.

### Fixed

- Комментарии для сессии, написанные на вкладке «Файлы» pull request на экране Pull requests, уходят в сессию в checkout ветки этого pull request, тогда как раньше «Отправить» вводил их в ту сессию, что была открыта до экрана Pull requests и ревьюила другую ветку. Если такой сессии нет, «Отправить» предлагает открыть её и сохраняет комментарии; «Открыть в сессии» её запускает. Ссылка на строку, отправленная с этой вкладки, идёт тем же путём.
- «Перейти к сессии» на pull request на экране Pull requests открывает ту сессию, в которой вы находитесь, если она в checkout этого pull request, тогда как раньше всегда открывала первую сессию в нём.
- В Windows при масштабировании экрана выше 100% перетаскивание снова следует за указателем: элемент, перетаскиваемый в «Настройки › Нижняя панель», или выделение, перетаскиваемое в терминале, оказывались вдали от курсора, масштабированные так, будто экран на 100%.
- Комментарии ревью, отправленные в сессию, хранятся, пока сессия их не примет. Сессия, отказавшаяся от пакета (например, остановившаяся), показывала «Не удалось отправить комментарии», хотя комментарии уже исчезли; теперь они остаются в пакете для повторной отправки. Так же отправка ревью pull request на экране Pull requests убирает только те комментарии, которые оно несло, тогда как комментарий, написанный, пока ревью отправлялось, терялся вместе с ними.
- В Windows окно носит значок lich и открывается под кнопкой lich на панели задач, тогда как раньше оно показывало общий значок и, будучи запущенным из lich, закреплённого на панели задач, открывалось отдельной кнопкой рядом с закреплённой.
- Клики по окну показывают результат сразу, тогда как многие ждали движения мыши: открытие и закрытие диалогов, кнопки закрытия дока и настроек, открытие файла с вкладки «Код», переключатели панели поиска, фильтры и обсуждение на экране Pull requests, фильтр боковой панели, а также разделы, переключатели, лестницы и выбор значений в настройках. Сегментированный элемент больше не показывает две нажатые опции сразу после клика.
- Клик по папке в дереве файлов вкладки «Код» или в дереве файлов pull request открывает или сворачивает её сразу, тогда как раньше он ждал движения мыши. Вкладка «Код» также строит дерево checkout с десятками тысяч файлов за миллисекунды, тогда как раньше это занимало секунды, а подсветка строки при наведении следует за указателем без отставания на одно событие.
- Перезапуск lich после обновления открывает окно новой версии, тогда как раньше старое окно оставалось открытым на новом lich, а сессия могла не запуститься с «want 8 arguments, got 9», пока lich не закрывали и не открывали снова. Окно закрывается и возвращается вместе с перезапуском; lich, запущенный без окна, остаётся без него. Это вступит в силу с обновления после этого релиза.
- Ctrl+F на файле, открытом на вкладке «Код», открывает панель поиска, и набранные там клавиши попадают в неё, тогда как раньше и то и другое уходило в терминал сессии за вкладкой: терминал отбирал клавиатуру у кода, панели поиска и списка «Показать все совпадения» в каждом кадре. Клик по терминалу теперь передаёт ему клавиатуру, так что выделение кода для копирования больше не оставляет вас печатающим в никуда.
- Pull request в списке на экране Pull requests больше не обрезает вердикт ревью при длинном имени автора: имя сокращается, а папка checkout в конце строки показывается, только когда помещается целиком, а не половиной значка.
- Pull request в списке на экране Pull requests, у которого все ветки ревью разрешены, показывает «Запрошены изменения» янтарным цветом с отметкой о разрешении, как и его заголовок, вместо красного, как у того, что всё ещё ждёт автора. GitHub хранит вердикт, пока ревьюер не одобрит или ревью не будет отклонено. «Черновик» у черновика теперь контурный серый значок, поэтому он больше не читается как часть янтарного вердикта рядом.

## [0.75.0] - 2026-10-21

### Added

- У Markdown-файла на вкладке «Ревью» рядом с «Добавить файл как контекст» появилась кнопка предпросмотра: она показывает файл в отрендеренном виде, с таблицами и ссылками, вместо его диффа. Панель под названием файла подсвечивает все совпадения, переходит между ними по Enter и Shift+Enter и умеет учитывать регистр, искать слово целиком или по регулярному выражению. Кнопка со списком показывает под панелью все строки с совпадениями, а щелчок по строке переносит код к ней. Escape закрывает панель.
- Подсказка карточки сессии называет модель, на которой работает сессия, для Claude Code, Codex и Kiro CLI. Если это уже не та модель, на которой сессия была открыта, например после `/model`, строка читается как «Открыта на …, работает на …».
- Экран Pull requests редактирует название и описание pull request и отправляет их в GitHub. Карандаш после названия переименовывает его на месте: Enter или щелчок в сторону сохраняет, Escape отменяет. «Изменить» рядом с «Описанием» на вкладке «Обзор» открывает описание как Markdown, сохраняется кнопкой «Сохранить» или Ctrl+Enter (Cmd+Enter в macOS). Длинное описание прокручивается внутри поля, с полосой прокрутки, так что «Сохранить» остаётся на экране. Каждое из них отправляет только то, что изменило, поэтому сохранение описания никогда не отменяет переименование, сделанное тем временем на GitHub.
- У профиля может быть свой цвет и своя картинка. В Настройки › Провайдеры меню ⋯ профиля содержит «Цвет», с теми же восемью цветами, что и у карточки сессии, и «Выбрать изображение…», которое принимает PNG, JPEG, GIF или WebP до 10 МБ и сохраняет его квадрат по центру. Картинка или цвет показываются везде, где показан профиль: в списке и выборе профилей, в нижней части боковой панели и в «Продолжить в». «Удалить изображение» возвращает инициал на цвете профиля.

### Changed

- Блок карточек в боковой панели, будь то worktree, папка или закреплённый блок, теперь плавно вырастает, когда открывается его первая карточка, и сворачивается вместе с последней, тогда как раньше он появлялся и исчезал мгновенно. Заголовки, которые показываются, когда список делится на блоки, раскрываются так же и сворачиваются, когда остаётся один блок.
- Проверки pull request, которые ещё выполняются, теперь показывают вращающийся индикатор на вкладке «Проверки» и в строке состояния над вкладками, где раньше стояли неподвижные часы.
- Кнопки больше не проседают на пиксель при нажатии, так что все кнопки в окне ведут себя одинаково: те, у которых было это движение, теперь совпадают с теми, у которых его никогда не было.

### Removed

- **Breaking:** lich больше не запускает `.lich/setup-worktree.sh`, когда `lich open --worktree` или `open_session` агента начинает сессию в новом worktree. Файл в вашем репозитории остаётся нетронутым. Если ваши worktree полагались на него для установки зависимостей, запустите его сами в терминале нового worktree (`sh .lich/setup-worktree.sh`) или попросите об этом агента. Копирование ваших `.env*` файлов из gitignore (или того, что названо в `.worktreeinclude`) и порт dev-сервера `LICH_WORKTREE_PORT` остаются без изменений.

### Fixed

- `git commit`, `rebase` или `stash` агента больше не падают время от времени с ошибкой «Unable to create '.git/index.lock': File exists» из-за того, что lich в тот же момент читал статус или дифф этого checkout. Чтение в lich не трогает индекс.
- Карточка закрытой сессии снова плавно сворачивается в боковой панели, тогда как раньше она исчезала мгновенно.
- Ctrl+Z в сессии больше не замораживает её агента навсегда. Раньше он приостанавливал агента, и ничто в lich не могло его вернуть; теперь lich не передаёт эту клавишу сессии.
- Полосы в подсказке об использовании тарифа, в нижней части окна, снова показывают пустую дорожку в темах, где цвета popover и muted совпадают, например в Everforest, где рисовалась только заполненная часть.
- Открытие или закрытие списка pull request на экране Pull requests больше не заставляет вкладку активного проекта отпускать панель под ней и снова захватывать её. Вкладка остаётся прикреплённой на всём пути и переходит на список, когда тот заезжает под неё.

  существующий worktree могли вернуться второй карточкой на разговоре, который
  другая карточка ещё вела, и обе писали в один транскрипт. «История» теперь
  показывает такой разговор один раз, по последнему закрытию, а «Забыть»
  удаляет все его копии.


## [0.69.0] - 2026-10-16

### Added

- **Нативное окно на macOS, экспериментально.** Lich.app поставляет его вместе
  с lich на Apple Silicon и Intel, а Настройки › Оформление › Окно предлагает его
  так же, как на Linux и Windows. Клавиша Option вводит символы в его терминале,
  как в Terminal.app, поэтому сочетания Option+буква агента до него не доходят.
  Пока оно запускалось только на macOS-машинах GitHub: уведомления простые, по
  ним нельзя щёлкнуть, а пункта в строке меню нет.
- **Дерево файлов знает гораздо больше типов файлов.** Java, Gradle, C и C++,
  C#, PHP, Ruby, Swift, SQL, Vue, Svelte, Terraform, Dockerfile, .gitignore и
  ещё около тридцати типов теперь показывают собственную иконку в дереве файлов
  и в результатах поиска, где раньше был обычный значок файла.

### Fixed

- **`lich quit` закрывает нативное окно.** Оно оставалось открытым и показывало
  lich как потерянный после остановки бэкенда; Quit в трее и сигнал остановки
  тоже его закрывают, а перезапуск после обновления по-прежнему его сохраняет.
- **Нативное окно предлагает удалить worktree, когда закрывается его последняя сессия.** В
  уведомлении «Закрыто» рядом с «Отменить» появляется «Удалить worktree»; worktree, созданный
  не lich, или с незакоммиченными изменениями, называется в диалоге до удаления.

- **Терминал нативного окна берёт ячейку под указателем.** Щелчок, выделение
  перетаскиванием, ссылка и программа, отслеживающая мышь, считывали положение
  указателя со сдвигом на отступ терминала, поэтому выбранная ячейка оказывалась
  ниже и правее той, на которую указывали, почти на целую ячейку на дисплее с
  масштабированием.
- **Терминал нативного окна рисует эмодзи.** Шрифт цветных эмодзи, например
  Noto Color Emoji, хранит каждое эмодзи как картинку, а не как контур, а
  терминал рисовал только контуры, поэтому каждое эмодзи выглядело пустым
  местом; теперь они рисуются цветными, шириной в две ячейки.
- **Дерево файлов нативного окна показывает иконку языка каждого файла.** Каждый
  файл рисовался одним и тем же обычным значком; теперь у каждого та иконка,
  которую ему даёт веб-окно.
- **Pull request, который открывает агент, появляется на его карточке в конце хода.**
  Значок перепроверялся только при смене ветки или её последнего коммита, а
  открытие pull request не меняет ни то, ни другое, поэтому он ждал, пока окно
  потеряет и вернёт фокус.
- **Нативное окно открывается на Windows.** Оно искало шрифты через fontconfig,
  которого в Windows нет, поэтому закрывалось при запуске, и lich переходил на
  веб-окно. Теперь на Windows оно само находит установленные шрифты, по умолчанию
  Cascadia Mono или Consolas для терминала, и списки шрифтов в Настройках их
  показывают.
- **Переключение между светлой и тёмной темой больше не зависает в нативном
  окне.** Сессию, которая следует цветовой схеме терминала, как Claude Code,
  уведомляли об изменении, пока окно ещё держало свои терминалы, поэтому окно
  зависало и закрывалось.
