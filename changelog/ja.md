## [0.90.1] - 2026-11-12

### Added

- 拡張機能で、新しい描画によって同じグループの別の一覧に移されたカード（ほかの人が動かしたあとに再読み込みされたボードなど）が、元の位置からそこへスライドするようになりました。一つの一覧の中ではすでにそうなっていました。自分でドロップしたカードや、現れたり消えたりするカードはアニメーションしません。

### Fixed

- 拡張機能で、並べ替え可能な一覧でドラッグしたカードを離しても、そのカードが押されなくなりました。ドラッグのしきい値を超えて動いた押下はドラッグとして扱われ、単純なクリックだけがカード自身のハンドラーに届きます。
- 実行中の呼び出しが上限に達している拡張機能が、結果を読んだ直後にもう一度呼び出しても拒否されなくなりました。完了した呼び出しは、結果が送られる前に枠を空けます。

## [0.90.0] - 2026-11-12

### Added

- セッションのブラウザーで、ツールバーに追加された新しいボタンから、ページの Chrome DevTools をペインのもう 1 つのタブとして開けるようになりました。Elements、Console、Network、Sources があり、そのタブを選んでいる間はページの代わりに表示されます。ページがデバッガーで一時停止している間は、タブに一時停止のマークが付き、エージェントのブラウザーツールはページを操作せず、ページが一時停止中であることを伝えます。エージェントが DevTools を見ることも操作することもないので、どのプロバイダーでも同じように動作します。

### Changed

- セッションのブラウザー内の文字は、ページの動きが止まるとくっきり表示されます。最後の変化からしばらくすると、動いている映像では文字の周りに出るにじみや色のにじみのない状態で、ページが 1 回再描画されます。大きな写真を表示しているページは、すでに見た目が同じなので、動いている映像のままです。すべてのプロバイダーに適用されます。

### Fixed

- フッターのブランチをクリックすると、すぐに Git パネルが開くようになりました。これまでは、マウスを動かすまでスライドアップしませんでした。
- 拡張機能で、項目をドラッグしている最中のスクロール内にある一覧が、スクロールの終わりまで、下端も含めて強調表示されるようになりました。これまでは強調表示が下端なしで画面の外まではみ出していました。
- セッションのブラウザーのペインが、ウルトラワイドや 4K サイズの非常に負荷の高いページで最後のフレームのまま固まることがなくなりました。最大 2 倍の大きさのフレームがウィンドウに届くようになっています。
- NVIDIA GPU を使う Linux で、ウィンドウが GPU で動いているのに、`lich-native.log` に「no GPU acceleration, the window draws on the CPU」と出力されることがなくなりました。この行は、Mesa が CPU で描画するデスクトップ通知のアイコンの描画に由来していました。今後は、ウィンドウ自体に GPU がないときだけ出力されます。
- セッションのブラウザーでタブを切り替えると、新しいタブが前回表示していたページが表示されるようになりました。これまでは、新しいタブが描画されるまで前のタブのページが画面に残っていました。一度も前面に出たことのないタブは、空のペインを表示します。
- ウィンドウを別の密度のモニターに移動しても、セッションのブラウザーがくっきり表示されたままになります。移動の約 1 秒後に、lich が新しい倍率でブラウザーを再起動し、タブ、開いていたタブ、その DevTools、サインイン状態を引き継ぎます。入力途中のフォームやスクロール位置のように、ページの中にしかないものは最初からになります。ページにダイアログが表示されている間、デバッガーで一時停止している間、エージェントがページを操作している間、および独自のウィンドウで開いているブラウザーでは、再起動は行われません。ページのズームを変えても再起動しません。

## [0.89.0] - 2026-11-12

### Added

- ガイドツアーが、エージェントを選んだ後の新規インストールで開くようになりました。プロジェクトの開き方、セッションの開始、ターミナル、セッションの行、worktree、そしてツアーを再び見つける場所を案内します。操作を求めるステップは、あなたが実行するまで待ちます。ダイアログやメニューが開いている間は、ツアーは脇に退きます。いつでも、右上の新しいメニューの「ガイド」（「設定」もここにあります）またはコマンドパレットからやり直せます。「ガイド」では、worktree、エージェントが変更した内容のレビュー、プルリクエスト、新しいセッションへの作業の引き継ぎ、セッションのブラウザも案内します。変更のあるセッションなど、まだ用意できていないものが必要なガイドは、メニューにその旨が表示されます。
- フッターのブランチ名をクリックすると、ターミナルとフッターの間に Git パネルが開くので、履歴を読んでいる間もセッションが見えたままです。すべてのブランチが色付きのグラフとして表示され、その横にブランチとタグが並び、右側に選択したコミットのメッセージとファイルが表示されます。ファイルをクリックすると、その差分が開きます。テキストやハッシュで検索したり、作成者、日付、パス、ブランチで絞り込んだりでき、セッションがいるブランチにはそのセッションのリングが付きます。ローカルブランチのメニューから、チェックアウト、名前の変更、そこからの新しいブランチの作成、削除ができ、「元に戻す」も使えます。セッションが使っているチェックアウトは先に確認され、どのブランチにも属さないコミットが残る削除も同様です。高さと列幅はドラッグで変えられて保持され、ターミナルの上に広げることもでき、「設定」の「キーボードショートカット」でキーを割り当てられます。
- gh が複数の GitHub アカウントでサインインしている場合、プルリクエスト画面は、何かを一覧表示する前に、プロジェクトがどのアカウントを使うかを尋ねるようになりました。これまでは、gh が最後に切り替えたアカウントで黙って実行されていました。プロジェクトが使うアカウントからは GitHub がリポジトリを見せないときも改めて尋ねるので、設定に戻らなくても別のアカウントを選べます。
- 拡張機能が独自の画面を持てるようになりました。拡張機能が宣言した画面ごとに、トップバーのベルとプルリクエストの間にボタンが付き、プルリクエスト画面と同じように、サイドバーを残したままステージ全体に開きます。開いている間は拡張機能独自のキーボードショートカットが動作し、拡張機能は自分の入力欄にキーボードを移せるので、`/` で検索に移動でき、Escape でキーボードが戻ります。ボタンのドットは拡張機能が止まったことを示します。lich が再起動している間は琥珀色、あきらめた後は赤で、その画面には理由が「再起動」と「フォルダーを開く」とともに表示されます。「設定」›「拡張機能」では、GitHub リポジトリからインストールでき（お使いのシステム向けにビルドされた最新リリースを取得し、リリースのチェックサムで検証します）、ディスク上のフォルダーからもインストールできます。どちらも、拡張機能の名前、バージョン、入手元を示し、プロジェクトやセッションに対してほかに何ができるかを平易な言葉で列挙した確認を経てからで、「インストール」を押すまで何も実行されません。すべての拡張機能が状態、バージョン、入手元とともに一覧表示され、あきらめた拡張機能の再起動、フォルダーを開く、削除ができ、拡張機能の状態にカーソルを合わせると何ができるかが表示されます。拡張機能が保存したものはそのフォルダーとは別に置かれ、削除しても残るので、更新の方法である再インストールをすれば、続きから再開します。それも削除したい場合は、削除の確認で「保存したデータも削除する」にチェックを入れてください。
- ある一覧から別の一覧へ項目をドラッグできる拡張機能の画面で、ドロップ先になる一覧が、空の一覧も含めて強調表示されるようになりました。サイドバーが、セッションを振り分けるフォルダーを強調表示するのと同じです。
- 拡張機能を翻訳できるようになりました。翻訳を同梱する拡張機能は、トップバーと「設定」›「拡張機能」で、名前と画面タイトルをあなたのインターフェース言語で表示し、起動時と言語を変えるたびにその言語が通知されるので、独自の画面やメッセージも言語に合わせられます。拡張機能の作者向けに、lich の翻訳フォーマットとそれを読む Go パッケージを用意しました。`docs/extensions.md` の Translating an extension を参照してください。
- 拡張機能が lich を読み取り、操作できるようになりました。プロジェクト、その worktree、セッションの一覧、セッションを開く、タスクを渡して答えを受け取る、Claude Code セッションに補足の質問をする、セッションの状態変化を受け取る、プロジェクトのサービスの一覧、起動、停止、再起動と、その出力の読み取り、チェックアウトのブランチ、変更、上流に対する先行・遅れのコミット、プルリクエストの読み取り、デスクトップ通知の送出、ドックでのファイル表示やセッションのブラウザでのページ表示ができます。エージェントが lich のツールを通じて行うのと同じです。拡張機能は、描画に使うのと同じチャネルで、マニフェストに列挙したものについてだけ依頼し、Go パッケージ `extension` には、その手続きを担うクライアントが含まれています。[Writing a lich extension](docs/extensions.md#calling-lich) を参照してください。
- エージェントが、プルリクエストでチェックが失敗した理由を `lich check-log` または `read_check_log` ツールで読めるようになりました。`checks-failed` の監視が発火したときに呼ぶものです。失敗した各チェックのリンクと、GitHub Actions のジョブについては、失敗した各ステップの最後の 80 行（タイムスタンプとターミナルのエスケープなし）が返り、`gh run view --log-failed` なら数十キロバイトになるところが数キロバイトで済みます。すべてのプロバイダーで動作し、lich のツールが届く環境ではツールで、それ以外ではコマンドで使えます。

### Changed

- セッションの分割、「横に表示」、ターミナルの横でブラウザが開く動作が、動きを伴うようになりました。新しいペインは分割した端から伸び、隣のペインがその場所を空けます。取り外したペインも同じように縮みます。これまでは、どちらも一瞬で切り替わっていました。各ターミナルは最終的なサイズをすぐに取るので、エージェントの再描画は 1 回で済みます。
- 分割レイアウト内のセッションが、プロジェクトのタブの下に二重に表示されなくなりました。プロジェクトのタブには、どのレイアウトにも入っていないセッションが表示され、すべてのセッションがレイアウトに入っているときはその旨が表示されます。レイアウト内のセッションにはサイドバーに列のマークが付き、クリックするとそのレイアウトのタブに移動します。そのタブには専用のサイドバーがあり、レイアウトのセッションだけを各プロジェクト名の下に表示します。worktree、親子セッション、ブラウザのツリーは同じで、「新しいセッション」、フィルター、サービスはプロジェクトのタブに残ります。「レイアウトから外す」は、ペインだけでなくセッションのメニューにもあります。すべてのプロバイダーに適用されます。
- サイドバーのリングと折りたたみが、ツリーのほかの部分と同じように動くようになりました。セッションが作業を始める、終える、あなたを待って止まるときに、リングは新しい色で再描画されます。これまでは一瞬で切り替わっていました。チェックアウトやフォルダーを折りたたむと、サブエージェントの上でセッションを折りたたむときと同様に、行がツリーの線に沿って消えます。新しい行のリングは少し速く描かれます。
- セッションのブラウザが、そのセッションがすでにあるセッションのターミナルの横で開くようになりました。これまでは、同じセッションを二重に表示する専用のタブで開いていました。分割では、ページはそのセッションのペインの横に置かれ、セッションが分割から出ると一緒に移動します。分割のタブを閉じても、見えないところでブラウザが動き続けることはなくなりました。ページのヘッダーに「最小化」ボタンが加わり、ページを隠したままエージェント用にブラウザを動かし続けます。その隣の「閉じる」はブラウザを閉じます。最小化したページは、セッションのメニューの「ブラウザー」から戻せます。動作中のブラウザは、セッションの下の行としてサイドバーにも表示されます。表示しているサイトの名前が付き、最小化中は暗く表示されます。クリックするとページが表示され、メニューから最小化、ウィンドウへの移動、閉じるができます。以前のバージョンで開いたままだったブラウザのタブは復元されません。セッションのメニューからブラウザを開き直してください。すべてのプロバイダーに適用されます。
- トーストが右下の隅、フッターのすぐ上に表示され、上方向に積み重なるようになりました。これまでは右上から降りてきて、拡張機能の「編集」や「保存」のように、画面がそこに置くボタンを覆っていました。すでに右下の隅で待っていた質問（プロセスが終了したセッション、2 枚のカードで開かれている会話、エージェントが開いたブラウザ、プロファイルの提案）も、ほかのトーストと同じスタックに表示されます。
- ポルトガル語、スペイン語、日本語、韓国語、ロシア語、中国語のインターフェースが、より自然に読めるようになりました。各言語を全体にわたって読み直し、英語の文に沿いすぎていた箇所を言い換え、概念ごとに 1 つの用語に統一したため、いくつかのラベルの名前が変わりました（たとえばポルトガル語のプルリクエストのタブは Checks です）。英語からはダッシュがなくなりました。
- セッションのブラウザでエージェントのカーソルの横に出るバッジが、プロバイダー名ではなく、エージェントが何をしているか（クリック中、入力中、スクロール中、移動中など）を表示するようになりました。プロバイダーはセッションがすでに示しています。バッジにはプロバイダーのアイコンが残り、各操作の後しばらく表示され、エージェントが考えている間は矢印だけが残ります。すべてのプロバイダーに適用されます。
- セッションのブラウザのタブが、ページの各フレームを 3 倍から 5 倍速くデコードするようになりました。画像がページに遅れる幅が小さくなり、アニメーションするページでのウィンドウの CPU 使用も減ります。ソースからウィンドウをビルドするには、libjpeg-turbo の `libturbojpeg` が必要になりました。パッケージ名は `CONTRIBUTING.md` に記載しています。

### Fixed

- 「横に表示」が、委任先を開いたセッションのペインが 2 つに分けるには狭くても、積み重ねるには十分な高さがある場合に、「No room for another pane here」と答えなくなりました。委任先はそのペインの下に置かれます。
- 非常に大きなブラウザペインに細かいノイズやフィルムグレインのページを表示すると、バックエンドとの接続が受け付けるより大きな画像がウィンドウに送られ、ウィンドウがすべてのセッションから切り離されることがありました。そのような画像はスキップされるようになり、ペインは、収まる次の画像が来るまで最後の画像を保持します。
- サブメニューが、開いたメニューの横に小さな隙間を空けて、どちら側にも表示されるようになりました。ウィンドウの右端で左に反転するサブメニューが、親メニューの一部を覆うことはなくなりました。トップバーのメニューは幅が広くなり、「設定」と「ガイド」が窮屈ではなくなりました。
- HiDPI ではない画面でのセッションのブラウザが、ページをペインの 1.5 倍のサイズで描画し、すべてのフレームを縮小してはめ込んでいたため、文字がぼやけ、大きなペインでアニメーションするページが約 30 フレーム/秒に抑えられていました。ブラウザはウィンドウ自身のスケールで描画するようになり、文字が鮮明になって、同じペインで 49 から 60 フレーム/秒が出ます。すでに開いているブラウザは起動時のスケールのままなので、ページのズームを変えたり、別の密度のモニターにウィンドウを移したりした後は、鮮明なフレームにするためにいったん閉じて開き直してください。
- プルリクエストの説明とコメント、Markdown プレビュー、拡張機能の画面で、Markdown が引用を淡い色のテキストのバーの後ろに、コードブロックを専用のパネルの上に描画するようになりました。どちらも、これまでは周りのテキストと同じに見えていました。
- プルリクエストの説明やコメント内のフェンス付きコードブロックが、二重に表示されていました。
- コードブロックやインラインコードにタブがあっても、Markdown がボックスを描画しなくなりました。タブは、コードビューと同じく、次の 4 の倍数の位置までの空白です。引用の中のコードブロック、リスト、別の引用は、引用の外と同じように、専用のパネルの上や専用のバーの後ろに描画されます。これまでは、引用がそれらを普通のテキストのようにまとめて表示していました。コードブロックの行間も、コードビューと同じ詰まり具合です。プルリクエストの説明とコメント、Markdown プレビュー、拡張機能の画面が対象です。
- gh がキーリングだけでなく `GH_TOKEN` からも読み取るアカウントが、「設定」›「バージョン管理」で 2 回ではなく 1 回だけ表示されるようになりました。
- 2 行にまたがるリンクに対するエージェントのブラウザのクリックが、覆われているとして失敗しなくなりました。行間の空白ではなく、リンクの最初の行に当たります。
- ターミナルの中国語、日本語、韓国語のテキストが、インストール済みのフォントがそれを含まないとき、空のボックスではなく、lich がウィンドウ用にダウンロードしたフォントで描画されるようになりました。ウィンドウのほかの部分は問題なく読めていました。
- プロファイル内の Claude Code セッションで、プロファイル自身のコピーが古くてサブエージェントを開けないときに、Personal ログインが持つ lich プラグインによってサブエージェントがカードにされることがなくなりました。プロファイルのプラグインが決めます。独自の `mcp.json` を持つプロファイル内の oh-my-pi セッションは、カードのツール名について、Personal のものではなく、そのファイルのサーバーを読むようになりました。
- 未コミットの作業とともに worktree へフォークしたセッションが、プロジェクトが指定した無視ファイル（`.env*` または `.worktreeinclude`）について、メインのチェックアウトのものではなく、自分のコピーを持ち込むようになりました。メインのもののコピーは、横に持ち込まれる作業と静かに食い違うことがありました。
- 手動で起動したサービスが、プロジェクトが開いたままであれば、アップデートのための lich の再起動後に再び実行されるようになりました。lich を終了して後で開いた場合は、これまでどおり、lich と一緒に起動するよう保存されたサービスだけが起動します。
- ブラウザペインから専用のウィンドウで開いたセッションのブラウザが、再びそのウィンドウに追従するようになりました。これまでは、ページが lich 内でのサイズに固定されたままで、ウィンドウのリサイズをすべて無視していました。

## [0.88.0] - 2026-11-10

### Added

### Security

- サンドボックスで動くセッションは、lich 自身のトークンを持たなくなりました。代わりにそのセッション専用に発行されたトークンが渡され、lich はそれを、閉じ込められたエージェントが使う呼び出しにだけ受け付けます。具体的には、隣のセッションへのメッセージ送信、セッションの開始と操作、自分のブラウザの操作、プロジェクトのサービスとコストの読み取りです。サービスの開始や編集（サンドボックスの外であなたのマシン上でコマンドを実行します）、サンドボックスの段階そのものなどの設定変更、別のセッションのターミナルへの入力、そのほかの呼び出しは、理由を示すメッセージとともに引き続き拒否されます。サンドボックスの内側から開いたセッションも、そのチェックアウトのサンドボックス設定にかかわらず閉じ込められ、閉じ込められたセッションが、メッセージの送信、挿入、制御、質問をできるのは、それ自身が閉じ込められたセッションだけです。メッセージは受け取ったエージェントが実行するため、閉じ込められていないセッションに送ると、あなたのマシン上で実行されてしまうからです。返信は誰にでも届き、閉じ込められたワーカーはこれで報告を返します。閉じ込められたセッションは、ワークツリーを強制的に閉じることもできません。
