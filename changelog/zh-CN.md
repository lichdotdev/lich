## [0.69.0] - 2026-10-16

### Added

- **macOS 上的原生窗口（实验性）。** Lich.app 在 Apple Silicon 和 Intel 上随 lich 一同提供它，设置 › 外观 › 窗口与 Linux 和 Windows 上一样可以选择它。Option 键在其终端中用于输入字符，和 Terminal.app 一样，因此智能体的 Option+字母快捷键无法到达终端。目前它只在 GitHub 的 macOS 机器上运行过：通知是无法点击的普通通知，也没有菜单栏图标。
- **文件树认识更多的文件类型。** Java、Gradle、C 和 C++、C#、PHP、Ruby、Swift、SQL、Vue、Svelte、Terraform、Dockerfile、.gitignore 以及约三十种其他类型，现在在文件树和搜索结果中都有各自的图标，此前它们显示的是普通文件图标。

### Fixed

- **`lich quit` 会关闭原生窗口。** 后端退出后，窗口原本仍然开着，并显示 lich 已丢失；托盘中的退出和停止信号现在也会关闭它，而更新后的重启仍会保留它。
- **最后一个会话关闭时，原生窗口会提示删除工作树。** 已关闭提示中，撤销旁边新增了删除工作树；对于不是 lich 创建的工作树，或带有未提交更改的工作树，删除前会在对话框中点明。
- **原生窗口的终端会选中指针下方的单元格。** 点击、拖动选择、链接以及跟踪鼠标的程序，读取到的指针位置都偏移了终端的内边距，导致它们选中的单元格位于所指单元格的右下方，在缩放显示器上偏差接近一个单元格。
- **原生窗口的终端会绘制 emoji。** Noto Color Emoji 等彩色 emoji 字体把每个 emoji 存为图片而非轮廓，而终端只会绘制轮廓，所以每个 emoji 都显示为空白；现在它们以彩色绘制，占两个单元格宽。
- **原生窗口的文件树显示每个文件的语言图标。** 此前每个文件都画成同一个普通文件图标；现在每个文件都带有网页窗口为它提供的图标。
- **智能体打开的拉取请求会在这一轮结束时显示在它的卡片上。** 徽章原本只在分支或其最新提交变化时才会重新检查，而打开拉取请求两者都不会变，所以它要等到窗口失去焦点再重新获得焦点后才出现。
- **原生窗口可以在 Windows 上打开。** 它原本通过 fontconfig 查找字体，而 Windows 并不提供，因此启动时就关闭了，lich 随后回退到网页窗口。在 Windows 上，它现在自己查找已安装的字体，终端默认使用 Cascadia Mono 或 Consolas，设置中的字体选择器也会列出它们。
- **在浅色和深色主题之间切换不再冻结原生窗口。** 像 Claude Code 那样跟随终端配色方案的会话，会在窗口仍持有其终端时收到变化通知，导致窗口卡死并关闭。
