## [0.79.0] - 2026-10-24

### Added

- 在 macOS 上，lich 有了菜单栏图标：窗口已关闭的 lich 会在那里表明它仍在运行会话，提供“显示 lich”、运行中的会话数和“退出 lich”，与 Linux 和 Windows 上的托盘一样。
- **服务：项目持续运行、由 lich 启动的命令。** 在项目的设置 › 服务中保存一次容器、隧道或开发服务器，然后从侧边栏底部、配置文件上方的“服务”行启动它。收起时，该行显示有多少个在运行（2/3）；展开后，它列出每个服务已运行多久或如何结束，悬停时显示“启动”、“停止”和“重启”。点击会打开它的控制台，可以在其中输入，Ctrl+C 停止它。服务不是终端：它的命令退出后，服务就停止了，最后的输出仍可阅读，“启动”会再次运行它。勾选“随 lich 启动”后，每次 lich 在打开其项目的情况下启动，它都会随之启动。在设置 › 服务中选择“全局”所保存的服务在你的主目录中运行，并显示在 lich 的首页上，适合放一个无论哪个项目都一直开着的 `lazydocker`。服务的存续与其项目的标签页一致：关闭标签页会停止它，重新打开项目则会启动那些保存为随 lich 启动的服务。关闭窗口时它们继续运行，托盘会列出它们，并提供“显示输出”、“重启”和“停止”；退出 lich 会停止它们，关闭对话框也会统计它们。侧边栏折叠时，边栏中的“服务”按钮会打开同一个列表。

- **把拉取请求的评审讨论发送到它的会话。** 在 Pulls 屏幕中，打开状态的评审讨论在“回复”和“标记为已解决”旁边有“发送到会话”，在对话标签页和差异中都有，对话标签页还可以一次发送所有未解决的讨论。这些讨论会作为一条提示发送到该分支检出目录中的会话（没有时 lich 会打开一个），其中包含每个讨论的文件、行、链接和其中的所有评论。Pulls 保持在屏幕上，会话接收讨论后，会有带“打开”的提示通知告知。随后 lich 会在 GitHub 上回复每个讨论“Fixing this. It'll be in the next commit.”，并在拉取请求再次被推送后将其标记为已解决，同时回复它所落入的提交；在此之前，该讨论显示“已发送 · 等待 push”。任何一次推送都会将其解决，即使这次推送没有触及它。

### Changed

- 在 lich 之外合并的拉取请求（在 github.com 上、在终端里用 `gh`，或由代理合并），现在会像从 Pulls 合并的那样，在合并后一分钟内通知其分支检出目录中的代理。此前它们会一直以为它仍处于打开状态。只有在 lich 看到它处于打开、随后被合并时正在那里运行的代理才会收到通知；当时已被搁置的代理，或在 lich 上次启动之前就已合并的拉取请求，则不会。
- Pulls 中的“解决冲突”和“修复 CI 错误”不再把你带到它们交付拉取请求的那个会话。Pulls 保持在屏幕上，方便你转到下一个拉取请求，会话在侧边栏中启动，代理接到任务时会有带“打开”的提示通知告知。需要你先回答才能启动的会话（例如是否恢复其上一次对话）仍会弹出。“在会话中打开”仍会前往该会话。
- Pulls 中拉取请求列表上方的快速筛选器（全部、就绪、草稿、失败）更轻量了：小号文字，选中的一项带底色，与停靠栏的标签页一样，宽度与列表一致。没有内容的筛选器会变淡，有检查失败时“失败”的计数会变红。使用等宽界面字体时，它们也不再超出列表的边缘。

### Fixed

- 在会话的 shell 移入另一个仓库之后，会话卡片上的拉取请求徽章、其“拉取请求”菜单项以及页脚的拉取请求按钮，不再打开错误的拉取请求。徽章显示的是那个仓库的拉取请求，而此前点击时会在 Pulls 中该项目自己的拉取请求里按编号查找；现在改为在 GitHub 上打开该拉取请求。
- 折叠的侧边栏会在边栏底部显示新会话所使用的配置文件，并打开与展开的侧边栏页脚相同的菜单。此前它完全不显示配置文件。
- 顶部栏中的标签页不再会卡在被抬起的状态，不再以强调色绘制得像在被拖动，并且在 lich 重启之前没有任何标签页能再移动。先用点击聚焦、再按空格或回车的标签页，会被拿起以便用键盘重新排序，而一旦点击别处夺走了键盘，它既无法放下也无法取消；现在它失去焦点时会回到原位。在拖动过程中被重命名的布局标签页，也不会再以同样的方式卡住。
- 会话卡片不再因其代理开始和结束使用工具、等待你或压缩上下文而变大变小，把下面的所有卡片推上推下。那一行现在会在显示期间占据卡片路径的位置，消失后路径再回来。
- 原生窗口的字体占用的内存更少了。被多次请求的字体文件（例如界面和终端设置为同一字体族，或同时充当半粗体的粗体）此前每次都会被重新解析，一个 Nerd Font 字体约 30MB；现在只解析一次，使用期间共享。界面语言不是中文、日文或韩文时，启动时不再加载数十兆字节的 CJK 字体：它会在屏幕上第一次出现 CJK 文本时才加载，在此期间用系统字体绘制。界面、终端和编辑器使用同一款 Nerd Font 且屏幕上没有 CJK 时，字体占用 119MB，而此前是 246MB。
- 在 macOS 上，当 lich 在窗口已关闭的状态下运行时，从 Dock、启动台、聚焦搜索或访达打开 lich，会重新打开窗口。包括以 `--no-window` 在登录时启动的 lich，此前点击没有任何反应。注销现在会像 `lich quit` 那样退出 lich，因此下次启动不会把它当作崩溃。

### Changed

- 会话工作时，窗口以每秒 30 帧而不是显示器的刷新率重绘其忙碌指示器；卡片只在其右键菜单打开时才构建该菜单；关闭的对话框则完全不构建任何内容。

### Fixed

- 卡片和页脚上的分支、更改和拉取请求，会在回合之外进行的提交、检出或编辑后一秒内跟上，此前可能滞后多达三秒；选中卡片时会立即读取其检出目录，而不再显示上一次读取的结果。
- 在 Pulls 中隐藏拉取请求列表时，列表会立即消失，而此前它会一直留在屏幕上，直到鼠标移动或 Pulls 下次检查 GitHub。再次显示时也不再等待一帧。

- 重新打开窗口不再向会话输入多余的文本。根据最近的输出重建终端时，会再次应答其中的终端查询（例如 nvim 启动时发送的那些），这些应答落到了会话的输入上：在 shell 中表现为 `command not found`，在代理中表现为提示中的文本。
- 会话正在打印输出时打开的会话终端，不再漏掉那一刻打印的内容。后端现在把会话的最近输出与实时输出衔接在一起交给窗口，因此两者之间不会丢失或重复显示任何内容。
- 在 Linux 上，调整终端字体大小和首次打开卡片时的卡顿减少了。此前每个终端每次都通过 fontconfig 重新查找字体，在一帧之内进行四次查找，每次约 10ms；lich 现在会在本次运行期间记住结果。
- 调整终端字体大小不再重新加载每个已打开终端的字体：每个终端保留其已有的字体，只是以新的大小绘制。
- 输出量很大的会话给后端带来的开销降低了。发往窗口的每个字节此前被复制进内存约七次，之后还要由垃圾回收器回收；现在只复制一次。
- 在审查和 Pulls 的差异中，开始于折叠区段上方的块注释，不再把该区段之后的代码染成注释。它的结束符 `*/` 落在隐藏的行中，因此下面的每个代码块都显示为注释，直到后面某个 `*/` 出现，只有展开该区段才能修复。被折叠区段截断的注释位于其上方的行，在展开之前仍可能显示为代码。

- **每次更新都会打开原生窗口。** 每个版本首次启动时，lich 会切换到原生窗口，无法启动时则回退到网页窗口；你在设置中切回后，lich 会一直停留在网页窗口，直到下一个版本。原生窗口首次打开时，会说明它是实验性的，并附上提交 bug 报告的链接。
- **原生窗口中的状态环更细了。** 会话卡片图标外的圆环画得更细，与网页窗口的粗细一致。
- **原生窗口中的快捷键按键更宽松。** 命令面板、快捷键叠层和 设置 › 快捷键 中的按键帽，文字周围留白更多，文字居中。
- **原生窗口的设置默认打开全局。** 顶栏的齿轮始终打开 全局 设置，而不是你上次离开时所在的范围；项目的标签页仍可通过 项目设置… 打开它自己的设置。
- **原生窗口中的命令面板更清爽。** 每个会话、项目和消息只占一行，路径跟在名称之后；工作树的路径显示最后三段。等待你处理的会话排在最前并有所标注，筛选标签页去掉了药丸样式，改用下划线。历史 中已关闭的会话在右侧显示分支和时长，只有搜索匹配到其对话时才多出第二行，并标出匹配的词。

### Fixed

- **重启的会话不再一直显示为忙碌。** 智能体在一轮中途死亡，或会话在一轮中途被关闭后，会话会回到同一张卡片上，但对其他会话仍显示为忙碌：发给它的任务会等待一个永远不会结束的轮次。现在它和新会话一样，以无状态启动。
- **Codex、Cursor CLI、Antigravity 和 Crush 不再重复询问你已回答过的问题。** 其中任何一个的沙盒会话都会直接停在提示符处。Cursor CLI 和 Antigravity 不再在你信任过的文件夹的工作树中再次询问，Antigravity 在其子文件夹中也不再询问，Crush 也不再要求初始化每个新的工作树。沙盒中的 oh-my-pi 会话不再打开设置向导。
- **Claude Code 不再在你已回答过的地方询问“信任此文件夹？”。** 你在主账户中信任过的文件夹，从下一次会话起在其他所有 Claude Code 配置文件中也被信任，沙盒中的 Claude Code 会话则完全不会出现这个问题。lich 为你打开的会话不再停留在那个界面上，在那里按 Enter 会退出。
- **重新打开的原生窗口知道每个会话去了哪里。** 通过 `cd` 移动过，或进入了 tmux 或 ssh 的会话，回来时会一直显示它检出的路径、分支和更改，直到下一次 `cd`；现在窗口在连接时会读取每个会话最后所在的位置。
- **原生窗口用你的提示词语言编写智能体提示词。** 拉取请求和 issue 的交接，以及一批审查评论，此前一直以英文输入。
- **重连期间更改主题不再导致原生窗口崩溃。** 在窗口重新连接到已重启的 lich 时切换主题，或系统切换浅色和深色，可能会绘制重连刚刚释放的终端，并使窗口崩溃。
- **中文、日文和韩文文本不再让 Linux 上的原生窗口卡死。** 满是 CJK 文本的会话、审查或拉取请求可能使窗口挂起数秒，长到出现“未响应”，缩放还会让卡死再次出现。
- **原生窗口占用的内存更少。** 每个会话的终端和审查都加载了各自的回退字体副本，CJK 或 emoji 字体每份就有数十 MB：现在打开六个会话，内存占用约为原来的一半。在安装了 CJK 字体的机器上，启动也更快。
- **重新打开对话已处于打开状态的会话时，会聚焦到那张卡片。** 从 历史 中打开已关闭的会话、撤销关闭或已有的工作树，可能会作为第二张卡片回到另一张卡片仍在运行的对话上，两者会写入同一份对话记录。历史 现在按最近一次关闭只列出这样的对话一次，忘记 会删除它的所有副本。

## [0.69.0] - 2026-10-16

### Added

- **macOS 上的原生窗口（实验性）。** Lich.app 在 Apple Silicon 和 Intel 上随 lich 一同提供它，设置 › 外观 › 窗口与 Linux 和 Windows 上一样可以选择它。Option 键在其终端中用于输入字符，和 Terminal.app 一样，因此智能体的 Option+字母快捷键无法到达终端。目前它只在 GitHub 的 macOS 机器上运行过：通知是无法点击的普通通知，也没有菜单栏图标。
- **文件树认识更多的文件类型。** Java、Gradle、C 和 C++、C#、PHP、Ruby、Swift、SQL、Vue、Svelte、Terraform、Dockerfile、.gitignore 以及约三十种其他类型，现在在文件树和搜索结果中都有各自的图标，此前它们显示的是普通文件图标。

### Fixed

- **`lich quit` 会关闭原生窗口。** 后端退出后，窗口原本仍然开着，并显示 lich 已丢失；托盘中的退出和停止信号现在也会关闭它，而更新后的重启仍会保留它。
- **最后一个会话关闭时，原生窗口会提示删除工作树。** 已关闭提示中，撤销旁边新增了删除工作树；对于不是 lich 创建的工作树，或带有未提交更改的工作树，删除前会在对话框中点明。
- **原生窗口的终端会选中指针下方的单元格。** 点击、拖动选择、链接以及跟踪鼠标的程序，读取到的指针位置都偏移了终端的内边距，导致它们选中的单元格位于所指单元格的右下方，在缩放显示器上偏差接近一个单元格。
- **原生窗口的终端会绘制 emoji。** Noto Color Emoji 等彩色 emoji 字体把每个 emoji 存为图片而非轮廓，而终端只会绘制轮廓，所以每个 emoji 都显示为空白；现在它们以彩色绘制，占两个单元格宽。
- **原生窗口的文件树显示每个文件的语言图标。** 此前每个文件都画成同一个普通文件图标；现在每个文件都带有网页窗口为它提供的图标。
- **智能体打开的拉取请求会在这一轮结束时显示在它的卡片上。** 徽章原本只在分支或其最新提交变化时才会重新检查，而打开拉取请求两者都不会变，所以它要等到窗口失去焦点再重新获得焦点后才出现。
- **原生窗口可以在 Windows 上打开。** 它原本通过 fontconfig 查找字体，而 Windows 并不提供，因此启动时就关闭了，lich 随后回退到网页窗口。在 Windows 上，它现在自己查找已安装的字体，终端默认使用 Cascadia Mono 或 Consolas，设置中的字体选择器也会列出它们。
- **在浅色和深色主题之间切换不再冻结原生窗口。** 像 Claude Code 那样跟随终端配色方案的会话，会在窗口仍持有其终端时收到变化通知，导致窗口卡死并关闭。
