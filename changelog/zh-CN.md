## [0.88.0] - 2026-11-10

### Added

- 代理可以向你展示它正在谈论的代码：要求查看后，文件会以只读方式在停靠栏的“代码”标签页中打开，定位到它找到的那几行，位于该会话自己的检出目录中，你的键盘仍然留在终端里，所有提供商都一样。代理有话要补充时，可以在这些行下方留一条简短的评论。如果来自你当前没有查看的会话，则会弹出一条通知来提供它，而不是占用你的屏幕。
- 在终端中打印出的 `path:line` 上按 Ctrl+点击（macOS 上为 Cmd+点击），会在“代码”标签页中打开它。没有目录的名称（如 Java 堆栈跟踪中的那样）会在检出目录中搜索，当有多个文件匹配时会出现一个选择列表。
- 项目标签页可以从其右键菜单中固定。固定的标签页集中在标签栏的左侧，只能从该菜单关闭；固定状态在窗口重新打开后依然保留。
- “拉取请求”界面的状态菜单新增了“已批准”：评审已被批准的未关闭拉取请求。
- 代理为向你展示而制作的页面，如报告、图表、原型，会在其会话的浏览器中从该会话自己的文件夹打开，而不是落在你的检出目录里，所有提供商都一样。该文件夹不进入 git，重启和关闭卡片后依然保留，并在会话被删除时一并删除。Claude Code 仍可能用它自己的 Artifact 工具把页面发布到 claude.ai；如果你想让它出现在标签页中，请要求在本地生成。
- 停靠栏新增“产物”标签页：当前会话制作的页面，以及其下项目中其他已打开会话制作的页面。点击会在该会话的浏览器中打开一个页面，“附加到提示词”则可以把一个会话制作的页面交给另一个会话，适用于任何提供商：页面会被复制到该会话自己的文件夹，其路径粘贴到提示符处，并附上一行说明它是副本。页脚上的一个按钮可打开该标签页；你已保存的页脚布局会把它列在“可用”之下。

### Fixed

- 侧边栏会绘制每个区块的标题，并把每张卡片挂在它所运行的检出目录下，与工作树旁边原有的做法一致：只包含某个项目唯一会话的文件夹不再消失，单独的会话或文件夹也不再显示游离的卡片。

## [0.87.0] - 2026-11-08

> [!CAUTION]
> **所有人：这是一个必须安装的更新。** 在此版本之前，你机器上任何浏览器中的页面，都可以通过会话浏览器的本地文件服务器读取该会话的检出目录；会话令牌会显示在进程的命令行中；在沙箱中运行的会话还能拿到 lich 自己的令牌，并借此在你的机器上执行操作。请立即更新。

### Added

- 一个版本可以要求必须更新。当某个版本修复了安全问题时，更新提示不再有“稍后”，关闭后会再次出现，并且在更新安装完成之前，lich 不会打开新的代理会话：窗口、`lich open` 和代理的工具都会拒绝，并各自说明原因和更新方法。已经在运行的会话不受影响，shell 仍然可以打开，让你在其中运行更新。它会把你跳过的每个版本都算在内，而不只是最新版本，并且需要能够访问 GitHub。在“新增内容”对话框中，这样的版本带有一个红色提示框。
- 会话可以等待某件事，然后再采取行动。会话菜单上的**定时发送提示词…**接受一段提示词，以及一个时间（`45m`、`2h30`、`14:30` 或完整日期，输入时会显示它对应的具体时刻），或者针对其分支的拉取请求设定的条件：检查失败、检查通过或收到评审。没有变化时不会消耗任何东西，提示词会像转发的消息那样输入到会话中，所有提供商都一样。针对检查失败的监视会在每次新提交后继续保持开启，直到拉取请求关闭，并在运行 3 次后停止，同时告诉你它停止了。会话所在行上的时钟或雷达图标表示它持有一个这样的设置，其提示会说明具体内容。代理可以用 `lich schedule` 或 `schedule_prompt` MCP 工具在它自己的会话上设置同样的东西，你在那里设置的内容会一直保留，直到你修改。
- 代理可以在其会话的浏览器中运行 JavaScript 并读取结果（`browser_eval`、`lich browser eval`）：你的应用的状态、页面没有打印出来的值、一次 `fetch` 的结果。结果会在 2000 个字符处截断，因此庞大的页面状态只会占用代理的上下文中它所请求的那一部分。脚本可以读取字段中的内容，包括密码，而页面读取从不会把这些交给它。
- 代理可以只读取页面的一部分，而不是全部：`browser_info` 接受 `within`，一个 CSS 选择器（`lich browser info --within <css>`），并返回它匹配到的第一个元素中的文本、按钮和链接，因此文档站点的主栏或一个打开的对话框只占整个页面及其导航的一小部分。匹配不到任何内容或无效的选择器会返回错误，并保持上一次读取的索引仍然可用。
- 会话浏览器的截图可以带上画在其上的每个按钮和链接的索引（`browser_screenshot` 的 `annotate`、`lich browser screenshot --annotate`），这样代理就能按索引点击没有标签的图标，而不必自己推算它在哪里。你的窗格会显示截取那一刻的编号。
- 任何程序都可以告诉其会话的卡片它在做什么。构建脚本、部署或没有 lich 钩子的代理写入 Program Status Protocol 序列（OSC 7501），卡片就会显示它正在工作并附带其消息、正在等你并附带其问题，或已完成。会话自己的钩子如果有，仍然优先。询问终端是否读取该协议的程序会得到回答。在 Windows 上尚未验证。
- 当使用额度上限中断了 Claude Code 或 Codex 的一个回合，而你的另一个同类代理的已登录配置档案仍有额度时，会出现一条通知，提议在那里继续。只有点击它才会移动会话，方式与“转到”相同，并立即发送继续的内容；否则会话像以前一样等待重置。lich 无法读取其套餐的配置档案绝不会被提议，会话已经继续往前之后的点击会被拒绝并说明原因。
- 交接工作的代理可以为接任者建议你的另一个配置档案（`handoff_session` 的 `profile`、`lich handoff --profile`）。接任者仍然在调用者的配置档案中启动，在它的第一个回合结束后，会有一条通知提议使用建议的那个：只有点击“转到”才会移动它。无法适用的建议会被丢弃，代理会被告知原因，交接继续进行。
- 代理可以在一个干净的断点处，把工作交接给自己的一个全新会话，而不是在已经变得很长的上下文中继续。`handoff_session` 工具（以及 `lich handoff`）接受一份简短的说明：已完成的内容、分支和提交、后续步骤以及注意事项，它会在同一个检出目录中，用相同的提供商、模型和配置档案打开一个新会话，并把说明输入到它的提示符中。旧会话保持打开，由你来关闭。
- 一个 Claude Code 会话在其对话被压缩时，如果仍有来自其他会话的任务在等它回答，那么压缩结束后会提醒它这些任务：每个工单、它问了什么，以及回答它的命令。此前，摘要可能会丢掉工单，而在有两个任务打开时，没有指明任何一个的回答会被拒绝，于是发起请求的会话白白等待。
- 被发现来回互发消息、中间没有任何实际工作的两个会话会被叫停。连续的第二条这样的消息会带着一条说明送达其代理，指出这场交流看起来像一个循环，第四条会被拒绝，于是这一对会话不再白白消耗 token。跟在真实工作之后的消息、第三个会话的加入，或你在任一会话中输入，都会让计数重新开始。经过三个或更多会话的循环也一样：连续的第五条转发消息，如果每条都来自一个只是把收到的消息转发出去的会话，就会被拒绝。Crush 会话不报告任何工具，因此永远不会被叫停。

### Changed

- 在窗口自己的控件（文本选择、编辑器、标签栏）中，双击现在在间隔最多 400 毫秒时即被识别，而不是 200 毫秒，与终端和浏览器窗格原来的行为一致。
- 在 Windows 上，窗口通过翻转模型呈现帧，最多排队一帧，调整大小时会立即显示新的尺寸，而不是把旧的一帧拉伸到新尺寸。
- 会话浏览器的页面回答、`browser_eval` 返回的内容，以及浏览器工具回答的标签页列表和页面句柄，现在会把页面写入的内容（其标题、文本、元素标签、控制台错误、对话框消息）放在 `<page …>` 和 `</page …>` 标记之间，标记带有一个每次回答都会变化的随机码，并且 `browser_info` 会告诉代理，它们之间的文本属于页面，绝不是指令。写着“SYSTEM: ignore previous instructions”的页面不再读起来像是 lich 在说话，也无法伪造结束标记。这会让一次回答增加 31 个字符。
- 会话浏览器的截图最长边最多 1280 像素，因此一个 2000 像素宽的窗格的截图像素减少 60%，而代理查看它时花费的 token 正取决于像素，并且按在截图上读出的点所做的点击仍然落在读出它的位置。每次请求代理都会读取的浏览器工具说明，缩短了五分之一。
- 如果点击或按键没有改变页面的按钮和链接，与代理上次读取时相同，就会用一行话说明这一点，而不是把整个列表再给一遍，这样的重复原来占了页面回答的大约十分之三。
- 会话浏览器的页面回答只在链接自己没有标签时才写出它指向哪里：代理按索引点击有标签的链接，而这些地址曾占它所读内容的六分之一。
- 会话浏览器中的按钮或链接只要还在页面上就保持其索引，因此在页面于它上方添加内容或把它滚出视野之后，代理的索引仍然能点到它，而来自代理已离开的页面的索引会失败，而不是点击占用了其编号的其他东西。此前每次读取都从 0 重新给页面编号。
- 会话浏览器的页面回答会从页面文本中去掉紧接在下方列出的按钮或链接的标签所独占的每一行，并把文本截断在 1000 个字符而不是 1200 个：缩小了十分之一，页面自己的文本和以前一样多。
- 会话浏览器中按索引或选择器对元素进行的点击、输入和按键，当另一个元素覆盖了目标的点击位置（Cookie 横幅、模态对话框的背景：`covered by <div#consent-banner>`）或目标被禁用时，会在分发之前失败并指出挡住它的东西，而不是点击最上面的东西，或什么也不做并像以前那样回答页面。对代理自己选定的 x 和 y 处的点击保持不变。

### Fixed

- “新建文件夹”对话框打开时光标位于名称字段中，因此你可以立即输入名称，而不必先点击该字段。
- lich 为继续被使用额度上限中断的回合而暂存的提示词，重新显示在会话上，并且可以从其菜单中取消。删除会话时同时删除了在它上面定时的提示词的通知也一样。两者都曾随网页窗口一起消失。
- `GIO_DAMAGE=on` 会重绘到 lich 自己保留的帧缓冲中，而不是信任驱动的缓冲区年龄，因此误报缓冲区年龄的驱动不会再让窗口留下陈旧的像素。
- 在 X11 上，滚轮滚一格只滚动一次而不是两次，并且指针离开窗口时悬停状态会清除，在 Windows 上也是如此。
- Codex 和 Kiro CLI 会话现在会用你的提示词语言被告知它们运行在 lich 中，以及何时应为这项工作打开另一个会话：这两个 CLI 都会丢弃 lich 的 MCP 服务器对模型说的话，因此它们有工具却不知道该使用。Codex 在新对话中得到这段说明，除非你的 `config.toml` 设置了 `developer_instructions`，lich 对它不会改动；Kiro 在 lich 下次更新那里的插件时得到。
- 代理在刚启动的会话浏览器中点击下载链接之后，紧接着的点击或按键，不再会被 Chrome 开始该下载时进行的页面重新加载所抹掉：lich 会把第二个操作保留到重新加载完成，或者直到浏览器启动满 6 秒。
- 创建不带名称的工作树时，如果 lich 为它挑选的名称落在了某个分支已被重命名的工作树的文件夹上，不再因为 "which already exists" 而失败。lich 现在会跳过任何文件夹已被占用的名称。
- git 已创建但无法读取为检出目录的工作树，会连同错误一起被移除。此前它的文件夹会留下，再次用该名称创建工作树会因 "which already exists" 而失败。
- 代理在页面下载了文件之后紧接着的导航，在 Chromium 157 及更高版本上不再因 `net::ERR_ABORTED` 而失败，该版本会在下载开始近 4 秒后重新加载页面：lich 会再次加载该页面。
- 发送给已信任某个文件夹的 Claude Code 或 Cursor CLI 会话的任务，即使该会话启动时没有 lich-plugin（这发生在会话启动的同时更新插件时），也会到达其提示符。此前，lich 会为这个会话永远不会发送的报告而保留任务，并在 5 分钟后回答说任务从未到达提示符，而代理一直闲置在那里。
- 打印超过 2 MB 的会话，在窗口重建其终端时（首次显示它，或在重新连接之后）会保留其终端模式。此前，鼠标可能停止工作或退回到旧的编码，粘贴可能在第一个换行处提交，按键在没有 kitty 协议的情况下传来，全屏应用会画在 shell 自己的屏幕上，而它设置的调色板、前景色、背景色和光标颜色会恢复原状。适用于每个提供商。
- 由多个字符组成的 emoji 在终端中显示为一个，宽度与其他终端的绘制一致：一个家庭是一个 emoji 而不是三个，一面旗帜是旗帜而不是两个字母，该行其余部分也不再向右移动。后面跟着组合重音符的字母会显示该重音符。复制文本或打开链接会保留每个字符。

### Security

- 在沙箱中运行的会话不再持有 lich 自己的令牌。它得到的是专门为它签发的令牌，lich 只对受限代理用得上的调用接受它：向身边的会话发消息、打开和引导会话、驱动它自己的浏览器、读取项目的服务及其成本。启动或编辑服务（这会在你的机器上、沙箱之外运行命令）、更改沙箱级别本身这样的设置、向另一个会话的终端输入，以及其他所有调用仍然被拒绝，并附带说明原因的消息。从沙箱内部打开的会话同样受限，无论该检出目录的沙箱设置是什么，而受限会话只能向本身也受限的会话发送消息、插入内容、控制或提问：消息由接收它的代理执行，因此发送到不受限会话中的消息会在你的机器上运行。回复可以送达任何人，受限的工作者就是这样汇报的。受限会话也不能强制关闭工作树。
- 沙箱会隐藏 lich 自己的目录和其他会话的工作树。`~/.config/lich`（lich 的令牌、它的数据库、你其他账号的配置档案）和 `~/.local/share/lich/worktrees` 此前在受限会话内是可读的，因为它们属于 `~/.config` 和 `~/.local/share`；现在每个位置上都盖着一个空目录，只把会话自己的配置档案、放入的文件、钩子脚本和检出目录挂载回来。
- 会话浏览器的本地文件服务器，即在 `http://127.0.0.1:<port>/` 提供会话检出目录的那个，现在只回答发往 `127.0.0.1:<port>` 或 `localhost:<port>` 的请求。你普通浏览器中的页面可以把它所控制的一个名称指向你的机器，并通过它读取检出目录，包括 `.env` 文件；这样的请求现在会被拒绝。
- lich 粘贴出来用于完成自更新的命令，会通过 curl 的标准输入提供的请求头，把会话令牌发送给 lich，因此它不再出现在进程的命令行中，而机器上的每个用户都能读取命令行。回环监听器除了 `?token=`，还接受 `Authorization: Bearer <token>`。`install.sh` 所做的重启也是如此。
- lich 自己的配置目录（Linux 上为 `~/.config/lich`）在每次启动时都会被设为只有你的用户可读，因此已有的安装也会被收紧。提示词和会话文本存放在那里的数据库中。它上一级的目录保持原样。

## [0.86.0] - 2026-11-07

### Added

- 托盘会告诉你哪些会话需要你。托盘菜单会列出正在等你处理的会话及其提出的问题，以及已完成回合但你尚未查看的会话，然后是工作中的会话及其正在运行的工具；点击其中一项，会在对应卡片上打开窗口。把鼠标悬停在图标上，会完整列出所有这些会话，不做截断（前提是你的托盘会显示图标的提示）；在 macOS 上，每一项的提示都包含完整的一行。有事发生时，图标会带一个圆点：会话在等你处理时为琥珀色，有未读回合时为绿色，有会话工作时为灰色。服务移到了一个子菜单中。
- 会话浏览器页面上的备注面板新增了一个文本框，用来写针对所有备注的总体说明，就像一批审查评论那样。你在其中写的内容会作为结尾放进代理收到的消息。Enter 发送备注，Shift+Enter 换行，“清除”会连同其余内容一并清空。

### Changed

- 窗口绘制每一帧时 CPU 占用降低约十分之一：当本来就要绘制整个画面时，它不再去计算画面的哪一部分发生了变化。
- 在窗口上移动指针不再每次移动都重绘：只有指针下方的内容发生变化时才会绘制；追踪鼠标的代理（Claude Code 就是）也不再因为指针移动而让其输出立即重绘。手放在鼠标上时更省电。
- 终端中的链接只有在按住 Ctrl（macOS 上为 Cmd）时才会显示下划线，指针也才会变成手形，这个键就是点击打开链接所用的键，与 Ghostty 一致。以前指针下的每个链接都会显示下划线。
- 在代码、审查和 Pulls 中，一批评审评论下方的备注现在是一个随输入增高的文本框：Shift+Enter 换行，Enter 仍将其加入这批评论。

### Fixed

- 会话工作时，lich 窗口使用的处理器减少了一半。屏幕上的每个图标、圆环和圆弧，此前每一帧都从轮廓重新构建；现在每个只构建一次，并保存在显卡上。

- Kiro CLI 会话现在遵循 `KIRO_HOME`。设置它之后，lich 仍从 `~/.kiro` 读取 Kiro 的对话、费用和上下文，而 Kiro 把它们保存在 `KIRO_HOME` 下，因此什么都显示不出来，历史中也没有列出任何内容；携带 lich 钩子的代理被安装在了 Kiro 从不查看的位置，沙箱会话也没有获得 Kiro 写入的目录。
- 打开或关闭停靠栏后，会话终端不再在停靠栏停下之后短暂地在边缘被截断。终端在停靠栏开始移动时就采用新的宽度，因此代理会在停靠栏滑动期间重绘，而此前终端要等到停靠栏停下十分之一秒后才跳变。分屏布局中的终端会在停靠栏停下的瞬间完成适配。
- 展开侧边栏后，会话终端不再在侧边栏打开之后短暂地停留在旧的宽度。与停靠栏一样，终端在侧边栏开始移动时就采用新的宽度，而此前它要等到侧边栏停下十分之一秒后才跳变；折叠时也会立即重新适配。分屏布局中的终端会在侧边栏停下的瞬间完成适配。

- 会话正在打印输出时打开的会话终端，不再漏掉那一刻打印的内容。后端现在把会话的最近输出与实时输出衔接在一起交给窗口，因此两者之间不会丢失或重复显示任何内容。
- 在 Linux 上，调整终端字体大小和首次打开卡片时的卡顿减少了。此前每个终端每次都通过 fontconfig 重新查找字体，在一帧之内进行四次查找，每次约 10ms；lich 现在会在本次运行期间记住结果。
- 调整终端字体大小不再重新加载每个已打开终端的字体：每个终端保留其已有的字体，只是以新的大小绘制。
- 输出量很大的会话给后端带来的开销降低了。发往窗口的每个字节此前被复制进内存约七次，之后还要由垃圾回收器回收；现在只复制一次。
- 在审查和 Pulls 的差异中，开始于折叠区段上方的块注释，不再把该区段之后的代码染成注释。它的结束符 `*/` 落在隐藏的行中，因此下面的每个代码块都显示为注释，直到后面某个 `*/` 出现，只有展开该区段才能修复。被折叠区段截断的注释位于其上方的行，在展开之前仍可能显示为代码。

### Fixed

- 在较窄的设置窗口中，如果某项设置的控件太宽、无法与文字同行（例如提供商的配置文件选择器），控件现在会放在标题和说明下方，此前文字被挤成一条窄缝，逐字换行。提供商的“文档”链接同样移到其名称下方，不再与“已启用”开关挤在一起。

### Added

- **智能体打开的拉取请求会在这一轮结束时显示在它的卡片上。** 徽章原本只在分支或其最新提交变化时才会重新检查，而打开拉取请求两者都不会变，所以它要等到窗口失去焦点再重新获得焦点后才出现。
- **原生窗口可以在 Windows 上打开。** 它原本通过 fontconfig 查找字体，而 Windows 并不提供，因此启动时就关闭了，lich 随后回退到网页窗口。在 Windows 上，它现在自己查找已安装的字体，终端默认使用 Cascadia Mono 或 Consolas，设置中的字体选择器也会列出它们。
- **在浅色和深色主题之间切换不再冻结原生窗口。** 像 Claude Code 那样跟随终端配色方案的会话，会在窗口仍持有其终端时收到变化通知，导致窗口卡死并关闭。
