## [0.73.0] - 2026-10-20

> [!IMPORTANT]
> **所有用户：原生窗口现在是 lich 唯一的窗口。** lich 每次启动都会打开它；网页窗口及其内嵌的 Chromium 已移除。

### Added

- **在 Windows 和 macOS 的原生窗口中，桌面通知现在可以点击。** 与 Linux 一样，会话需要你输入或完成了一轮后，会弹出带有“打开”和“忽略”的通知：“打开”会把 lich 带到该会话的卡片上，你回复或打开该会话后，通知随即消失。在 macOS 上，lich 需要从 Lich.app 运行，并会请求一次权限；在 Windows 上，等待你操作的会话会让通知一直留在屏幕上，直到你处理。
- 当会话通过自定义可执行文件启动时，设置 › 提供商会在配置文件下方给出警告，显示其路径，并提供显示该文件或恢复默认值的按钮。自行设置登录或配置目录的包装脚本会覆盖配置文件，而“可执行文件”设置折叠在界面底部。

### Changed

- 会话进程退出时，现在由右下角的提示框询问如何处理，取代终端底部的横条。有对话的卡片提供“继续”（在其启动时所用的配置文件中重新打开同一段对话）、“新建对话”（像之前的“重新启动”一样在卡片中开始另一段对话）和“关闭会话”。Shell，或在第一条提示之前就结束的智能体，则提供“重新启动”和“关闭会话”。忽略提示框会保持卡片原样，聚焦该卡片会让提示框重新出现。
- **项目的配置文件现在位于侧边栏底部，而不是每张卡片上。** 当一个提供商有多个登录时，侧边栏最后一行会显示该项目中此提供商的新会话所使用的配置文件：取决于屏幕上卡片的提供商，终端则取默认的那个。点击它可以选择另一个登录（每个登录都显示五小时用量），或回到“全局”的设置；“其他提供商”可在同一菜单中修改其余的。卡片不再在分支旁显示配置文件标签。

### Removed

- 网页窗口。lich 会打开原生窗口，发布包也不再附带 Chromium。设置中的“窗口”选项（网页或原生）以及用于打开另一个窗口的托盘项均已移除，`lich -- <chromium flags>`、`lich --shell` 和 `LICH_SHELL` 同样移除。如果原生窗口无法启动，lich 会说明原因以及日志的位置。

### Fixed

- 登录 Claude Code 或 Codex 配置文件时，在你于浏览器中完成登录或提交粘贴的代码后，现在会显示正在验证；此前对话框会一直等待登录直到最后，代码输入框只是被清空。
- 在巴西葡萄牙语中，所有消息现在都称 worktree 为“a worktree”，此前有几处写成“o worktree”。
- 在 macOS 上，原生窗口重新有了关闭、最小化和缩放按钮；自 0.72.0 起，顶栏为它们留出的位置是空的。
- 在 Windows 上，从原生窗口更新 lich 不再因“Setup was unable to automatically close all applications”而回滚：窗口一直占用着安装程序必须替换的 `lich-native.exe`。现在它会在安装程序运行前关闭，并在 lich 恢复后重新打开。从 0.72.0 或更早版本更新仍会遇到一次：出现该消息时，在任务管理器中结束 `lich-native.exe`，选择“重试”，之后从开始菜单打开 lich。
- 当 lich 不在运行（已退出或正在重启）时关闭原生窗口，无论“关闭窗口时”设为何值，窗口都会关闭。设为“询问”或“退出”时，窗口此前会一直开着，只显示无法统计会话数的错误。
- 在较窄的设置窗口中，如果某项设置的控件太宽、无法与文字同行（例如提供商的配置文件选择器），控件现在会放在标题和说明下方，此前文字被挤成一条窄缝，逐字换行。提供商的“文档”链接同样移到其名称下方，不再与“已启用”开关挤在一起。
- “转到”现在可以把 Claude Code 对话移回它刚离开的配置文件；此前在会话结束后仍在运行的插件钩子（例如 WakaTime 的）会留下一个文件，导致移动被以 "already holds" 拒绝。
