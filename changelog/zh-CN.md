- 配置文件可以有自己的颜色和图片。在设置 › 提供商中，配置文件的 ⋯ 菜单里有“颜色”（与会话卡片相同的八种颜色）和“选择图片…”，后者接受最大 10 MB 的 PNG、JPEG、GIF 或 WebP，并保留其居中的正方形区域。图片或颜色会显示在所有出现该配置文件的地方：配置文件列表和选择器、侧边栏底部以及“转到”。“移除图片”会回到配置文件颜色上的首字母。

### Changed

- 侧边栏中的卡片块，无论是工作树、文件夹还是置顶块，现在会在第一张卡片打开时渐渐展开，并随最后一张卡片关闭而渐渐收起，而此前它们是瞬间出现和消失的。列表分成多个块时显示的标题也以同样方式展开，在只剩一个块时收起。
- 拉取请求中仍在运行的检查，现在在其“检查”标签页和标签页上方的状态行中显示旋转的指示器，而此前是一个静止的时钟。
- 按钮在按下时不再下沉一个像素，因此窗口中的所有按钮行为一致：原先有这种动效的按钮现在与一直没有这种动效的按钮保持一致。

### Removed

- **Breaking:** 当 `lich open --worktree` 或智能体的 `open_session` 在新工作树中启动会话时，lich 不再运行 `.lich/setup-worktree.sh`。你仓库中的该文件不受影响。如果你的工作树依赖它来安装依赖项，请自行在新工作树的终端中运行它（`sh .lich/setup-worktree.sh`），或者让智能体来运行。复制被 gitignore 忽略的 `.env*` 文件（或 `.worktreeinclude` 中列出的内容）以及开发服务器端口 `LICH_WORKTREE_PORT` 保持不变。

### Fixed

- 智能体的 `git commit`、`rebase` 或 `stash` 不再因为 lich 恰好在同一时刻读取该检出目录的状态或差异，而偶尔失败并提示“Unable to create '.git/index.lock': File exists”。lich 的读取不会触碰索引。
- 已关闭会话的卡片重新会从侧边栏渐渐收起，而此前它是瞬间消失的。
- 在会话中按 Ctrl+Z 不再让其智能体永久冻结。此前它会挂起智能体，而 lich 中没有任何办法将其恢复；现在 lich 不会再把这个按键交给会话。
- 页脚中计划用量提示里的进度条，在 popover 与 muted 颜色相同的主题（例如 Everforest）上重新显示空轨道，此前只绘制了已填充的部分。
- 在拉取请求屏幕上打开或关闭拉取请求列表，不再让当前项目标签页松开其下方的面板后又重新抓住它。标签页全程保持连接，并在列表滑到其下方时移到列表上。

## [0.73.0] - 2026-10-20

> [!IMPORTANT]
> **所有用户：原生窗口现在是 lich 唯一的窗口。** lich 每次启动都会打开它；网页窗口及其内嵌的 Chromium 已移除。

### Added

- **在 Windows 和 macOS 的原生窗口中，桌面通知现在可以点击。** 与 Linux 一样，会话需要你输入或完成了一轮后，会弹出带有“打开”和“忽略”的通知：“打开”会把 lich 带到该会话的卡片上，你回复或打开该会话后，通知随即消失。在 macOS 上，lich 需要从 Lich.app 运行，并会请求一次权限；在 Windows 上，等待你操作的会话会让通知一直留在屏幕上，直到你处理。
- 当会话通过自定义可执行文件启动时，设置 › 提供商会在配置文件下方给出警告，显示其路径，并提供显示该文件或恢复默认值的按钮。自行设置登录或配置目录的包装脚本会覆盖配置文件，而“可执行文件”设置折叠在界面底部。

### Changed

- 会话进程退出时，现在由右下角的提示框询问如何处理，取代终端底部的横条。有对话的卡片提供“继续”（在其启动时所用的配置文件中重新打开同一段对话）、“新建对话”（像之前的“重新启动”一样在卡片中开始另一段对话）和“关闭会话”。Shell，或在第一条提示之前就结束的智能体，则提供“重新启动”和“关闭会话”。忽略提示框会保持卡片原样，聚焦该卡片会让提示框重新出现。
- **项目的配置文件现在位于侧边栏底部，而不是每张卡片上。** 当一个提供商有多个登录时，侧边栏最后一行会显示该项目中此提供商的新会话所使用的配置文件：取决于屏幕上卡片的提供商，终端则取默认的那个。点击它可以选择另一个登录（每个登录都显示五小时用量），或回到“全局”的设置；“其他提供商”可在同一菜单中修改其余的。卡片不再在分支旁显示配置文件标签。

### Removed

- 网页窗口。lich 会打开原生窗口，发布包也不再附带 Chromium。设置中的“窗口”选项（网页或原生）以及用于打开另一个窗口的托盘项均已移除，`lich -- <chromium flags>`、`lich --shell` 和 `LICH_SHELL` 同样移除。如果原生窗口无法启动，lich 会说明原因以及日志的位置。

### Fixed

- 登录 Claude Code 或 Codex 配置文件时，在你于浏览器中完成登录或提交粘贴的代码后，现在会显示正在验证；此前对话框会一直等待登录直到最后，代码输入框只是被清空。
- 在巴西葡萄牙语中，所有消息现在都称 worktree 为“a worktree”，此前有几处写成“o worktree”。
- 在 macOS 上，原生窗口重新有了关闭、最小化和缩放按钮；自 0.72.0 起，顶栏为它们留出的位置是空的。
- 在 Windows 上，从原生窗口更新 lich 不再因“Setup was unable to automatically close all applications”而回滚：窗口一直占用着安装程序必须替换的 `lich-native.exe`。现在它会在安装程序运行前关闭，并在 lich 恢复后重新打开。从 0.72.0 或更早版本更新仍会遇到一次：出现该消息时，在任务管理器中结束 `lich-native.exe`，选择“重试”，之后从开始菜单打开 lich。
- 当 lich 不在运行（已退出或正在重启）时关闭原生窗口，无论“关闭窗口时”设为何值，窗口都会关闭。设为“询问”或“退出”时，窗口此前会一直开着，只显示无法统计会话数的错误。
- 在较窄的设置窗口中，如果某项设置的控件太宽、无法与文字同行（例如提供商的配置文件选择器），控件现在会放在标题和说明下方，此前文字被挤成一条窄缝，逐字换行。提供商的“文档”链接同样移到其名称下方，不再与“已启用”开关挤在一起。
- “转到”现在可以把 Claude Code 对话移回它刚离开的配置文件；此前在会话结束后仍在运行的插件钩子（例如 WakaTime 的）会留下一个文件，导致移动被以 "already holds" 拒绝。

## [0.71.0] - 2026-10-17

### Added

- **原生窗口中的分屏布局（实验性）。** 可以把任意已打开项目的会话并排放在一起，并按需要自由分割：Ctrl+Shift+G 把当前聚焦的会话向右分割，Ctrl+Shift+I 向下分割，两者都会询问放入哪个会话；也可以把侧边栏中的卡片拖到某个窗格的边缘。要调整布局，可以拖动窗格标题到另一个窗格的边缘，或拖到其中间以交换两者，并用 Ctrl+Shift+R 在并排和上下堆叠之间切换一对窗格。每个布局都是项目之后的一个标签页，显示其各窗格的状态，双击即可重命名；拖动两个窗格之间的间隙可调整大小，用 Ctrl+Shift+M 放大一个窗格，用 Ctrl+Shift+F 在窗格之间切换，用 Ctrl+Shift+W 移出一个窗格；只剩一个窗格的布局会关闭。把拖动中的会话停在另一个标签页上，该标签页就会弹出，就像浏览器拖动文件时那样。侧边栏和页脚会跟随当前聚焦的窗格。

- **必需的检查会被标出。** 在原生窗口中，拉取请求的 检查 标签页会像 GitHub 一样，用 必需 标出那些控制其合并的检查。

### Changed

- **lich 迁到 `lichdotdev/lich`。** 仓库已迁至 [lichdotdev](https://github.com/lichdotdev) 组织，网站迁至 [lichdotdev.github.io/lich](https://lichdotdev.github.io/lich/)。旧的 GitHub 链接、克隆和更新检查都会重定向；旧网站的书签则不会。

- **差异视图不再因中日韩文本而卡顿，也不再为每个文件堆积内存。** 在原生窗口中，包含中文、日文或韩文的 审查 或拉取请求的 文件，会因为每个新字符都要查找字体而可能卡住数秒；而且每个文件的差异都各自保留一份字体副本，因此大型拉取请求会占用数百兆内存。

## [0.70.0] - 2026-10-17

### Added

- **“新功能”对话框使用你的语言。** 更新后弹出的对话框会用你所选的界面语言显示发布说明及其分组名称，两个窗口都是如此。如果某个版本的说明尚无译文，则以英文显示。

- **两张卡片运行同一段对话时，原生窗口会发出警告。** 在智能体自己的 TUI 中恢复一段已被另一张卡片打开的对话，会在右下角弹出警告；点击 切换 会关闭执行恢复的那张卡片，并切到原本打开该对话的卡片。
- **原生窗口可以显示图片。** PNG、JPEG、GIF、WebP 或 BMP 会在文件标签页的预览中以棋盘格为底打开，并显示大小和尺寸；审查中发生更改的图片会并排显示更改前后的样子。PDF 或其他无法预览的文件不再报错，而是提供 用默认应用打开 和 在文件夹中显示；在拉取请求中，二进制文件会链接到它在 GitHub 上的页面。
- **原生窗口支持你的语言。** 原生窗口的每个界面都可以用葡萄牙语、西班牙语和中文显示，设置 › 常规 中提供界面语言和提示词语言，与网页窗口在外观下的做法一致。在你选择之前，界面跟随系统语言。在没有中文字体的机器上选择中文时，会提示将 Noto Sans SC（约 25 MB）下载到 lich 自己的文件夹中。
- **日语。** 两个窗口都支持日语，日语同时也是一种提示词语言，因此 lich 会用日语与你的智能体交流。只要安装了对应字体（Noto Sans CJK、Yu Gothic、Hiragino、Malgun Gothic 等），原生窗口就会让日语、中文和韩语各自使用所属地区的字体绘制，汉字不再呈现中文字形；若没有安装，则会提示下载 Noto Sans JP 或 KR，与中文下载 Noto Sans SC 的方式相同。README 也提供了日语版本。
- **韩语。** 两个窗口都支持韩语，在网页窗口的 设置 › 外观 和原生窗口的 设置 › 常规 中选择；韩语同时也是一种提示词语言：简报、转发的消息和通知都会以韩语送达你的智能体。
- **lich 会说俄语。** 在网页窗口的 设置 › 外观 或原生窗口的 设置 › 常规 中，可以选择 Русский 作为界面语言，也可以选作提示词语言，这样 lich 输入到智能体中的简报、转发说明和交接内容也都以俄语呈现。计数遵循俄语的 one、few 和 many 三种形式（1 файл、2 файла、5 файлов）。
- **macOS 和 Windows 上的 opencode 配置文件，以及 Windows 上的 Cursor CLI 配置文件。** 原生窗口的 设置 › 提供商 会像在 Linux 上一样列出它们。macOS 上的 Cursor CLI，以及 macOS 和 Windows 上的 Kiro CLI 仍然没有：它们把登录信息保存在钥匙串中，或保存在任何设置都无法移动的文件夹里，因此每个配置文件都会共用同一个账户。

### Changed

- **每次更新都会打开原生窗口。** 每个版本首次启动时，lich 会切换到原生窗口，无法启动时则回退到网页窗口；你在设置中切回后，lich 会一直停留在网页窗口，直到下一个版本。原生窗口首次打开时，会说明它是实验性的，并附上提交 bug 报告的链接。
- **原生窗口中的状态环更细了。** 会话卡片图标外的圆环画得更细，与网页窗口的粗细一致。
- **原生窗口中的快捷键按键更宽松。** 命令面板、快捷键叠层和 设置 › 快捷键 中的按键帽，文字周围留白更多，文字居中。
- **原生窗口的设置默认打开全局。** 顶栏的齿轮始终打开 全局 设置，而不是你上次离开时所在的范围；项目的标签页仍可通过 项目设置… 打开它自己的设置。
- **原生窗口中的命令面板更清爽。** 每个会话、项目和消息只占一行，路径跟在名称之后；工作树的路径显示最后三段。等待你处理的会话排在最前并有所标注，筛选标签页去掉了药丸样式，改用下划线。历史 中已关闭的会话在右侧显示分支和时长，只有搜索匹配到其对话时才多出第二行，并标出匹配的词。

### Fixed

- **重启的会话不再一直显示为忙碌。** 智能体在一轮中途死亡，或会话在一轮中途被关闭后，会话会回到同一张卡片上，但对其他会话仍显示为忙碌：发给它的任务会等待一个永远不会结束的轮次。现在它和新会话一样，以无状态启动。
- **Codex、Cursor CLI、Antigravity 和 Crush 不再重复询问你已回答过的问题。** 其中任何一个的沙盒会话都会直接停在提示符处。Cursor CLI 和 Antigravity 不再在你信任过的文件夹的工作树中再次询问，Antigravity 在其子文件夹中也不再询问，Crush 也不再要求初始化每个新的工作树。沙盒中的 oh-my-pi 会话不再打开设置向导。
- **Claude Code 不再在你已回答过的地方询问“信任此文件夹？”。** 你在主账户中信任过的文件夹，从下一次会话起在其他所有 Claude Code 配置文件中也被信任，沙盒中的 Claude Code 会话则完全不会出现这个问题。lich 为你打开的会话不再停留在那个界面上，在那里按 Enter 会退出。
- **重新打开的原生窗口知道每个会话去了哪里。** 通过 `cd` 移动过，或进入了 tmux 或 ssh 的会话，回来时会一直显示它检出的路径、分支和更改，直到下一次 `cd`；现在窗口在连接时会读取每个会话最后所在的位置。
- **原生窗口用你的提示词语言编写智能体提示词。** 拉取请求和 issue 的交接，以及一批审查评论，此前一直以英文输入。
- **重连期间更改主题不再导致原生窗口崩溃。** 在窗口重新连接到已重启的 lich 时切换主题，或系统切换浅色和深色，可能会绘制重连刚刚释放的终端，并使窗口崩溃。
- **中文、日文和韩文文本不再让 Linux 上的原生窗口卡死。** 满是 CJK 文本的会话、审查或拉取请求可能使窗口挂起数秒，长到出现“未响应”，缩放还会让卡死再次出现。
- **原生窗口占用的内存更少。** 每个会话的终端和审查都加载了各自的回退字体副本，CJK 或 emoji 字体每份就有数十 MB：现在打开六个会话，内存占用约为原来的一半。在安装了 CJK 字体的机器上，启动也更快。
- **重新打开对话已处于打开状态的会话时，会聚焦到那张卡片。** 从 历史 中打开已关闭的会话、撤销关闭或已有的工作树，可能会作为第二张卡片回到另一张卡片仍在运行的对话上，两者会写入同一份对话记录。历史 现在按最近一次关闭只列出这样的对话一次，忘记 会删除它的所有副本。

## [0.69.0] - 2026-10-16

### Added

- **macOS 上的原生窗口（实验性）。** Lich.app 在 Apple Silicon 和 Intel 上随 lich 一同提供它，设置 › 外观 › 窗口与 Linux 和 Windows 上一样可以选择它。Option 键在其终端中用于输入字符，和 Terminal.app 一样，因此智能体的 Option+字母快捷键无法到达终端。目前它只在 GitHub 的 macOS 机器上运行过：通知是无法点击的普通通知，也没有菜单栏图标。
- **文件树认识更多的文件类型。** Java、Gradle、C 和 C++、C#、PHP、Ruby、Swift、SQL、Vue、Svelte、Terraform、Dockerfile、.gitignore 以及约三十种其他类型，现在在文件树和搜索结果中都有各自的图标，此前它们显示的是普通文件图标。

### Fixed

- **`lich quit` 会关闭原生窗口。** 后端退出后，窗口原本仍然开着，并显示 lich 已丢失；托盘中的退出和停止信号现在也会关闭它，而更新后的重启仍会保留它。
- **最后一个会话关闭时，原生窗口会提示删除工作树。** 已关闭提示中，撤销旁边新增了删除工作树；对于不是 lich 创建的工作树，或带有未提交更改的工作树，删除前会在对话框中点明。
- **原生窗口的终端会选中指针下方的单元格。** 点击、拖动选择、链接以及跟踪鼠标的程序，读取到的指针位置都偏移了终端的内边距，导致它们选中的单元格位于所指单元格的右下方，在缩放显示器上偏差接近一个单元格。
- **原生窗口的终端会绘制 emoji。** Noto Color Emoji 等彩色 emoji 字体把每个 emoji 存为图片而非轮廓，而终端只会绘制轮廓，所以每个 emoji 都显示为空白；现在它们以彩色绘制，占两个单元格宽。
- **原生窗口的文件树显示每个文件的语言图标。** 此前每个文件都画成同一个普通文件图标；现在每个文件都带有网页窗口为它提供的图标。
- **智能体打开的拉取请求会在这一轮结束时显示在它的卡片上。** 徽章原本只在分支或其最新提交变化时才会重新检查，而打开拉取请求两者都不会变，所以它要等到窗口失去焦点再重新获得焦点后才出现。
- **原生窗口可以在 Windows 上打开。** 它原本通过 fontconfig 查找字体，而 Windows 并不提供，因此启动时就关闭了，lich 随后回退到网页窗口。在 Windows 上，它现在自己查找已安装的字体，终端默认使用 Cascadia Mono 或 Consolas，设置中的字体选择器也会列出它们。
- **在浅色和深色主题之间切换不再冻结原生窗口。** 像 Claude Code 那样跟随终端配色方案的会话，会在窗口仍持有其终端时收到变化通知，导致窗口卡死并关闭。
